## `status`

```text
Usage: pitboard status [OPTIONS]
```

| Option | Description |
| --- | --- |
| `--offline` | Answer from what was last measured, without asking anyone |
| `--fresh` | Ask about every account, even one asked about moments ago |

The two options cannot be given together.

| Tool | Without `--offline` | With `--offline` |
| --- | --- | --- |
| Claude Code | Renews each parked login whose access token has expired or expires within 2 minutes, then asks Anthropic about every account | Takes the account in use from Pitboard's record |
| Codex | The same, asking OpenAI | Takes the account in use from the login itself |
| Claude Desktop | Renews nothing and asks no service. Takes the account in use from Pitboard's record, and reads Claude's settings. | The same |

`status` sends every request at once, and each times out after 5 seconds. `--offline` sends no request and writes nothing. [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) says when an account is asked again, and what `--fresh` changes.

[How Pitboard knows whose login it is](/concepts/identity) explains the record for each tool.

`status` exits 0 when a service cannot be reached, and that account's last line says why. It exits 1 on an error in [The Pitboard directory](/reference/errors#the-pitboard-directory).

| Warning | Tool | When | With `--offline` |
| --- | --- | --- | --- |
| `parked_login_refused` | Claude Code, Codex | Anthropic or OpenAI refused a parked login for good during renewal. Pitboard dropped it. | No |
| A renewal error, such as `renewal_failed` | Claude Code, Codex | Renewing a parked login failed for another reason. | No |
| `recovery_undetermined` | Claude Code, Codex | An interrupted switch is waiting that the next change cannot finish. | Where Pitboard can tell without asking Anthropic |
| `login_replaced` | Claude Code, Codex | A sign-in outside Pitboard replaced an account's only login. | Yes |
| `in_use_unconfirmed` | Claude Code | Claude Code's config has named another account since Anthropic last identified the login stored, or Anthropic was not asked since an update from 0.9.0 or earlier. | Yes |
| `config_names_another` | Claude Code | Claude Code's config names another account than the one whose login is stored. | Yes |
| `fallback_login` | Claude Code | On macOS, `~/.claude/.credentials.json` sits behind the keychain. On Windows, `.credentials.json` sits behind Credential Manager. | No |
| `login_replaced` | Claude Desktop | The account in use was signed out in Claude, or a sign-in outside Pitboard replaced its login. Pitboard holds no login for it. | Yes |
| `in_use_unconfirmed`, `config_names_another` | Claude Desktop | Claude's settings have named another account, or nobody, since Pitboard last read Claude. | Yes |
| `looks_signed_out` | Claude Desktop | Claude's settings look signed out since Pitboard last read the account in use. | Yes |
| `move_waiting` | Claude Desktop | A move was interrupted, and its record waits. | Yes |
| `sign_in_awaited` | Claude Desktop | Claude is signed out for a sign-in, and the account that was in use is parked. | Yes |
| `read_only` | Any | `status` runs where a change fails with [`elevated`](/reference/errors#root-sudo-and-administrator) or [`system_too_old`](/reference/errors#windows). It answers as `--offline` does. | No |

[Warning codes](/reference/errors#warning-codes) gives each message and what to do.

```sh
pitboard status --offline
```

```text
● personal  me@example.com  Max 20x  signed in
    5h    ██████░│░░   59%  resets in 1h 10m  18% under pace
    week  █│█████░░░   73%  resets in 5d 18h  55% over pace
          weekly limit runs out in 11h 05m at this pace
          measured 14:02, 3m ago · read without asking Anthropic

○ work      me@company.com  Max 20x  ready · good for 26d 4h
    5h    █░░░│░░░░░   12%  resets in 3h 00m  28% under pace
    week  ████░░│░░░   40%  resets in 2d 4h   29% under pace
          measured 14:02, 3m ago · read without asking Anthropic
```

A Codex account's last line ends `read without asking OpenAI` instead.

A Claude Desktop account has no usage lines. `status` says so once for all of them:

| Accounts listed | Where the line goes |
| --- | --- |
| Claude Desktop's alone | First, as `Pitboard reads no usage for Claude Desktop` |
| Beside another tool's | On the tool's heading: `Claude Desktop · Pitboard reads no usage for Claude Desktop` |

```text
Pitboard reads no usage for Claude Desktop
● work    signed in · read 2h 05m ago
○ home    ready · sign-in may lapse in 25d 3h
```

Where any Claude Desktop account reads `login replaced outside Pitboard`, `status` leaves that line out.

[Account status](/reference/account-status) says what each line means, and [Status data](/reference/json-output#status-data) lists the `--json` fields.

## `enroll`

```text
Usage: pitboard enroll [OPTIONS] <LABEL>
```

| Argument or option | Description |
| --- | --- |
| `<LABEL>` | The account's label: `work` for Claude Code, `codex/work` for Codex, and on macOS `desktop/work` for Claude Desktop |
| `--sign-in` | Sign in to the account before enrolling it |

Without `--sign-in`, `enroll` records the account the tool is signed in to. It parks nothing: [Parked logins](/concepts/switching#parked-logins) says why.

With `--sign-in`:

| Tool | What Pitboard does |
| --- | --- |
| Claude Code | Runs `claude auth login` with `CLAUDE_CONFIG_DIR` set to `signin` in Pitboard's directory. Claude Code stores the new login in a keychain item made for that directory on macOS, and in `.credentials.json` there on Linux. On Windows, it stores it in `.credentials.json` there, or in a Credential Manager item made for that directory where its Credential Manager store is on. |
| Codex | Runs `codex -c 'cli_auth_credentials_store="file"' login` with `CODEX_HOME` set to `signin` in Pitboard's directory. Codex stores the new login in `auth.json` there. |
| Claude Desktop, on macOS | Runs nothing. Parks the account in use, which leaves Claude signed out, then waits while you open Claude, sign in and quit it. Enrols the account Claude is then signed in to. |

A Claude Code or Codex sign-in leaves the account in use signed in. Before each one, Pitboard deletes `signin` and makes it again, private to you. It reads the new login from there, then deletes the directory and, on macOS, that keychain item. On Windows, it deletes that Credential Manager item too.

On Windows, before a Codex sign-in, Pitboard names on standard error what runs Codex: a Codex sign-in open there ends as this one starts.

A lock on `signin.lock` in Pitboard's directory keeps sign-ins to one at a time. A Claude Desktop sign-in holds it for the whole wait.

Where Claude is already signed out and its settings still hold an account's keys, Pitboard sets those keys aside before it waits.

While it waits, a Claude Desktop sign-in prints these lines on standard error. A warning raised while it parks the account in use comes first, as a plain line without `warning:`.

| Line | When |
| --- | --- |
| ``Parked `desktop/work`. Claude is signed out, and nothing was signed out at claude.ai.`` | Pitboard parked the account in use. |
| ``Open Claude and sign in to the account to add as `desktop/travel`. When Claude shows your chats, quit it with Command-Q.`` | The label is not enrolled. |
| ``Open Claude and sign in to `desktop/home` again. When Claude shows your chats, quit it with Command-Q.`` | The label is enrolled. |
| `Do not choose Log out in Claude: it ends the login Claude holds at claude.ai, and Pitboard cannot bring it back.` | Always. |
| ``Waiting for Claude to quit. Control-C stops waiting and keeps `desktop/work` parked; `pitboard use desktop/work` puts it back.`` | An account is parked for this sign-in. |
| `Waiting for Claude to quit. Control-C stops waiting.` | No account is parked for it. |
| `Claude is open.` | Claude opened. |
| `Claude quit with nobody signed in. Still waiting.` | Claude quit signed out. |
| `Claude quit before it finished signing in. Open it, wait until it shows your chats, then quit it. Still waiting.` | Claude quit before the sign-in finished. |

After Control-C, Claude stays signed out. An account parked for the sign-in stays parked, and every read warns `sign_in_awaited`. [Finish or undo an add or a sign-in again](/troubleshooting/claude-desktop#finish-or-undo-an-add-or-a-sign-in-again) says what to do next.

The `enrolled` field of `--json` output names the outcome.

| `enrolled` | Tool | When | First line |
| --- | --- | --- | --- |
| `current` | Claude Code, Codex | Without `--sign-in` | `Enrolled personal (me@example.com), the account signed in now.` |
| `current` | Claude Desktop | Without `--sign-in` | `Enrolled desktop/work, the account Claude is signed in to now. Check that Claude shows that account: Pitboard cannot ask claude.ai whose it is.` |
| `signed_in` | Claude Code, Codex | A label not enrolled before, signed in as an account that is not in use | `Enrolled work (me@company.com). Switch to it with: pitboard use work` |
| `renewed` | Claude Code, Codex | An enrolled label not in use. Its parked login is replaced. | `Renewed work (me@company.com): its parked login is a fresh one.` |
| `in_use` | Claude Code, Codex | The label of the account in use. The new login replaces the one in use. | `Signed in to personal (me@example.com) again. Its new login is the one in use now.` |
| `in_use` | Claude Code, Codex | A label not enrolled before, signed in as the account in use | `Enrolled personal (me@example.com), the account signed in now. Its new login is the one in use.` |
| `in_use` | Claude Desktop | With `--sign-in`, a label not enrolled before | `Enrolled desktop/travel, the account Claude is signed in to now.` |
| `in_use` | Claude Desktop | With `--sign-in`, an enrolled label | `Signed in to desktop/home again. Claude is signed in to it now.` |

`current` adds a second line:

| Tool | Second line |
| --- | --- |
| Claude Code | `Add another without signing out of it: pitboard enroll <label> --sign-in` |
| Codex | `Add another without signing out of it: pitboard enroll codex/<label> --sign-in` |
| Claude Desktop | `Add another: pitboard enroll desktop/<label> --sign-in` |

When Pitboard cannot identify the Claude Code or Codex login in use, `--sign-in` parks the new login instead of replacing that one. [If Pitboard cannot identify the login in use](/guides/sign-in-again#if-pitboard-cannot-identify-the-login-in-use) says what to do.

`enroll` refuses with these codes. For a Claude Code or Codex sign-in, Pitboard checks the first five before your browser opens.

| Code | Tool | When |
| --- | --- | --- |
| `custom_oauth_endpoint` | Claude Code | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set. |
| `live_store_unsupported` | Codex | Pitboard cannot write where Codex keeps its login, such as a store other than `file`. See [Codex keeps its login outside its file store](/troubleshooting/codex#codex-keeps-its-login-outside-its-file-store). |
| `sign_in_not_isolated` | Claude Code, Codex | The tool's sign-in would not stay inside the private directory. |
| `claude_program_missing`, `codex_program_missing` | Claude Code, Codex | Pitboard cannot find the tool's program. |
| `sign_in_in_progress` | Any | Another sign-in is running. |
| `sign_in_incomplete` | Claude Code, Codex | The tool's sign-in failed or stored no login. |
| `live_credential_absent` | Any | Without `--sign-in`, the tool is not signed in. |
| `already_enrolled` | Any | The account is enrolled under another label. |
| `label_taken` | Any | The label names another account. |
| `login_restricted` | Claude Code, Codex | With `--sign-in`, a setting of the tool's rules out the new login of the account in use. |
| `live_store_unsupported` | Claude Desktop | Pitboard runs off macOS, or with `HOME` set to a folder other than your account's own home. |
| `live_account_not_enrolled` | Claude Desktop | With `--sign-in`, Claude is signed in to an account not enrolled. Pitboard parks no account it has not enrolled. |
| A code in [Claude Desktop](/reference/errors#claude-desktop), such as `app_open` | Claude Desktop | Claude is open, has not finished signing in, or holds a login Pitboard cannot identify. |

`enroll` can warn:

| Warning | Tool | When |
| --- | --- | --- |
| `sign_in_parked_not_in_use` | Claude Code, Codex | `--sign-in` parked the new login for the account Pitboard last recorded in use. |
| `sessions_keep_old_login` | Codex | The new login replaced the one in use, and Codex processes started before still run. |
| `sessions_unknown` | Codex | The new login replaced the one in use, and Pitboard could not read the list of processes. |
| `lock_compromised` | Claude Code | Claude Code took back its write or refresh lock while Pitboard wrote the new login. |
| `written_on_the_command_line` | Claude Code, Codex | On macOS, Pitboard passed a login to `security` as an argument. See [Large logins on macOS](/security#large-logins-on-macos). |
| `login_taken_as_named` | Claude Desktop | Pitboard filed the login Claude held as the account Claude's settings name. |
| `set_aside` | Claude Desktop | Pitboard moved something into a folder in `~/.pitboard/parks` and deleted nothing. |

[Warning codes](/reference/errors#warning-codes) gives each message.

To add a second Claude Code account:

```sh
pitboard enroll work --sign-in
```

This line and Claude Code's own output go to standard error. For an enrolled label, the line names the account's email.

```text
Opening Claude Code's sign-in. Sign in as the account to add; the account in use now stays signed in.
```

Claude Code then opens your browser. Once you sign in, Pitboard prints:

```text
Enrolled work (me@company.com). Switch to it with: pitboard use work
```

## `use`

```text
Usage: pitboard use [OPTIONS] <LABEL>
```

| Argument or option | Description |
| --- | --- |
| `<LABEL>` | The account's label, such as `work`, `codex/work` or, on macOS, `desktop/work` |
| `-y, --yes` | Where the service refuses the login in use for good, put this account's login in its place without asking; needed without a terminal or with `--json` |

`use` parks the login the label's tool has stored and puts the account's parked login in its place. Where nothing is signed in to Claude Code or Codex, as before its first sign-in, it puts the account's login where the tool reads it and parks nothing.

A Claude Code login whose refresh token Anthropic refuses for good no longer works, and cannot be parked. `use` says why, and asks before it puts the account's login in its place, which loses nothing. `use` never asks about a login Anthropic will not name, an account on hold, or when Anthropic cannot be reached.

| Tool | Before a switch |
| --- | --- |
| Claude Code, Codex | Anthropic or OpenAI identifies the parked login. Pitboard renews that login first when its access token has expired. A switch always needs the network. |
| Claude Desktop | Claude must be closed. Pitboard asks no service. |

Before anything moves, `use` refuses with:

| Code | Tool | When |
| --- | --- | --- |
| `live_credential_elsewhere` | Claude Code | Claude Code's config names an account in use, and Pitboard cannot find its login. |
| `live_account_not_enrolled` | Any | The tool is signed in to an account you have not enrolled. |
| `nothing_parked` | Any | The account has no parked login. |
| `parked_login_expired` | Claude Code, Codex | The parked login's refresh token has expired. |
| `parked_login_refused` | Claude Code, Codex | Anthropic or OpenAI no longer accepts the parked login. |
| `parked_login_belongs_elsewhere` | Claude Code, Codex | The parked login is another account's. |
| `login_restricted` | Codex | A setting of Codex's rules out the account's login. See [Codex settings rule out an account](/troubleshooting/codex#codex-settings-rule-out-an-account). |
| `login_restricted` | Claude Code | A managed `forceLoginOrgUUID` leaves out the account's organisation. |
| `identity_unverifiable` | Claude Code, Codex | Anthropic or OpenAI could not confirm whose a login is. |
| `live_login_refused` | Claude Code | Anthropic refuses the refresh token of the login in use for good, and you did not agree to replace it. |
| `account_on_hold` | Claude Code | Anthropic has put the account of the login in use, or of the account switched to, on hold. |
| A code in [Claude Desktop](/reference/errors#claude-desktop), such as `app_open` | Claude Desktop | Claude is open, its data folder is in a state Pitboard moves no login in, or Pitboard cannot identify the login Claude holds. |

[Switching](/reference/errors#switching) lists what else can stop a switch.

For the account in use, `use` moves no login and prints `work is already signed in.` Where Claude Code's config names another account, `use` writes `work` there and adds `Claude Code's config named another account, and now names work.` The `--json` field `config_updated` is then `true`.

After a switch, `use` prints `Switched to work; personal is parked.` and a second line:

| Tool | Second line |
| --- | --- |
| Claude Code | `Claude Code sessions already running follow within 33 seconds.` |
| Claude Code, with a login file behind the keychain or Credential Manager | ``Claude Code sessions already running keep the account they are on until their login is next renewed, or until they are started again: /Users/you/.claude/.credentials.json is there. `pitboard stow` puts it away.`` |
| Codex | ``Restart any running `codex` for this to take effect. It will not pick the switch up on its own.`` |
| Claude Desktop | `Claude opens signed in to it.` |

A switch where nothing is signed in parks nothing. Its first line names the tool, such as `Switched Claude Code to work.` or `Switched Claude Desktop to desktop/work.`

[Open sessions](/concepts/open-sessions) explains both Claude Code lines.

After a switch, `use` can warn:

| Warning | Tool | When |
| --- | --- | --- |
| `sessions_still_running` | Codex | Something started before the switch still runs Codex. |
| `sessions_unknown` | Codex | Pitboard could not read the list of processes. |
| `written_on_the_command_line` | Claude Code, Codex | On macOS, Pitboard passed the parked login to `security` as an argument. See [Large logins on macOS](/security#large-logins-on-macos). |
| `login_taken_as_named` | Claude Desktop | Pitboard had not seen the login Claude held, and parked it as the account Claude's settings name. |
| `set_aside` | Claude Desktop | Pitboard moved something into a folder in `~/.pitboard/parks` and deleted nothing. |
| `login_item_gone` | Claude Desktop | An item of the login was in neither place after the move. |

[Warning codes](/reference/errors#warning-codes) gives each message.

```sh
pitboard use codex/work
```

```text
Switched to codex/work; codex/personal is parked.
Restart any running `codex` for this to take effect. It will not pick the switch up on its own.
```

## `forget`

```text
Usage: pitboard forget [OPTIONS] <LABEL>
```

| Argument or option | Description |
| --- | --- |
| `<LABEL>` | The label to drop |
| `-y, --yes` | Do not ask first; needed without a terminal or with `--json` |

`forget` drops the account from Pitboard's list and deletes what Pitboard keeps for it:

| Tool | Deleted |
| --- | --- |
| Claude Code, Codex | The parked login and the last usage reading |
| Claude Desktop | The parked login and every folder set aside for the account |

Pitboard does not revoke the login it deletes: see [SECURITY.md](https://github.com/datlechin/pitboard/blob/main/SECURITY.md#out-of-scope).

For a Claude Code or Codex account, the app deletes its window data, sign-in included, at its next read of the accounts. [How account windows keep their data](/concepts/account-windows) has the rules.

| Code | Tool | When |
| --- | --- | --- |
| `cannot_forget_active_account` | Any | The account is in use. |
| `identity_unverifiable` | Claude Code, Codex | Pitboard cannot identify the login in use, and the account is the one last in use or has no parked login. |
| `app_open` | Claude Desktop | Claude is open while a move waits, or while the account is the one last in use or has no parked login. |
| `recovery_undetermined` | Claude Desktop | A move waits that Pitboard cannot settle. |
| Another code in [Claude Desktop](/reference/errors#claude-desktop), such as `login_folder_unknown` or `login_in_doubt` | Claude Desktop | Pitboard cannot identify the login Claude holds, and the account is the one last in use or has no parked login. |
| `confirmation_needed` | Any | It cannot ask, as in a script or with `--json`, and `--yes` is not given. Exit status 2. |

At a terminal, without `--yes` or `--json`, `forget` asks on standard error:

| Account | Question |
| --- | --- |
| Claude Code or Codex | `Forget old and delete its parked login? Adding it again needs a browser sign-in. [y/N]` |
| Claude Desktop | `Forget desktop/home and delete its parked login and the folders set aside for it? Adding it again needs a sign-in in Claude. [y/N]` |

Anywhere else it needs `--yes`, and refuses with `confirmation_needed` without it. A label that names no account fails with its own error instead. The account in use needs `--yes` too, and then fails with `cannot_forget_active_account`. [Questions before deleting](/reference/commands#questions-before-deleting) says when it asks and what each answer does.

```sh
pitboard forget old --yes
```

```text
Forgot old (old@example.com).
```

## `rename`

```text
Usage: pitboard rename [OPTIONS] <FROM> <TO>
```

| Argument | Description |
| --- | --- |
| `<FROM>` | The label it has now |
| `<TO>` | The label it should have |

`rename` changes only the label. The account keeps what Pitboard holds for it, such as its parked login, usage reading, account window or folders set aside. It stays in use if it is.

A rename stays inside the account's tool: `pitboard rename codex/work job` gives `codex/job`.

| Code | When | Exit status |
| --- | --- | --- |
| `label_taken` | Another account of the same tool has the label `<TO>`. | 1 |
| `usage` | `<TO>` names another tool, as in `pitboard rename work codex/work`. | 2 |

```sh
pitboard rename wrong right
```

```text
Renamed wrong to right (me@company.com).
```

## `warm`

```text
Usage: pitboard warm [OPTIONS] [COMMAND]
```

| Form | What it does |
| --- | --- |
| `pitboard warm` | Lists each Claude Code account, whether it is warmed up, and when it warms up next |
| `pitboard warm on <label>` | Warms up the account from now on, between the hours set |
| `pitboard warm off <label>` | Stops warming up the account |
| `pitboard warm range <FROM> <TO>` | Warms up only between these times of each day, such as `07:00 23:00`, in this computer's time zone. `TO` of `00:00` or `24:00` is midnight at the end of the day, and a `FROM` later than `TO` runs past midnight |
| `pitboard warm now <label>` | Warms up the account at once, whatever the hours |

[Warm up accounts](/guides/warm-up) says what a warm-up sends and when Pitboard holds back. The app and `pitboard watch` warm up the accounts turned on; `warm` itself never runs by itself.

`warm on` and `warm now` refuse a Codex or Claude Desktop account with `warm_up_unsupported`. `warm now` refuses an account with nothing to start, with the code of the reason, such as `limit_used_up`:

```sh
pitboard warm now work
```

```text
error: `work` has its weekly limit used up until Oct 15 03:00, so it is not warmed up now.
```

```sh
pitboard warm now personal
```

```text
Warmed up personal: its 5-hour period runs until 22:50.
```

`warm now` prints `personal's 5-hour period runs already, until 22:50.` and changes nothing while the period runs.

## `watch`

```text
Usage: pitboard watch [OPTIONS]
       pitboard watch <COMMAND>
```

| Option | Description |
| --- | --- |
| `--at <PERCENT>` | Switch once a limit of the account in use reaches this share: a whole number from 50 to 99, 95 by default |
| `--once` | Decide once whether to switch, from the usage Pitboard last measured, asking no service for usage, and stop. Warms nothing up |

`watch` switches Claude Code only. [Switch before an account runs out](/guides/automatic-switching) gives the rules it follows. It also warms up the accounts [`warm on`](#warm) turned on, as [Warm up accounts](/guides/warm-up) describes.

It runs in the foreground until you press Control-C, whatever the app's **When a limit reaches** setting says. [The watch service](#the-watch-service) runs it in the background instead.

While it runs, `watch`:

- Reads every account when it starts and every 5 minutes, as often as [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) allows.
- Looks every 2 seconds at when the account list and usage readings were last written, and decides again when either changed.
- Decides at least every 30 seconds.

On standard output, each line but the first starts with the local time, such as `14:02:11`.

| Line | When |
| --- | --- |
| `Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 95%. Stop with Ctrl-C.` | It starts. With an account turned on for warm-ups, the first sentence ends `, and warms up personal from 06:00 to 22:00.` |
| `Watching work: 62% of its 5-hour limit, as of 14:00.` | No limit of the account in use has reached the share. The line names its fullest limit that has not reset. While Anthropic holds Pitboard off asking about the account, it ends `Anthropic holds Pitboard off asking again until 15:28.` |
| `Switched Claude Code from work to personal: work has used 96% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.` | It switched. The last sentence is the second line `use` prints. |
| `work has used 97% of its 5-hour limit. Pitboard is not switching: no other Claude Code account has room below 95% in every limit.` | No other account qualifies: `no_room`. |
| `work has used 96% of its 5-hour limit. Pitboard tries again at 14:03.` | A try came to nothing, and Pitboard waits before the next. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: <reason>.` | It stays on the account, for a reason in [When it stays on the account](/reference/automatic-switching#when-it-stays-on-the-account) other than `no_room`. |
| `Pitboard is not switching Claude Code: <reason>.` | It cannot decide whether to switch, for a reason in [When it decides nothing](/reference/automatic-switching#when-it-decides-nothing). |
| `Warmed up personal: its 5-hour period runs until 22:50.` | It warmed up an account. |
| `personal has its weekly limit used up until Oct 15 03:00, so Pitboard is not warming it up for now.` | An account turned on is held back, for a reason in the first table of [When it holds back](/guides/warm-up#when-it-holds-back). |
| `Pitboard is not warming up accounts: <reason>.` | An account is turned on, and nothing can be warmed up here, for a reason in the second table there. |

A limit of one model is named with its model, as in `97% of its weekly Opus limit`.

Three reasons end the line in their own way:

| Reason | The line ends |
| --- | --- |
| `settling` | `It decides again at 14:07.` |
| `not_identified` | `It asks again at 14:03.` |
| `switch_interrupted` | `` or give up on it with `pitboard abandon`. `` |

`watch` names the account it watches whenever its last line said something else. Until the next switch, it prints each reason, wait and error code once. A warning also comes once, on standard error, with the line of the decision that found it.

A switch or a warm-up that fails prints its error on standard error, as `pitboard use` would, and `watch` goes on. [Automatic switching](/reference/automatic-switching) says what ends each reason and how long Pitboard waits after a failure.

`watch` ends with the error's exit status where a change fails with [`elevated`](/reference/errors#root-sudo-and-administrator) or [`system_too_old`](/reference/errors#windows). It also ends on an error in [The Pitboard directory](/reference/errors#the-pitboard-directory) while deciding whether to switch. No warm-up error ends it.

With `--once`, `watch` prints only the line of one decision, with no start line or time. It may still ask Anthropic to identify Claude Code's stored login, and a switch checks the parked login as `use` does. It exits 0, or with the error's status.

With `--json`, `watch` prints one line of JSON per event. [Watch events](/reference/json-output#watch-events) lists the fields.

```sh
pitboard watch --once
```

```text
Watching work: 62% of its 5-hour limit, as of 14:00.
```

### The watch service

| Command | What it does | Output begins |
| --- | --- | --- |
| `install` | Hands `pitboard watch` to the system's own service manager and starts it, with its own `--at`, replacing one already there. | `Pitboard watches Claude Code in the background from now on, and at each sign-in.`, then where the job is |
| `status` | Checks that the job is there, not whether it runs. | `Pitboard watches Claude Code in the background` or `Nothing watches Claude Code in the background here.` |
| `uninstall` | Stops the job and deletes what `install` wrote. | `Stopped watching Claude Code in the background.` or `Nothing was watching Claude Code in the background.` |

The service starts at each sign-in and runs `watch` at the share `install` was given. Its first line ends `` Stop it with `pitboard watch uninstall`. `` in place of `Stop with Ctrl-C.` On macOS, its lines go to `~/Library/Logs/Pitboard/watch.log`, and on Linux to your user's journal. On Windows, nothing keeps them. [`pitboard log`](/reference/maintenance-commands#log) records each switch and warm-up either way. [Watch service](/reference/files#watch-service) lists where each system keeps it.

On Linux, your user's systemd runs the service from your first sign-in to your last sign-out. To keep it running with nobody signed in, as on a server, run `loginctl enable-linger`, as loginctl(1) says.

Where `watch` ends on an error or a crash, macOS and Linux start the service again a minute later. On Windows, it starts again at your next sign-in, or with `pitboard watch install`.

After you update Pitboard, the service runs the updated `pitboard` from your next sign-in, or at once after `pitboard watch install`. On Windows, Scoop and WinGet cannot update a `pitboard.exe` the service is running: `scoop update` skips it, and `winget upgrade` fails. Run `pitboard watch uninstall` before you update, and `pitboard watch install` after.

`install` follows the rules of [`schedule install`](/reference/maintenance-commands#schedule):

- It watches the accounts in Pitboard's own directory, whatever `PITBOARD_HOME` it is given. While `PITBOARD_HOME` names another directory, `install` refuses with `schedule_not_default_home`.
- It gives the service each proxy variable it was started with. Run `install` again after your proxy changes.
- Where Pitboard may change nothing, it refuses with `elevated` or `system_too_old`.

The app and the service can both switch Claude Code: as with `pitboard watch` in a terminal, they never make two switches from one reading.

```sh
pitboard watch install --at 90
```

```text
Pitboard watches Claude Code in the background from now on, and at each sign-in. It switches once a limit of the account in use reaches 90%, and warms up the accounts `pitboard warm on` turned on.
/Users/me/Library/LaunchAgents/com.datlechin.pitboard.watch.plist

Anthropic's terms may cover automatic switching and warm-ups: https://docs.usepitboard.com/concepts/limits#is-this-allowed
```

On Windows, the second line is the task's path, such as `\Pitboard\Watch S-1-5-21-…`.
