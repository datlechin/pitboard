The account commands show, add, switch, forget and rename the accounts Pitboard knows. `watch` switches Claude Code by itself, before an account runs out, for as long as it runs. Each command also takes `--json` and `--help`, described in [Global options](/reference/commands#global-options). Exit statuses are as in [Exit codes](/reference/commands#exit-codes) unless a section says otherwise.

A label such as `codex/work` names an account of OpenAI's Codex CLI. `pitboard enroll` reads a bare label such as `work` as a Claude Code account. `pitboard use`, `pitboard forget` and the first label of `pitboard rename` look for a bare label in both tools.

A parked login is the login Pitboard keeps for an account that is not in use. For more on both, see [Labels](/reference/commands#labels) and [Parked logins](/concepts/switching#parked-logins).

## `status`

```text
What is signed in, and how much each account has left (the default)

Usage: pitboard status [OPTIONS]
```

First, `status` renews each parked login whose access token has expired or expires within 2 minutes. Then it asks about every account at the same time: Anthropic for Claude Code accounts, OpenAI for Codex accounts. Each request times out after 5 seconds.

An account asked about recently is not asked again until its numbers could have moved. For how long that takes, see [How usage is read](/concepts/usage#how-often-pitboard-asks).

`status` shows Codex accounts only once one is enrolled. Until then, it reads none of Codex's files and asks OpenAI nothing.

| Option | Description |
| --- | --- |
| `--offline` | Answer from what was last measured, without asking anyone |
| `--fresh` | Ask about every account, even one asked about moments ago |

`--offline` renews nothing and writes nothing. It takes the Claude Code account in use from whose login Anthropic last named, and the Codex one from its login's own claims. Each account says `read without asking Anthropic` or `read without asking OpenAI`. Where Claude Code's config has named another account since Anthropic last named the login stored, it warns with `in_use_unconfirmed`, and `status` without `--offline` asks again.

`--fresh` asks again a service Pitboard could not reach moments ago, but not one that asked Pitboard to wait: those accounts keep their last numbers until the wait ends. Giving both options is refused with exit status 2.

`status` exits 0 even when a service cannot be reached, and the account's last line says why. It exits 1 only when Pitboard cannot load its account list.

While `~/.claude/.credentials.json` sits behind the keychain on macOS, `status` warns with `fallback_login`, whatever the file holds. `--offline` reads no keychain, so it does not. See [Claude Code over SSH uses another account](/troubleshooting#claude-code-over-ssh-uses-another-account).

When an interrupted switch is waiting that the next change cannot finish, `status` warns with `recovery_undetermined` and the message that change would stop with. It finishes nothing; see [Recover after a crash, a restore or a move](/troubleshooting/recovery#an-interrupted-switch-cannot-be-finished). `--offline` gives the same warning wherever it can tell without asking Anthropic. It cannot tell when Claude Code renewed its login after the switch stopped, because only Anthropic can say whose that login is.

To see the last numbers measured, without asking anyone:

```sh
pitboard status --offline
```

```text
● personal  me@example.com  signed in
    5h    ██████░│░░   59%  resets in 1h 10m  18% under pace
    week  █│█████░░░   73%  resets in 5d 18h  55% over pace
          weekly limit runs out in 11h 05m at this pace
          measured 14:02, 3m ago · read without asking Anthropic

○ work      me@company.com  ready · good for 26d 4h
    5h    █░░│░░░░░░   12%  resets in 3h 02m  27% under pace
    week  ████░░│░░░   40%  resets in 2d 4h   29% under pace
          measured 14:02, 3m ago · read without asking Anthropic
```

For what each line means, see [Check what each account has left](/guides/usage#read-the-lines-under-each-account). For the fields of `--json` output, see [JSON output](/reference/json-output#status-data).

## `enroll`

```text
Add an account: the one signed in now, or with --sign-in, another one

Usage: pitboard enroll [OPTIONS] <LABEL>
```

Without `--sign-in`, `pitboard enroll` records the account the tool is signed in to. It parks nothing: that account's login is parked the first time you switch away from it.

With `--sign-in`, Pitboard runs the tool's own sign-in without touching the login in use. Before a browser opens, Pitboard checks that it can load its account list and write where the tool keeps its login. It also checks that the tool's program is on your `PATH`.

Only one sign-in runs at a time. While one runs, Pitboard holds a lock on `~/.pitboard/signin.lock` and refuses a second sign-in until the first finishes.

The sign-in runs in a private directory, `~/.pitboard/signin`, which Pitboard deletes and creates again, with mode 0700, before each sign-in. For Claude Code it runs `claude auth login` with `CLAUDE_CONFIG_DIR` set to that directory. For Codex it runs `codex login` with `CODEX_HOME` set to it.

When the sign-in finishes, Pitboard reads the new login the tool stored. Codex, and Claude Code on Linux, store it in that directory. Claude Code on macOS stores it in a keychain item made for that directory.

Pitboard then deletes the directory and, on macOS, the keychain item Claude Code created for that sign-in.

| Argument | Description |
| --- | --- |
| `<LABEL>` | A short name for this account, such as `personal` or `work`. `codex/work` names a Codex account; a bare name means Claude Code |

| Option | Description |
| --- | --- |
| `--sign-in` | Sign in through the tool's own sign-in, without signing out of the account in use. For the account in use, this puts its new login in use; for another enrolled label, it renews its parked login |

The `enrolled` field of the `--json` output names what happened:

| `enrolled` | When | First line printed |
| --- | --- | --- |
| `current` | Without `--sign-in` | `Enrolled work (me@company.com), the account signed in now.` |
| `signed_in` | With `--sign-in`, for a label not enrolled before, signed in as an account that is not in use | `Enrolled work (me@company.com). Switch to it with: pitboard use work` |
| `renewed` | With `--sign-in`, for an enrolled label whose account is not in use; its parked login is replaced | `Renewed work (me@company.com): its parked login is a fresh one.` |
| `in_use` | With `--sign-in`, signed in as the account in use; the new login replaces the one in use and nothing is parked | `Signed in to work (me@company.com) again. Its new login is the one in use now.` |

For a label not enrolled before, `in_use` prints `Enrolled work (me@company.com), the account signed in now. Its new login is the one in use.` instead.

`enroll` enrols nothing if the account is already enrolled under another label (`already_enrolled`), or if the label names another account (`label_taken`).

If Pitboard cannot tell whose login the tool is using, it parks the new login instead of putting it in use. It warns only when that label is the one it last recorded in use. For the warning and what to do, see [Sign in to an account again](/guides/sign-in-again#if-pitboard-cannot-tell-whose-login-is-in-use).

To add a second Claude Code account:

```sh
pitboard enroll work --sign-in
```

Pitboard prints this line to standard error:

```text
Opening Claude Code's sign-in. Sign in as the account to add; the account in use now stays signed in.
```

Claude Code then opens your browser. What it prints also goes to standard error, so `--json` output stays one line. When you finish signing in, Pitboard prints:

```text
Enrolled work (me@company.com). Switch to it with: pitboard use work
```

For the same task in the app, see [Add and manage accounts](/guides/accounts#add-another-account).

## `use`

```text
Switch a tool to an enrolled account

Usage: pitboard use [OPTIONS] <LABEL>
```

`pitboard use` parks the login the label's tool is using and puts the named account's parked login in its place. The tool must be signed in to an enrolled account. The named account must have a parked login whose refresh token has not expired.

Before anything moves, Pitboard checks that the parked login belongs to that account and that Anthropic or OpenAI still accepts it. If only its access token has expired, Pitboard renews the parked login first. A switch therefore needs the network, for Claude Code and Codex alike.

| Argument | Description |
| --- | --- |
| `<LABEL>` | The label the account was enrolled under, such as `work` or `codex/work` |

If the account is already in use, `use` prints `work is already signed in.` and moves no login. Where Claude Code's config names another account, `use` writes `work` into it, as a switch does, and adds `Claude Code's config named another account, and now names work.` `/status` in Claude Code then shows `work`.

After a switch, it prints `Switched to work; personal is parked.` and one more line. For Claude Code, that line is `Claude Code sessions already running follow within 33 seconds.` On macOS, while `~/.claude/.credentials.json` sits behind the keychain, it is ``Claude Code sessions already running keep the account they are on until their login is next renewed, or until they are started again: /Users/you/.claude/.credentials.json is there. `pitboard doctor` says more.`` instead. See [Open sessions](/concepts/switching#open-sessions). For Codex, it is the second line of the following example.

For every error a switch can end with, and what to do about each, see [Error and warning codes](/reference/errors).

To switch Codex to `codex/work`:

```sh
pitboard use codex/work
```

```text
Switched to codex/work; codex/personal is parked.
Restart any running `codex` for this to take effect. It will not pick the switch up on its own.
```

For what to do with sessions that are already open, see [Switch accounts](/guides/switch#what-happens-to-open-sessions).

## `forget`

```text
Drop an account and its parked login

Usage: pitboard forget [OPTIONS] <LABEL>
```

`pitboard forget` drops an account from Pitboard's list. It deletes the account's parked login and its last usage reading. Deleting a parked login does not revoke it; see [Security and privacy](/security#what-pitboard-protects-against).

The menu bar app then deletes the account's [window](/reference/app#account-windows) data, sign-in included, at its next successful read of the accounts.

`forget` refuses the account in use, and its message says to switch to another account first. It learns which account is in use as a switch does, so it asks Anthropic only about a Claude Code login that changed since Anthropic last named it. Where Anthropic cannot be asked, it refuses the account last in use and any account with nothing parked, with why.

| Argument | Description |
| --- | --- |
| `<LABEL>` | The label to drop |

| Option | Description |
| --- | --- |
| `-y, --yes` | Do not ask first |

At a terminal, without `--yes` or `--json`, `forget` asks first on standard error:

```text
Forget old and delete its parked login? Adding it again needs a browser sign-in. [y/N]
```

For when it asks and what each answer does, see [Output](/reference/commands#output).

To forget `old` without being asked:

```sh
pitboard forget old --yes
```

```text
Forgot old (old@example.com).
```

For the same task in the app, see [Add and manage accounts](/guides/accounts#forget-an-account).

## `rename`

```text
Change the label an account is enrolled under

Usage: pitboard rename [OPTIONS] <FROM> <TO>
```

`pitboard rename` changes only the label. The account keeps its parked login and its last usage reading, because Pitboard files both under the account's id, not its label. An account in use stays in use.

| Argument | Description |
| --- | --- |
| `<FROM>` | The label it has now |
| `<TO>` | The label it should have |

A rename stays inside the account's tool: `pitboard rename codex/work job` gives `codex/job`. Pitboard refuses a `<TO>` that another account of that tool already has. Naming the other tool in `<TO>`, as in `pitboard rename work codex/work`, fails with exit status 2:

```text
error: `work` is a claude account, and a rename cannot move it to codex. Sign in to that tool and enrol the account there instead.
```

To fix a label:

```sh
pitboard rename wrong right
```

```text
Renamed wrong to right (me@company.com).
```

For the same task in the app, see [Add and manage accounts](/guides/accounts#rename-an-account).

## `watch`

```text
Switch Claude Code to another of your accounts before the one in use runs out, for as long as this runs

Usage: pitboard watch [OPTIONS]
```

`pitboard watch` switches Claude Code to another enrolled account once a limit of the account in use reaches a share, 95% unless `--at` gives another. It never switches Codex, because a running `codex` keeps its account until it is started again. [Switch before an account runs out](/guides/automatic-switching) says which account Pitboard picks, what it never does and how the app does the same.

| Option | Description |
| --- | --- |
| `--at <PERCENT>` | Switch once a limit of the account in use reaches this share, from 50 to 99 [default: 95] |
| `--once` | Decide once from the usage Pitboard last measured, asking no service for usage, and stop |

A share outside 50 to 99, or one that is not a whole number, fails with exit status 2.

`watch` runs in the foreground until you press Control-C. Running it is what turns automatic switching on, whatever the app's **Switch Claude Code automatically** setting says. Nothing installs it, and it starts nothing that outlives it.

While it runs, `watch`:

- Reads every account when it starts and every 5 minutes, as the app does. Each account is asked about only as often as [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) allows.
- Looks every 2 seconds at when the account list and usage readings were last written, such as by a [status line](/guides/status-line) after a response. It decides again when either has changed.
- Decides again at least every 30 seconds, even when nothing was written.

A decision first reads Pitboard's files and sends no request. Unless a switch may be due, or Pitboard's record of whose login is stored is in doubt, it takes no lock and records nothing. Otherwise, holding Pitboard's lock, it tells whose login Claude Code has stored, as a switch does, before it decides. [Who starts a switch](/concepts/switching#who-starts-a-switch) says when that record is in doubt.

A switch is the one `pitboard use` makes, with the same checks and journal. [`pitboard log`](/reference/maintenance-commands#log) records it with the verb `auto-switch`.

`watch`, the app and your own `pitboard use` can run at once without making two switches from one reading. See [Who starts a switch](/concepts/switching#who-starts-a-switch).

`watch` prints a line when it starts, then a line for each switch. Each line but the first starts with the local time, such as `14:02:11`.

It names the account it watches whenever its last line said something else. That is once it has read your accounts, and after a switch, a reason, a wait or an error. It prints each thing that stops a switch once, until the next switch. A reason not to switch away from a limit is printed once for that limit and its reset. A wait is printed once for when it ends.

| Output | When |
| --- | --- |
| `Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 95%. Stop with Ctrl-C.` | `watch` starts. |
| `Watching work: 62% of its 5-hour limit, as of 14:00.` | No limit of the account in use has reached the share. The line names its fullest limit that has not reset, and when Pitboard read it. While Anthropic holds Pitboard off asking about the account, as after a rate limit, the line ends `Anthropic holds Pitboard off asking again until 15:28.` |
| `Switched Claude Code from work to personal: work has used 96% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.` | It switched. While a login file sits behind the keychain, the last sentence says when open sessions follow instead, as for `use`. |
| `work has used 97% of its 5-hour limit, and no other Claude Code account has room below 95% in every limit.` | A limit reached the share, and no other account has room. Nothing moves. Where Anthropic has given no reading of an account it could switch to yet, the line ends `, and there is no reading of personal from Anthropic yet.` |
| `work has used 96% of its 5-hour limit. Pitboard tries again at 14:03.` | A try at switching away from a limit came to nothing, and Pitboard waits before the next. The line names the limit it tries then. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: this limit was switched away from once already, and is not again before it resets.` | Pitboard switched away from the limit before, and the account was put back in use before it reset. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: 3 attempts to switch away from this limit failed, and none is made again before it resets.` | Three tries at the limit failed for a reason that trying again does not mend. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: the account was put in use less than 5 minutes ago. It decides again at 14:07.` | The account was put in use less than 5 minutes ago. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: Claude Code signs in another way, set by ANTHROPIC_API_KEY in the environment, so a switch would change nothing its sessions use.` | A limit reached the share and another account has room, but something other than the login Pitboard switches signs Claude Code in, as `pitboard doctor` warns. The line names each setting and where it is set. |
| `Pitboard is not switching Claude Code: <reason>.` | Pitboard cannot decide whether to switch at all. |

A limit for one model is named with its model, as in `97% of its weekly Opus limit`.

`<reason>` is one of these:

| `<reason>` | When |
| --- | --- |
| `` a switch was interrupted, and the next change you make finishes it, or give up on it with `pitboard abandon` `` | A switch did not finish. |
| `Claude Code uses a custom OAuth endpoint, and Pitboard does not act on Claude Code then` | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set. |
| `Claude Code has no login stored` | Claude Code is signed out. |
| `Claude Code has me@example.com's login stored, and that account is not enrolled` | Claude Code is signed in to an account you have not enrolled. |
| `whose login Claude Code has stored could not be told (could not reach Anthropic: timed out). It asks again at 14:03` | Pitboard could not tell whose the login is, for the reason in brackets. It tries again at that time, as [When it holds back](/guides/automatic-switching#when-it-holds-back) describes. |
| `there is no reading of work from Anthropic yet` | Anthropic has given no reading of the account in use, as after an update of Pitboard. |

A switch that fails prints its error on standard error, as `pitboard use` would, and `watch` goes on. Each error code is printed once until the next switch. [What it never does](/guides/automatic-switching#what-it-never-does) says how Pitboard waits after a try that came to nothing.

After an error, `watch` makes no decision that takes Pitboard's lock for 1 minute. It waits twice as long after each error in a row, up to 15 minutes, and any other outcome ends the row. Meanwhile it still reads Pitboard's files and prints what they show.

Warnings found while deciding, such as `fallback_login` while a login file sits behind the keychain, follow the line on standard error. Each is printed once until the next switch, even if it goes away and comes back. A warning not printed yet comes with the line of the decision that found it, even when that line was printed before.

`watch` ends, with the error and its exit status, when it may change nothing or cannot use Pitboard's own files. That is when it runs as root or with `sudo` (`elevated`), or on a Windows build (`windows_not_released`). It also ends with any error from [The Pitboard directory](/reference/errors#the-pitboard-directory).

If you press Control-C while a switch runs, the next change Pitboard makes finishes or undoes it, as [Interrupted switches](/concepts/switching#interrupted-switches) describes.

With `--once`, `watch` decides once from the usage Pitboard last measured, without asking any service for usage. It prints what it came to, without a start line or the time. When there is nothing to do, that is the line naming the account it watches. A decision that takes Pitboard's lock may ask Anthropic whose login Claude Code has stored, as a switch does. A switch it makes still checks the parked login with Anthropic, as `pitboard use` does. It exits 0, or with the error's status if it ends with one.

With `--json`, `watch` prints one line of JSON for each event, and `--once` prints one. For the fields, see [Watch events](/reference/json-output#watch-events).

To switch once a limit reaches 90%, and keep watching:

```sh
pitboard watch --at 90
```

```text
Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 90%. Stop with Ctrl-C.
13:41:05 Watching work: 82% of its 5-hour limit, as of 13:41.
14:02:11 Switched Claude Code from work to personal: work has used 91% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.
14:02:13 Watching personal: 12% of its 5-hour limit, as of 14:01.
```
