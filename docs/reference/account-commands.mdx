## `status`

```text
Usage: pitboard status [OPTIONS]
```

| Option | Description |
| --- | --- |
| `--offline` | Answer from what was last measured, without asking anyone |
| `--fresh` | Ask about every account, even one asked about moments ago |

The two options cannot be given together.

`status` first renews each parked login whose access token has expired or expires within 2 minutes. It then asks about every account at once: Anthropic for Claude Code accounts, OpenAI for Codex ones. Each request times out after 5 seconds. [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) says when an account is asked again, and what `--fresh` changes.

`--offline` sends no request and writes nothing. It takes the account in use from Pitboard's record for Claude Code, and from the login itself for Codex. [How Pitboard knows whose login it is](/concepts/switching#how-pitboard-knows-whose-login-it-is) explains both.

`status` exits 0 when a service cannot be reached, and that account's last line says why. It exits 1 on an error in [The Pitboard directory](/reference/errors#the-pitboard-directory).

| Warning | When | With `--offline` |
| --- | --- | --- |
| `parked_login_refused` | Anthropic or OpenAI refused a parked login for good during renewal. Pitboard dropped it. | No |
| A renewal error, such as `renewal_failed` | Renewing a parked login failed for another reason. | No |
| `recovery_undetermined` | An interrupted switch is waiting that the next change cannot finish. | Where Pitboard can tell without asking Anthropic |
| `login_replaced` | A sign-in outside Pitboard replaced an account's only login. | Yes |
| `in_use_unconfirmed` | Claude Code's config has named another account since Anthropic last identified the login stored. | Yes |
| `config_names_another` | Claude Code's config names another account than the one whose login is stored. | Yes |
| `fallback_login` | On macOS, `~/.claude/.credentials.json` sits behind the keychain. | No |
| `read_only` | `status` runs as root or under `sudo`, and answers as `--offline` does. | No |

[Warning codes](/reference/errors#warning-codes) gives each message and what to do.

```sh
pitboard status --offline
```

```text
● personal  me@example.com  signed in
    5h    ██████░│░░   59%  resets in 1h 10m  18% under pace
    week  █│█████░░░   73%  resets in 5d 18h  55% over pace
          weekly limit runs out in 11h 05m at this pace
          measured 14:02, 3m ago · read without asking Anthropic

○ work      me@company.com  ready · good for 26d 4h
    5h    █░░│░░░░░░   12%  resets in 3h 02m  27% under pace
    week  ████░░│░░░   40%  resets in 2d 4h   29% under pace
          measured 14:02, 3m ago · read without asking Anthropic
```

A Codex account's last line ends `read without asking OpenAI` instead. [Read the lines under each account](/guides/usage#read-the-lines-under-each-account) says what each line means, and [Status data](/reference/json-output#status-data) lists the `--json` fields.

## `enroll`

```text
Usage: pitboard enroll [OPTIONS] <LABEL>
```

| Argument or option | Description |
| --- | --- |
| `<LABEL>` | The account's label, such as `work`, or `codex/work` for a Codex account |
| `--sign-in` | Sign in through the tool's own sign-in, without signing out of the account in use |

Without `--sign-in`, `enroll` records the account the tool is signed in to. It parks nothing: [Parked logins](/concepts/switching#parked-logins) says why.

With `--sign-in`, Pitboard runs the tool's own sign-in in `~/.pitboard/signin`. Before each sign-in, it deletes that directory and makes it again with mode 0700.

| Tool | Command | Where the tool stores the new login |
| --- | --- | --- |
| Claude Code | `claude auth login`, with `CLAUDE_CONFIG_DIR` set to the directory | On macOS, a keychain item made for the directory. On Linux, `.credentials.json` in it. |
| Codex | `codex -c 'cli_auth_credentials_store="file"' login`, with `CODEX_HOME` set to the directory | `auth.json` in the directory |

Pitboard reads the new login from there, then deletes the directory and, on macOS, that keychain item. A lock on `~/.pitboard/signin.lock` keeps sign-ins to one at a time.

The `enrolled` field of `--json` output names the outcome.

| `enrolled` | When | First line |
| --- | --- | --- |
| `current` | Without `--sign-in` | `Enrolled personal (me@example.com), the account signed in now.` |
| `signed_in` | A label not enrolled before, signed in as an account that is not in use | `Enrolled work (me@company.com). Switch to it with: pitboard use work` |
| `renewed` | An enrolled label not in use. Its parked login is replaced. | `Renewed work (me@company.com): its parked login is a fresh one.` |
| `in_use` | The label of the account in use. The new login replaces the one in use. | `Signed in to personal (me@example.com) again. Its new login is the one in use now.` |
| `in_use` | A label not enrolled before, signed in as the account in use | `Enrolled personal (me@example.com), the account signed in now. Its new login is the one in use.` |

`current` adds a second line: `Add another without signing out of it: pitboard enroll <label> --sign-in`. For a Codex account, it has `codex/<label>`.

If Pitboard cannot identify the login in use, it parks the new login instead of replacing that one. It warns `sign_in_parked_not_in_use` only when the label is the account Pitboard last recorded in use. [If Pitboard cannot identify the login in use](/guides/sign-in-again#if-pitboard-cannot-identify-the-login-in-use) says what to do.

`enroll` refuses with these codes. With `--sign-in`, Pitboard checks the first five before your browser opens.

| Code | When |
| --- | --- |
| `custom_oauth_endpoint` | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, for a Claude Code label. |
| `live_store_unsupported` | Pitboard cannot write where the tool keeps its login, such as a Codex store other than `file`. See [Before you enrol a Codex account](/guides/codex#before-you-enrol-a-codex-account). |
| `sign_in_not_isolated` | The tool's sign-in would not stay inside the private directory. |
| `claude_program_missing`, `codex_program_missing` | Pitboard cannot find the tool's program. |
| `sign_in_in_progress` | Another sign-in is running. |
| `sign_in_incomplete` | The tool's sign-in failed or stored no login. |
| `live_credential_absent` | Without `--sign-in`, the tool is not signed in. |
| `already_enrolled` | The account is enrolled under another label. |
| `label_taken` | The label names another account. |

To add a second Claude Code account:

```sh
pitboard enroll work --sign-in
```

This line and Claude Code's own output go to standard error. For an enrolled label, the line names the account's email.

```text
Opening Claude Code's sign-in. Sign in as the account to add; the account in use now stays signed in.
```

Claude Code then opens your browser. Once you sign in, Pitboard prints:

```text
Enrolled work (me@company.com). Switch to it with: pitboard use work
```

## `use`

```text
Usage: pitboard use [OPTIONS] <LABEL>
```

| Argument | Description |
| --- | --- |
| `<LABEL>` | The account's label, such as `work` or `codex/work` |

`use` parks the login the label's tool has stored and puts the account's parked login in its place. Before anything moves, it refuses with:

| Code | When |
| --- | --- |
| `live_credential_absent` | The tool is not signed in. |
| `live_account_not_enrolled` | The tool is signed in to an account you have not enrolled. |
| `nothing_parked` | The account has no parked login. |
| `parked_login_expired` | The parked login's refresh token has expired. |
| `parked_login_refused` | Anthropic or OpenAI no longer accepts the parked login. |
| `parked_login_belongs_elsewhere` | The parked login is another account's. |
| `identity_unverifiable` | Anthropic or OpenAI could not be reached to check a login. |

Before it switches, `use` has Anthropic or OpenAI identify the parked login. It renews that login first when its access token has expired. A switch needs the network for both tools. [Switching](/reference/errors#switching) lists what else can stop one.

For the account in use, `use` moves no login and prints `work is already signed in.` Where Claude Code's config names another account, `use` writes `work` there and adds `Claude Code's config named another account, and now names work.` The `--json` field `config_updated` is then `true`.

After a switch, `use` prints `Switched to work; personal is parked.` and a second line:

| Tool | Second line |
| --- | --- |
| Claude Code | `Claude Code sessions already running follow within 33 seconds.` |
| Claude Code on macOS, with a login file behind the keychain | ``Claude Code sessions already running keep the account they are on until their login is next renewed, or until they are started again: /Users/you/.claude/.credentials.json is there. `pitboard doctor` says more.`` |
| Codex | ``Restart any running `codex` for this to take effect. It will not pick the switch up on its own.`` |

[Open sessions](/concepts/switching#open-sessions) explains both Claude Code lines.

After a Codex switch, `use` can also warn:

| Warning | When |
| --- | --- |
| `sessions_still_running` | Something started before the switch still runs Codex. |
| `sessions_unknown` | Pitboard could not read the list of processes. |
| `written_on_the_command_line` | On macOS, Pitboard passed the parked login to `security` as an argument. See [Large logins on macOS](/security#large-logins-on-macos). |

```sh
pitboard use codex/work
```

```text
Switched to codex/work; codex/personal is parked.
Restart any running `codex` for this to take effect. It will not pick the switch up on its own.
```

## `forget`

```text
Usage: pitboard forget [OPTIONS] <LABEL>
```

| Argument or option | Description |
| --- | --- |
| `<LABEL>` | The label to drop |
| `-y, --yes` | Do not ask first |

`forget` drops the account from Pitboard's list and deletes its parked login and its last usage reading. Pitboard does not revoke the login it deletes: see [What Pitboard does not protect against](/security#what-pitboard-does-not-protect-against).

The app deletes the account's window data, sign-in included, at its next read of the accounts. [Where account windows keep their data](/security#where-account-windows-keep-their-data) has the rules.

| Code | When |
| --- | --- |
| `cannot_forget_active_account` | The account is in use. |
| `identity_unverifiable` | Pitboard cannot identify the login in use, and the account is the one last in use or has no parked login. |

At a terminal, without `--yes` or `--json`, `forget` asks on standard error:

```text
Forget old and delete its parked login? Adding it again needs a browser sign-in. [y/N]
```

[Questions before deleting](/reference/commands#questions-before-deleting) says when it asks and what each answer does.

```sh
pitboard forget old --yes
```

```text
Forgot old (old@example.com).
```

## `rename`

```text
Usage: pitboard rename [OPTIONS] <FROM> <TO>
```

| Argument | Description |
| --- | --- |
| `<FROM>` | The label it has now |
| `<TO>` | The label it should have |

`rename` changes only the label. The account keeps its parked login, its usage reading and its account window, and stays in use if it is.

A rename stays inside the account's tool: `pitboard rename codex/work job` gives `codex/job`.

| Code | When | Exit status |
| --- | --- | --- |
| `label_taken` | Another account of the same tool has the label `<TO>`. | 1 |
| `usage` | `<TO>` names the other tool, as in `pitboard rename work codex/work`. | 2 |

```sh
pitboard rename wrong right
```

```text
Renamed wrong to right (me@company.com).
```

## `watch`

```text
Usage: pitboard watch [OPTIONS]
```

| Option | Description |
| --- | --- |
| `--at <PERCENT>` | Switch once a limit of the account in use reaches this share: a whole number from 50 to 99, 95 by default |
| `--once` | Decide once from the usage Pitboard last measured, asking no service for usage, and stop |

`watch` switches Claude Code only, never Codex. [Switch before an account runs out](/guides/automatic-switching) gives the rules it follows.

It runs in the foreground until you press Control-C, whether the app's **Switch Claude Code automatically** setting is on or off. Nothing installs it, and it starts nothing that outlives it.

While it runs, `watch`:

- Reads every account when it starts and every 5 minutes, as often as [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) allows.
- Looks every 2 seconds at when the account list and usage readings were last written, and decides again when either changed.
- Decides at least every 30 seconds.

On standard output, each line but the first starts with the local time, such as `14:02:11`.

| Line | When |
| --- | --- |
| `Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 95%. Stop with Ctrl-C.` | It starts. |
| `Watching work: 62% of its 5-hour limit, as of 14:00.` | No limit of the account in use has reached the share. The line names its fullest limit that has not reset. While Anthropic holds Pitboard off asking about the account, it ends `Anthropic holds Pitboard off asking again until 15:28.` |
| `Switched Claude Code from work to personal: work has used 96% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.` | It switched. The last sentence is the second line `use` prints. |
| `work has used 97% of its 5-hour limit, and no other Claude Code account has room below 95% in every limit.` | No other account qualifies. Where Anthropic has given no reading of one that could, the line ends `in every limit, and there is no reading of personal from Anthropic yet.` |
| `work has used 96% of its 5-hour limit. Pitboard tries again at 14:03.` | A try came to nothing, and Pitboard waits before the next. |
| `work has used 96% of its 5-hour limit. Pitboard is not switching: <reason>.` | It stays on the account, for a reason in the first list. |
| `Pitboard is not switching Claude Code: <reason>.` | It cannot decide whether to switch, for a reason in the second list. |

A limit of one model is named with its model, as in `97% of its weekly Opus limit`.

`<reason>` after `Pitboard is not switching:` is one of:

- `this limit was switched away from once already, and is not again before it resets`
- `3 attempts to switch away from this limit failed, and none is made again before it resets`
- `the account was put in use less than 5 minutes ago`, followed by `It decides again at 14:07.`
- `Claude Code signs in another way, set by ANTHROPIC_API_KEY in the environment, so a switch would change nothing its sessions use`, naming each setting and where it is set

`<reason>` after `Pitboard is not switching Claude Code:` is one of:

- `` a switch was interrupted, and the next change you make finishes it, or give up on it with `pitboard abandon` ``
- `Claude Code uses a custom OAuth endpoint, and Pitboard does not act on Claude Code then`
- `Claude Code has no login stored`
- `Claude Code has me@example.com's login stored, and that account is not enrolled`
- `whose login Claude Code has stored could not be told (could not reach Anthropic: no route to host). It asks again at 14:03`
- `there is no reading of work from Anthropic yet`

`watch` names the account it watches whenever its last line said something else. Until the next switch, it prints each reason, wait and error code once. A warning also comes once, on standard error, with the line of the decision that found it.

A switch that fails prints its error on standard error, as `pitboard use` would, and `watch` goes on. [When it holds back](/guides/automatic-switching#when-it-holds-back) says what ends each reason and how long Pitboard waits after a failure.

`watch` ends with the error's exit status when it runs as root or under `sudo` (`elevated`). It also ends on an error in [The Pitboard directory](/reference/errors#the-pitboard-directory).

With `--once`, `watch` prints only the line of one decision, with no start line or time. It may still ask Anthropic to identify Claude Code's stored login, and a switch checks the parked login as `use` does. It exits 0, or with the error's status.

With `--json`, `watch` prints one line of JSON per event. [Watch events](/reference/json-output#watch-events) lists the fields.

```sh
pitboard watch --once
```

```text
Watching work: 62% of its 5-hour limit, as of 14:00.
```
