The app and `pitboard watch` pick an account by the same rules, and give each reason in the same words. The app shows it in a notification, as the [menu bar app](/reference/mac-app#notifications) and [the app on Windows](/reference/windows-app#notifications) list, and under the share in [Settings](/reference/settings#when-a-limit-reaches). `pitboard watch` prints it in [its lines](/reference/account-commands#watch), and with `--json` gives the code in [`reason`](/reference/json-output#watch-events).

## Which account it switches to

Pitboard watches every limit of the account in use, a model's weekly limit included. A limit counts at the whole percentage Pitboard shows, so 94.5% reaches 95%.

Once a limit reaches the share, Pitboard looks for another enrolled Claude Code account that:

- Has a parked login that has not expired.
- Has a reading from Anthropic.
- Has used less than the share of every limit it has.
- Has not been passed over at this limit, as [When a try fails](#when-a-try-fails) says.

Of those, Pitboard picks by these rules, in order:

1. An account without a weekly limit for all models goes first, such as a Team seat. What it leaves unused is lost at each five-hour reset.
2. Then the most room in the limit at the share. An account without that limit counts as having used none of it.
3. On a tie, the account least full in its other limits.

A limit past its reset time counts as reset.

A reading may leave a limit out when Anthropic answers without its list of limits, or Pitboard cannot read the answer whole. Such a reading qualifies only with the five-hour and weekly limits, and with a model's weekly limit when that one is at the share. Pitboard counts it as having a weekly limit for all models.

When several limits are at the share, Pitboard acts on the fullest one it has not already left or given up on.

The app's offer once an account runs out follows the same rules at 100%.

## When it stays on the account

Once a limit of the account in use reaches the share, Pitboard stays on the account while one of these holds. `pitboard log` records `auto-stay` with the code, once for each limit and its reset.

| Code | Text | Ends when |
| --- | --- | --- |
| `no_room` | `no other Claude Code account has room below 95% in every limit` | Another account [qualifies](#which-account-it-switches-to), or the limit resets. |
| `already_switched` | `this limit was switched away from once already, and is not again before it resets` | The limit resets. |
| `attempts_spent` | `3 attempts to switch away from this limit failed, and none is made again before it resets` | The limit resets. |
| `settling` | `the account was put in use less than 5 minutes ago` | 5 minutes pass. |
| `auth_overridden` | `Claude Code signs in another way, set by ANTHROPIC_API_KEY in the environment, so a switch would change nothing its sessions use` | You remove that setting, which `pitboard doctor` also names. |

Where Anthropic has given no reading of an account that could qualify, `no_room` ends `, and there is no reading of personal from Anthropic yet`.

`settling` counts from the switch, sign-in or enrolment that put the account in use.

In JSON, `no_room` is an event of its own. The other codes are the `reason` of a `skipped` event.

## When it decides nothing

While one of these holds, Pitboard does not decide whether to switch.

| Code | Text | Ends when |
| --- | --- | --- |
| `switch_interrupted` | `a switch was interrupted, and the next change you make finishes it` | Your next change finishes it, or [`pitboard abandon`](/reference/recovery-commands#abandon) gives up on it. |
| `custom_oauth_endpoint` | `Claude Code uses a custom OAuth endpoint, and Pitboard does not act on Claude Code then` | You unset [`CLAUDE_CODE_CUSTOM_OAUTH_URL`](/reference/environment-variables#custom-oauth-endpoint). |
| `nothing_signed_in` | `Claude Code has no login stored` | You sign in. |
| `not_enrolled` | `Claude Code has me@example.com's login stored, and that account is not enrolled` | You enrol it. |
| `not_identified` | `whose login Claude Code has stored could not be told (could not reach Anthropic)` | A later try identifies it. |
| `no_reading` | `there is no reading of work from Anthropic yet` | Pitboard's next read gets one. |

## When a try fails

Pitboard records each try in `autoswitch.json` before anything moves, so a try stopped partway still counts. The next try waits 1 minute, and each failure in a row doubles the wait, up to 15 minutes. A failure that may pass, such as Anthropic out of reach, does not count toward `attempts_spent`.

These refusals over the account a try would switch to pass that account over until the limit resets. The next try picks another at once.

| Code | When |
| --- | --- |
| `account_unknown` | The account is no longer enrolled. |
| `nothing_parked` | The account has no parked login. |
| `parked_credential_missing` | Its parked login is missing. |
| `parked_login_expired` | Its parked login has expired. |
| `parked_login_refused` | Anthropic no longer accepts its parked login. |
| `parked_credential_corrupt` | Its parked login is damaged. |
| `parked_login_belongs_elsewhere` | Its parked login is another account's. |
| `identity_unverifiable` | Anthropic refuses for good to identify its parked login. |
| `renewal_failed` | Anthropic refuses for good to renew its parked login. |
| `account_on_hold` | Anthropic has put the account on hold. |
