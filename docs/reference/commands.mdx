Commands follow the order of `pitboard --help`.

| Command | What it does |
| --- | --- |
| [`status`](/reference/account-commands#status) | Show who is signed in, and what each Claude Code and Codex account has left |
| [`use`](/reference/account-commands#use) | Switch a tool to an enrolled account |
| [`enroll`](/reference/account-commands#enroll) | Add an account: the one signed in, or another with `--sign-in` |
| [`rename`](/reference/account-commands#rename) | Change an account's label |
| [`forget`](/reference/account-commands#forget) | Forget an account and delete its parked login |
| [`watch`](/reference/account-commands#watch) | Stay running, switch Claude Code before the account in use runs out, and warm up accounts, in a terminal or as a background service |
| [`warm`](/reference/account-commands#warm) | Choose which accounts Pitboard warms up and when, or warm one up now |
| [`statusline`](/reference/integration-commands#statusline) | Print one line for Claude Code's status line |
| [`renew`](/reference/maintenance-commands#renew) | Renew every parked login that is due |
| [`schedule`](/reference/maintenance-commands#schedule) | Install, check or remove the daily renewal schedule |
| [`vault`](/reference/maintenance-commands#vault) | Say where parked logins are kept, or on Linux move them between the login keyring and files |
| [`log`](/reference/maintenance-commands#log) | List what Pitboard changed, and when |
| [`doctor`](/reference/maintenance-commands#doctor) | Check that what Pitboard relies on still holds |
| [`uninstall`](/reference/maintenance-commands#uninstall) | Delete the parked logins this Pitboard wrote, its schedule, watch service and directory |
| [`stow`](/reference/recovery-commands#stow) | Put away a login file behind the keychain or Credential Manager |
| [`repair`](/reference/recovery-commands#repair) | Account for every parked login on this computer |
| [`abandon`](/reference/recovery-commands#abandon) | Give up on an interrupted switch or Claude Desktop move, keeping every login |
| [`adopt`](/reference/recovery-commands#adopt) | Take over a Pitboard directory from another computer |
| [`completions`](/reference/integration-commands#completions) | Print a shell completion script |
| [`help`](#global-options) | Print the help of `pitboard` or of a command |
| [`manpage`](/reference/integration-commands#manpage) | Print the man page |

`pitboard --help` and the shell completions leave out `manpage`. On Windows, the help names no Claude Desktop label.

## Default command

`pitboard` alone runs `pitboard status`, and `pitboard --json` runs `pitboard status --json`. The options of `status` need its name: `pitboard status --offline`.

## Global options

| Option | What it does |
| --- | --- |
| `--json` | Print the result as one JSON envelope, described in [JSON output](/reference/json-output) |
| `-h`, `--help` | Print help |
| `-V`, `--version` | Print the version |

- Every command but `help` takes `--help`.
- Every command but `help`, `completions` and `manpage` takes `--json`.
- `--json` goes before or after the command: `pitboard --json use work` is `pitboard use work --json`.
- `pitboard help <command>` prints the same help as `pitboard <command> --help`.
- Only `pitboard` itself takes `--version`.

## Labels

A label names one account within its tool, so each tool can have a `work`. Labels compare exactly: `Work` and `work` are two labels.

A label you choose, for `pitboard enroll` or as the second label of `pitboard rename`, follows these rules. Breaking one exits 2 with error code `usage`.

| Rule | Refused |
| --- | --- |
| One word, with no spaces or control characters. `é` and `工` are allowed. | `two words`, `""` |
| An optional tool prefix: `claude/`, `codex/` or `desktop/`, in lower case | `codx/work`, `Codex/work` |
| A name after the prefix | `codex/` |
| No `/` but the prefix's | `codex/a/b` |
| `rename` keeps the account in its tool | `rename work codex/job`, where `work` is a Claude Code account |

What a bare label, one with no prefix, means depends on the command:

| Where | A bare `work` means |
| --- | --- |
| `pitboard enroll` | The Claude Code account `work` |
| `pitboard use`, `pitboard forget`, the first label of `pitboard rename` | Whichever tool has a `work`, refused if more than one does |
| The second label of `pitboard rename` | `work` in the account's own tool |

Pitboard writes a label the way a command takes it:

| Account | Written |
| --- | --- |
| Claude Code's `work` | `work` |
| Claude Code's `work`, where another tool has a `work` too | `claude/work` |
| Codex's `work` | `codex/work` |
| Claude Desktop's `work` | `desktop/work` |

Against the enrolled accounts, a label fails with exit status 1:

| Case | Code |
| --- | --- |
| No account has the label | `account_unknown` |
| More than one tool has the bare label | `label_ambiguous` |
| The prefix is not a tool | `provider_unknown` |
| `enroll` or `rename` chose a label another account of the tool holds | `label_taken` |

On Windows and Linux, `pitboard enroll` refuses a `desktop/` label with `live_store_unsupported` and exit status 3.

## Output

| What | Where |
| --- | --- |
| The result | Standard output |
| `error: <message>`, `warning: <message>` and a refused command line | Standard error |
| With `--json`, all of these as one line of JSON; for `watch`, one line per event | Standard output |
| `--help` and `--version`, as text even with `--json` | Standard output |
| The question before deleting | Standard error |
| The `Opening` line and the tool's own sign-in text from a Claude Code or Codex `pitboard enroll --sign-in` | Standard error |
| The lines a Claude Desktop `pitboard enroll --sign-in` prints while it waits for Claude | Standard error |

Pitboard colours output to a terminal, and none to a file or a pipe. JSON output never has colour.

`NO_COLOR`, set and not empty, turns colour off. `CLICOLOR_FORCE`, set and not empty, turns it on for a file or a pipe too. `NO_COLOR` wins when both are set.

[`statusline`](/reference/integration-commands#statusline) has its own colour rules.

## Questions before deleting

`pitboard forget`, `pitboard stow` and `pitboard uninstall` ask before they delete anything. They ask when standard input and standard error are both terminals and `--json` is not given. `--yes` or `-y` skips the question.

Only `y`, `Y` and `yes` go ahead. Any other answer, an empty one included, changes nothing, prints nothing more and exits 0.

With standard input or standard error redirected, as in a script or `2>/dev/null`, or with `--json`, each needs `--yes`. Without it, the command changes nothing and exits 2 with [`confirmation_needed`](/reference/errors#command-output).

With nobody to ask, these answer as they do with `--yes`:

- `pitboard stow` with nothing behind the keychain or Credential Manager, as always on Linux, or with a login of an account not enrolled.
- `pitboard forget` with a label that names no account. It fails with that label's error, such as `account_unknown`.
- `pitboard forget` and `pitboard uninstall` where Pitboard may change nothing, and `pitboard stow` there once it finds a file to put away. Each fails with the reason, [`elevated`](/reference/errors#root-sudo-and-administrator) or [`system_too_old`](/reference/errors#windows).

With nobody to ask, a refusal found only once the command runs shows only with `--yes`. Without it, the answer is `confirmation_needed`. Forgetting the account in use is one, with `cannot_forget_active_account`. `identity_unverifiable`, `custom_oauth_endpoint`, `app_open` and `uninstall`'s `pitboard_open` are others.

`pitboard use` asks only where Anthropic refuses the refresh token of Claude Code's login in use for good, before it puts the account's login in its place. It asks and takes `--yes` as these do. With nobody to ask and no `--yes`, it changes nothing and exits 1 with [`live_login_refused`](/reference/errors#switching).

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The command did what was asked, or found nothing to do |
| `1` | A request could not be met, such as an unknown label or a service that did not answer |
| `2` | The command line was wrong |
| `3` | A login or a tool's files are in a state Pitboard will not act on, such as Codex signed in with an API key |

`pitboard doctor` also exits 3 when a check fails.

Exit status 2 covers:

- An unknown command or option, or an extra word: `pitboard status --verbose`, `pitboard status work`.
- A missing argument: `pitboard use`.
- A value out of range or not offered: `pitboard watch --at 40`, `pitboard completions fish2`.
- `--offline` together with `--fresh`.
- `pitboard schedule` with no subcommand, which prints its help on standard error.
- A chosen label that breaks a rule in [Labels](#labels).
- `--json` on `help`, `completions` or `manpage`.
- `forget`, `stow` or `uninstall` without `--yes` where it cannot ask, as [Questions before deleting](#questions-before-deleting) describes.

`status`, `renew` and `statusline` report some failures in their output and still exit 0. Each command's entry says which.

For the exit status of every error code, see [Error and warning codes](/reference/errors).
