description: "The `--json` envelope, each command's `data`, status rows, `watch` events and stale codes."

With `--json`, every command prints one line of JSON on standard output, whether it succeeds or fails. `pitboard watch` prints one per event.

## The envelope

```sh
pitboard rename wrong right --json
```

It prints this on one line:

```json
{
  "v": 1,
  "command": "rename",
  "ok": true,
  "data": {
    "from": "wrong",
    "to": "right",
    "email": "me@example.com"
  },
  "warnings": [],
  "error": null
}
```

<ResponseField name="v" type="integer" required>
  The envelope's version, `1`. Pitboard adds fields and codes without changing it.
</ResponseField>

<ResponseField name="command" type="string | null" required>
  The command that ran, such as `rename`. `pitboard` alone gives `status`, the three `schedule` commands give `schedule`, and `completions` and `manpage` give `generate`.
</ResponseField>

<ResponseField name="ok" type="boolean" required>
  `true` when the command succeeded and exits with status 0. [Exit codes](/reference/commands#exit-codes) lists the other statuses.
</ResponseField>

<ResponseField name="data" type="object | null" required>
  What the command found or did, as [Data by command](/reference/json-output#data-by-command) lists. `null` when the command failed. `doctor` and `generate` keep it when they fail.
</ResponseField>

<ResponseField name="warnings" type="object[]" required>
  One object per warning, with `code` and `message`, or an empty array. A change that failed still lists the warnings it found first. [Warning codes](/reference/errors#warning-codes) lists the codes.
</ResponseField>

<ResponseField name="error" type="object | null" required>
  Set when `ok` is `false`, and `null` otherwise.

  <Expandable title="error fields">
    <ResponseField name="code" type="string">
      A stable code, listed in [Error and warning codes](/reference/errors).
    </ResponseField>

    <ResponseField name="message" type="string">
      What went wrong, in words for a person.
    </ResponseField>

    <ResponseField name="cause" type="object | null">
      What went wrong in a request to Anthropic or OpenAI. `null` on every error that [Cause codes](/reference/errors#cause-codes) does not list.

      <Expandable title="cause fields">
        <ResponseField name="code" type="string">
          A cause code, listed in [Cause codes](/reference/errors#cause-codes).
        </ResponseField>

        <ResponseField name="worth_retrying" type="boolean">
          `true` when the same request could succeed later.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

These failures have a shape of their own:

| Case | `command` | `data` | `error.code` | Exit status |
| --- | --- | --- | --- | --- |
| Pitboard cannot parse the command line | `null` | `null` | `usage` | 2 |
| The command refuses a label, as `pitboard enroll codx/work` does | The command | `null` | `usage` | 2 |
| `forget`, `stow` or `uninstall` where it cannot ask, without `--yes`, as [Questions before deleting](/reference/commands#questions-before-deleting) describes | The command | `null` | `confirmation_needed` | 2 |
| `doctor` finds a check that fails | `doctor` | The whole report | `checks_failed` | 3 |
| `completions` or `manpage`, which have no JSON form | `generate` | `{}` | `output_is_not_a_report` | 2 |

In the last two rows, `error` has no `cause` field.

Every byte is ASCII. Pitboard writes a character outside ASCII as a `\u` escape: the label `Đạt` comes out as `\u0110\u1ea1t`. A character beyond U+FFFF becomes its UTF-16 surrogate pair.

Times are Unix times in seconds, such as `1790474400`. In `log` entries, `at` is a local time instead, such as `2026-09-22T01:01:00+07:00`.

<Note>
  Only `doctor --json` hides email addresses and account ids, behind placeholders such as `<email 1a2b3c4d>`. Email addresses appear in the output of `status`, `enroll`, `forget`, `rename` and `watch`, and in error messages such as `label_taken`. `status` also prints account ids. `repair` prints parked login names, and each name holds an account id.
</Note>

## Data by command

In the order of `pitboard --help`:

| Command | `data` |
| --- | --- |
| `status` | See [Status data](/reference/json-output#status-data). |
| `enroll` | `label` as typed, `provider` (`claude`, `codex` or `desktop`), `email`, and `enrolled`: `current`, `signed_in`, `renewed` or `in_use`, as [`enroll`](/reference/account-commands#enroll) explains. |
| `use`, already in use | `to`, `changed` (`false`) and `config_updated`, `true` where Claude Code's config named another account and `use` wrote this one into it. |
| `use`, after a switch | `from`, `to`, `provider`, `changed` (`true`), `parked_at` (when the login of `from` was parked), `adoption_ceiling_seconds` and `adoption`. |
| `use`, where nothing was signed in | The same, with `from` and `parked_at` set to `null`. |
| `forget` | `label` and `email`. |
| `stow` | `stowed`, `false` when no login file sits behind the keychain or Credential Manager. When `true`, also `path`, the file deleted, and `login`, what became of its login: a code from [`stow`](/reference/recovery-commands#stow). Then `account`, the label of the login's account or `null`, and `dropped`, the file's other keys. |
| `abandon` | `abandoned`, `true` when it gave up a Claude Code or Codex switch, with `from`, `to` and `logins_kept`, a count. `moves_given_up`, one object per Claude Desktop move it gave up, as [Moves given up](/reference/json-output#moves-given-up) lists, or an empty array. |
| `repair` | `given_back`, objects with `label` and `service`, the parked login's name. `deleted`, `strangers` and `unreadable`, lists of parked login names, as [`repair`](/reference/recovery-commands#repair) explains. `set_aside`, the names of the folders it set aside in `parks/`. |
| `adopt` | `adopted`, `false` when the Pitboard directory was already this computer's. When `true`, also `accounts`, the labels kept, `logins_dropped`, the labels whose parked login was dropped, and `set_aside`, the labels whose Claude Desktop parked login was set aside. |
| `renew` | `accounts`, one object per parked login that was due, with `label`, `provider` and `outcome`; and `renewed`, a count. `outcome` is `renewed`, `parked_login_refused`, `renewal_deferred` or an error code, as [`renew`](/reference/maintenance-commands#renew) explains. |
| `schedule install` | `installed` (`true`) and `path`, the job's file. On Windows, `task`, the task's path in Task Scheduler, in place of `path`. |
| `schedule status` | `installed`. When `true`, also `every_seconds` (`86400`) and `path`, or `task` on Windows. Where Pitboard has no scheduler to write, also `supported` (`false`). |
| `schedule uninstall` | `installed` (`false`) and `removed`, `false` when nothing was scheduled. |
| `log` | `entries`, oldest first, each with `at`, `caller` (`cli`, `app` or `unknown`), `verb`, `subject` and `outcome`, as [`log`](/reference/maintenance-commands#log) explains. |
| `uninstall` | The counts `parks_removed`, `parks_pending` (could not be deleted, or a renewal of Claude Code's login not saved yet), `parks_left` (left because another Pitboard may own them) and `set_aside_removed` (folders set aside it deleted), the booleans `home_removed`, `warming_up` (a warm-up running kept the directory) and `schedule_removed`, and `home_kept_by`, the paths of the files that could not be removed, which kept the directory. |
| `rename` | `from`, `to` and `email`. |
| `doctor` | `environment`, the paths, login stores and versions Pitboard found, as [Doctor environment](/reference/json-output#doctor-environment) lists. `checks`, each with `code`, `name`, `level` (`ok`, `warn` or `fail`), `detail` and `advice`, as [`doctor`](/reference/maintenance-commands#doctor) lists. |
| `statusline` | `line`, the status line without colour, as [`statusline`](/reference/integration-commands#statusline) describes. |
| `warm` | `range`, with `from` and `to` as `HH:MM`; `halted`, `null`, or an object with `reason`, a `warm_up_halted` code from [Watch events](/reference/json-output#watch-events), where nothing can be warmed up here; and `accounts`, one object per Claude Code account with `label` and `on`. An account turned on also has `state`: `due`, `running`, `resting`, `waiting` or `held`, with `until` and `next_at` where they are known and, for `held`, `reason`, a code from [Watch events](/reference/json-output#watch-events). |
| `warm on`, `warm off` | `label`, `on`, and `changed`, `false` when it was so already. |
| `warm range` | `range`, with `from` and `to`. |
| `warm now` | `label`, `outcome`, `started` or `running`, and `until`, when its five-hour period resets, or `null` where Anthropic has not said yet. |
| `watch` | One envelope per event, as [Watch events](/reference/json-output#watch-events) lists. |
| `completions`, `manpage` | `{}`, in the failure shape [The envelope](/reference/json-output#the-envelope) gives. |

A Claude Desktop account has no email address, so `email` is empty wherever one of its accounts appears.

`adoption` says how each tool takes up a switch, as [Open sessions](/concepts/open-sessions) explains:

| Case | `adoption` | `adoption_ceiling_seconds` |
| --- | --- | --- |
| Claude Code | `{"follows":"polling","within_seconds":33}` | `33` |
| Claude Code, while a login file sits behind the keychain or Credential Manager | `{"follows":"renewal","path":"/Users/you/.claude/.credentials.json"}` | `null` |
| Codex | `{"follows":"restart","program":"codex"}` | `null` |
| Claude Desktop | `{"follows":"open","app":"Claude"}` | `null` |

### Moves given up

Each object in the `moves_given_up` of `abandon`:

| Field | Type | Meaning |
| --- | --- | --- |
| `provider` | string | `desktop`. |
| `label` | string | The account whose login was moving, as `pitboard use` takes it, such as `desktop/work`. |
| `parked` | integer | `1` when the account holds a parked login afterwards, `0` otherwise. |
| `set_aside` | integer | How many folders the give-up set aside. |
| `left` | array of strings | The items that stay in Claude's data folder. |
| `slot` | string or null | The data folder the move was made in, where it is not the one this run reads. `null` otherwise. |

### Doctor environment

The `environment` of `doctor`. It is `{}` where a variable naming a folder is empty or relative.

| Field | Type | Meaning |
| --- | --- | --- |
| `config_file` | string | Claude Code's config file, such as `~/.claude.json`. |
| `storage_dir` | string | The folder that holds Claude Code's login file and locks, and picks the name of its keychain or Credential Manager item: `CLAUDE_SECURESTORAGE_CONFIG_DIR`, `CLAUDE_CONFIG_DIR` or `~/.claude`. |
| `credential_service` | string | The name of the item that holds Claude Code's login in the keychain on macOS, or in Credential Manager on Windows, such as `Claude Code-credentials`. |
| `credential_store` | string | Where Pitboard found Claude Code's login: `keychain`, `credential_manager`, `file`, `absent`, `unknown` or `unreadable`. |
| `home` | string | The Pitboard directory. |
| `codex` | object | `home`, Codex's folder: `CODEX_HOME`, or else `.codex` in your home, in your profile folder on Windows. `present`, whether that folder exists. `backend`, where Codex keeps its login: `file`, `keyring`, `auto`, `ephemeral`, `secrets` or `unknown`. `login_present`, whether `auth.json` exists, or `null` for any store but `file`. `version`, the version of OpenAI's Codex CLI, or `null`. |
| `desktop` | object | `data_folder`, Claude's data folder, or `null` where Pitboard leaves Claude Desktop alone. `present`, whether that folder exists. `build`, the version of `/Applications/Claude.app`, or `null`. |

## Status data

| Field | Type | Meaning |
| --- | --- | --- |
| `slot` | object | The Claude Code login this output is about. `service` names its item in the keychain on macOS or in Credential Manager on Windows, and no item on Linux. `default` is `true` for `Claude Code-credentials`, the item used when no [environment variable](/reference/environment-variables) picks another. |
| `signed_in` | object or null | The Claude Code account in use: `account_uuid`, `email` and `organization_uuid`. With `--offline`, the account Anthropic last named for the login stored. |
| `signed_in_error` | string or null | Why `signed_in` is `null`, such as `nothing is signed in` or `not asked`. |
| `accounts` | array | One object per enrolled account, Claude Code's first, and the account in use first within each tool. A login in use that no account matches gets one too, and so does a login Pitboard could not read, use or identify. |
| `awaiting` | array | One object per sign-in inside Claude left halfway with an account parked for it, or empty. |

For Codex and Claude Desktop, the account in use is the object in `accounts` with that `provider` and `signed_in` set to `true`.

Each object in `accounts`:

| Field | Type | Meaning |
| --- | --- | --- |
| `label` | string or null | The label without its tool, such as `work`. `null` for a login nobody enrolled. |
| `email` | string | The account's email address. Empty on a Claude Desktop account, and when Pitboard could not identify the login. |
| `account_uuid` | string | The account id, empty when Pitboard could not identify the login. Claude Code: the Anthropic account UUID, which one person's accounts in two organisations share. Claude Desktop: the account UUID Claude's settings named. |
| `organization_uuid` | string or null | The Claude organisation of a Claude Code login. `null` on any other tool's account, and for a login Pitboard could not identify. |
| `signed_in` | boolean | `true` for the account its tool is using. |
| `switchable` | boolean | `true` when `pitboard use` can switch to it: it is not in use, and the `refresh_expires_at` of its parked login has not passed. |
| `parked` | object or null | The parked login's `parked_at` and its expiries, as the next table lists, or `null` when nothing is parked. |
| `lasts` | object or null | `seconds` and `why`. For the account in use, until its first limit runs out at its [pace](/concepts/usage#pace) (`why` is `filling`), or else until its first reset (`resets`). For any other account, until its first reset. `null` when no limit has a reset ahead. |
| `usage` | object or null | The reading: `source`, `observed_at` (when it was taken) and `windows`. `null` when no usage is known. |
| `stale` | string or null | Why the reading is not live, as [Stale codes](/reference/errors#stale-codes) lists. |
| `provider` | string | `claude`, `codex` or `desktop`. |
| `qualified` | string or null | The label with its tool, such as `claude/work`. `null` for a login nobody enrolled. |
| `plan` | string or null | The plan the account's login last said it is on, such as `Max 20x`, `Team 5x` or `Plus`. Pitboard records it when it enrols the account and each time it reads the account's login. `null` where no login Pitboard read said one. |
| `read_at` | integer or null | On the Claude Desktop account in use, when Pitboard last read it in use. `null` on every other account. |
| `reason` | string or null | On a login Pitboard could not read, use or identify, why, as its store or service said. `null` on every other account. |

Which expiries `parked` gives depends on the tool. A time is `null` where it is unknown.

| Tool | `access_expires_at` | `refresh_expires_at` | `session_expires_at` |
| --- | --- | --- | --- |
| Claude Code | A time | A time | Always `null` |
| Codex | A time | Always `null` | Always `null` |
| Claude Desktop | Always `null` | Always `null` | The expiry its session cookie carries |

`source` is `live` when Pitboard asked the service this time. It is `remembered` for the last reading Pitboard recorded, from the command line, the app or a Claude Code status line.

Each object in `windows` is one limit:

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | string | The limit, such as `session` or `five_hour` for a five-hour limit and `weekly_all` or `seven_day` for a weekly one. |
| `scope` | string or null | The model or surface a narrower limit applies to, by the name Anthropic gives it. `null` for the account's own limit, and always for Codex. |
| `percent` | number | How much of the limit is used. Over 100 when the limit is exceeded. |
| `resets_at` | integer or null | When the limit resets. |
| `is_active` | boolean | Anthropic's own `is_active` for the limit. Always `true` for Codex. |
| `severity` | string or null | Anthropic's own grade of the limit. `null` where it gives none, as for every Codex limit. |
| `length_seconds` | integer | How long the limit's period runs, such as `18000`. Left out when unknown. |
| `pace` | object or null | The limit's [pace](/concepts/usage#pace) as of `observed_at`. `expected` is the share an even pace would have used. `delta` is `percent` less `expected`, in percentage points. `standing` is `over`, `under` or `even` (within 5 points). Over pace adds `runs_out_in`, the seconds left until the limit runs out at its rate since its period began. `null` in a period's first 3%, for a limit used up, after its reset, and where its reset or length is unknown. |

Each object in `awaiting`:

| Field | Type | Meaning |
| --- | --- | --- |
| `provider` | string | `desktop`. |
| `label` | string | The label an add enrols under, or the account signed in to again, in the form `pitboard use` takes, such as `desktop/travel`. |
| `put_back` | string | The account parked for it, in the same form. |
| `since` | integer | When the sign-in began. |
| `again` | boolean | `true` for a sign-in again, `false` for an add. |

## Watch events

Each event's envelope has `command` set to `watch`. With `--once`, `watch` prints one event. The `data` of every event has `event`. Every event but the warm-up ones also has `threshold`, the share it switches at, such as `95`.

| `event` | When | Other fields |
| --- | --- | --- |
| `watching` | `watch` starts. Not printed with `--once`. | `warm`, where an account is turned on for warm-ups: `range` and `accounts`, their labels |
| `idle` | No limit of the account in use has reached the share. | `account`, `limit`, `as_of` and `held_until` |
| `switched` | Pitboard switched Claude Code. | `from`, `to`, `limit` and `adoption` |
| `waiting` | A limit reached the share, and a try at switching away came to nothing. | `from`, `limit` and `until` |
| `no_room` | A limit reached the share, and no other account has room. | `from`, `limit` and `unread` |
| `skipped` | A limit reached the share, and Pitboard stays on the account for a `reason`. | `from`, `limit` and `reason`, and `until` for `settling` |
| `not_watching` | Pitboard cannot decide whether to switch. | `reason`, and `email`, `account`, or `detail` and `until`, by reason |
| `warmed_up` | Pitboard warmed up an account. | `account` and `until` |
| `warm_up_held` | An account turned on is held back. | `account`, `reason` and `until` |
| `warm_up_halted` | Nothing can be warmed up here. | `reason` |

The other fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `account` | string | The Claude Code account in use, by its label: for `idle`, the one Pitboard watches, and for `no_reading`, the one with no reading. For `warmed_up` and `warm_up_held`, the account warmed up or held back. |
| `from` | string | The Claude Code account in use, by its label as `pitboard use` takes it. |
| `to` | string | The account switched to, by its label. |
| `limit` | object or null | The limit of `from` that reached the share, as last read: `kind`, `scope`, `percent` and `resets_at`, as in [Status data](/reference/json-output#status-data). A limit reaches the share at its whole percentage, a half rounded up, so `percent` can be `94.5` for a `threshold` of `95`. For `idle`, the fullest limit of `account` that has not reset, or `null` when it has none. |
| `as_of` | integer or null | When the reading of `account` was taken. |
| `held_until` | integer or null | When Pitboard may next ask Anthropic about `account`, while it waits after a rate limit or an error. `null` otherwise. |
| `unread` | array of strings | The accounts Pitboard could switch to that Anthropic has given no reading of yet, by label. Empty when there are none. |
| `adoption` | object | How sessions already running pick up the switch: the `polling` or `renewal` shape of [Data by command](/reference/json-output#data-by-command). |
| `until` | integer or null | For `waiting`, when Pitboard tries again. For `settling`, when the account has been in use 5 minutes. For `not_identified`, when Pitboard tries again to identify the login. For `warmed_up`, when the period started resets, or `null` where Anthropic has not said yet. For `warm_up_held`, when the reason ends, where that is known. |
| `reason` | string | Why, as a code. The codes for each event follow this table. |
| `email` | string | For `not_enrolled`, the email address of the account whose login Claude Code has stored. |
| `detail` | string | For `not_identified`, why Pitboard could not identify the login, in a few words. |

For `skipped` and `not_watching`, [Automatic switching](/reference/automatic-switching) lists the codes.

For `warm_up_held`, `reason` is one of these:

| `reason` | Meaning |
| --- | --- |
| `limit_used_up` | One of the account's own limits is used up. `until` is when it resets. |
| `no_reading` | Anthropic has given no reading of the account. |
| `nothing_to_start` | Its plan has no five-hour limit. |
| `parked_login_expired` | Its parked login has expired. |
| `nothing_parked` | It is not in use and has nothing parked. |
| `attempts_spent` | Three warm-ups of it came to nothing today. `until` is the start of the next day. |

For `warm_up_halted`, `reason` is one of these:

| `reason` | Meaning |
| --- | --- |
| `switch_interrupted` | A switch did not finish. |
| `custom_oauth_endpoint` | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, so Pitboard does not act on Claude Code. |
| `warm_up_auth_overridden` | Claude Code's managed settings, or an API key in its remote token file, sign it in another way. |
| `claude_not_found` | Claude Code is not installed where Pitboard looks. |

[When it holds back](/guides/warm-up#when-it-holds-back) says when each ends.

A warm-up that came to nothing prints an envelope with `ok` set to `false` and its error, once for each reason until that account warms up.

An error prints an envelope with `ok` set to `false`, and `watch` goes on. An error that ends `watch` prints the same, and `watch` exits with its status. [`watch`](/reference/account-commands#watch) says which errors end it, and what it prints only once.

A switch prints this on one line:

```json
{
  "v": 1,
  "command": "watch",
  "ok": true,
  "data": {
    "event": "switched",
    "threshold": 95,
    "from": "work",
    "to": "personal",
    "limit": {
      "kind": "session",
      "scope": null,
      "percent": 96.0,
      "resets_at": 1790474400
    },
    "adoption": {
      "follows": "polling",
      "within_seconds": 33
    }
  },
  "warnings": [],
  "error": null
}
```
