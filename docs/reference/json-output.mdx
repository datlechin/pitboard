With `--json`, every command prints one line of JSON on standard output, whether it succeeds or fails. `pitboard watch` prints one per event.

## The envelope

```sh
pitboard rename wrong right --json
```

It prints this on one line:

```json
{
  "v": 1,
  "command": "rename",
  "ok": true,
  "data": {
    "from": "wrong",
    "to": "right",
    "email": "me@example.com"
  },
  "warnings": [],
  "error": null
}
```

<ResponseField name="v" type="integer" required>
  The envelope's version, `1`. Pitboard adds fields and codes without changing it.
</ResponseField>

<ResponseField name="command" type="string | null" required>
  The command that ran, such as `rename`. `pitboard` alone gives `status`, the three `schedule` commands give `schedule`, and `completions` and `manpage` give `generate`.
</ResponseField>

<ResponseField name="ok" type="boolean" required>
  `true` when the command succeeded and exits with status 0. [Exit codes](/reference/commands#exit-codes) lists the other statuses.
</ResponseField>

<ResponseField name="data" type="object | null" required>
  What the command found or did, as [Data by command](/reference/json-output#data-by-command) lists. `null` when the command failed. `doctor` and `generate` keep it when they fail.
</ResponseField>

<ResponseField name="warnings" type="object[]" required>
  One object per warning, with `code` and `message`, or an empty array. A change that failed still lists the warnings it found first. [Warning codes](/reference/errors#warning-codes) lists the codes.
</ResponseField>

<ResponseField name="error" type="object | null" required>
  Set when `ok` is `false`, and `null` otherwise.

  <Expandable title="error fields">
    <ResponseField name="code" type="string">
      A stable code, listed in [Error and warning codes](/reference/errors).
    </ResponseField>

    <ResponseField name="message" type="string">
      What went wrong, in words for a person.
    </ResponseField>

    <ResponseField name="cause" type="object | null">
      What went wrong in a request to Anthropic or OpenAI. `null` on every error that [Cause codes](/reference/errors#cause-codes) does not list.

      <Expandable title="cause fields">
        <ResponseField name="code" type="string">
          A cause code, listed in [Cause codes](/reference/errors#cause-codes).
        </ResponseField>

        <ResponseField name="worth_retrying" type="boolean">
          `true` when the same request could succeed later.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

These failures have a shape of their own:

| Case | `command` | `data` | `error.code` | Exit status |
| --- | --- | --- | --- | --- |
| Pitboard cannot parse the command line | `null` | `null` | `usage` | 2 |
| The command refuses a label, as `pitboard enroll codx/work` does | The command | `null` | `usage` | 2 |
| `doctor` finds a check that fails | `doctor` | The whole report | `checks_failed` | 3 |
| `completions` or `manpage`, which have no JSON form | `generate` | `{}` | `output_is_not_a_report` | 2 |

In the last two rows, `error` has no `cause` field.

Every byte is ASCII. Pitboard writes a character outside ASCII as a `\u` escape: the label `Đạt` comes out as `\u0110\u1ea1t`. A character beyond U+FFFF becomes its UTF-16 surrogate pair.

Times are Unix times in seconds, such as `1790474400`. In `log` entries, `at` is a local time instead, such as `2026-09-22T01:01:00+07:00`.

<Note>
  Only `doctor --json` hides email addresses and account ids, behind placeholders such as `<email 1a2b3c4d>`. Email addresses appear in the output of `status`, `enroll`, `forget`, `rename` and `watch`, and in error messages such as `label_taken`. `status` also prints account ids. `repair` prints parked login names, and each name holds an account id.
</Note>

## Data by command

In the order of `pitboard --help`:

| Command | `data` |
| --- | --- |
| `status` | See [Status data](/reference/json-output#status-data). |
| `enroll` | `label` as typed, `provider` (`claude` or `codex`), `email`, and `enrolled`: `current`, `signed_in`, `renewed` or `in_use`, as [`enroll`](/reference/account-commands#enroll) explains. |
| `use`, already in use | `to`, `changed` (`false`) and `config_updated`, `true` where Claude Code's config named another account and `use` wrote this one into it. |
| `use`, after a switch | `from`, `to`, `provider`, `changed` (`true`), `parked_at` (when the login of `from` was parked), `adoption_ceiling_seconds` and `adoption`. |
| `forget` | `label` and `email`. |
| `stow` | `stowed`, `false` when no login file sits behind the keychain. When `true`, also `path`, the file deleted, and `login`, what became of its login: a code from [`stow`](/reference/recovery-commands#stow). Then `account`, the label of the login's account or `null`, and `dropped`, the file's other keys. |
| `abandon` | `abandoned`, `false` when no switch was interrupted. When `true`, also `from`, `to` and `logins_kept`, a count. |
| `repair` | `given_back`, objects with `label` and `service`, the parked login's name. `deleted`, `strangers` and `unreadable`, lists of parked login names, as [`repair`](/reference/recovery-commands#repair) explains. |
| `adopt` | `adopted`, `false` when the Pitboard directory was already this computer's. When `true`, also `accounts`, the labels kept, and `logins_dropped`, the labels whose parked login was dropped. |
| `renew` | `accounts`, one object per parked login that was due, with `label`, `provider` and `outcome`; and `renewed`, a count. `outcome` is `renewed`, `parked_login_refused`, `renewal_deferred` or an error code, as [`renew`](/reference/maintenance-commands#renew) explains. |
| `schedule install` | `installed` (`true`) and `path`. |
| `schedule status` | `installed`. When `true`, also `path` and `every_seconds` (`86400`). Where Pitboard has no scheduler to write, also `supported` (`false`). |
| `schedule uninstall` | `installed` (`false`) and `removed`, `false` when nothing was scheduled. |
| `log` | `entries`, oldest first, each with `at`, `caller` (`cli`, `app` or `unknown`), `verb`, `subject` and `outcome`, as [`log`](/reference/maintenance-commands#log) explains. |
| `uninstall` | The counts `parks_removed`, `parks_pending` (could not be deleted, or a renewal of Claude Code's login not saved yet) and `parks_left` (left because another Pitboard may own them), and the booleans `home_removed` and `schedule_removed`. |
| `rename` | `from`, `to` and `email`. |
| `doctor` | `environment`, the paths and login stores Pitboard found and the version of OpenAI's Codex CLI. `checks`, each with `code`, `name`, `level` (`ok`, `warn` or `fail`), `detail` and `advice`, as [`doctor`](/reference/maintenance-commands#doctor) lists. |
| `statusline` | `line`, the status line without colour, as [`statusline`](/reference/integration-commands#statusline) describes. |
| `watch` | One envelope per event, as [Watch events](/reference/json-output#watch-events) lists. |
| `completions`, `manpage` | `{}`, in the failure shape [The envelope](/reference/json-output#the-envelope) gives. |

`adoption` says how sessions already running pick up a switch, as [Open sessions](/concepts/switching#open-sessions) explains:

| Case | `adoption` | `adoption_ceiling_seconds` |
| --- | --- | --- |
| Claude Code | `{"follows":"polling","within_seconds":33}` | `33` |
| Claude Code on macOS, while a login file sits behind the keychain | `{"follows":"renewal","path":"/Users/you/.claude/.credentials.json"}` | `null` |
| Codex | `{"follows":"restart","program":"codex"}` | `null` |

## Status data

| Field | Type | Meaning |
| --- | --- | --- |
| `slot` | object | The Claude Code login this output is about. `service` names its keychain item on macOS, and no item on Linux. `default` is `true` for `Claude Code-credentials`, the item used when no [environment variable](/reference/files#environment-variables) picks another. |
| `signed_in` | object or null | The Claude Code account in use: `account_uuid`, `email` and `organization_uuid`. With `--offline`, the account Anthropic last named for the login stored. |
| `signed_in_error` | string or null | Why `signed_in` is `null`, such as `nothing is signed in` or `not asked`. |
| `accounts` | array | One object per enrolled account, Claude Code's first, and the account in use first within each tool. A login in use that no account matches gets one too, and so does a login Pitboard could not read or use. |

For Codex, the account in use is the object in `accounts` with `provider` set to `codex` and `signed_in` set to `true`.

Each object in `accounts`:

| Field | Type | Meaning |
| --- | --- | --- |
| `label` | string or null | The label without its tool, such as `work`. `null` for a login nobody enrolled. |
| `email` | string | The account's email address. Empty when Pitboard could not identify the login. |
| `account_uuid` | string | The account id, empty in the same case. For Claude Code, the Anthropic account UUID. One person's accounts in two organisations share it. |
| `organization_uuid` | string or null | The Claude organisation of the login. `null` for Codex, and for a login Pitboard could not identify. |
| `signed_in` | boolean | `true` for the account its tool is using. |
| `switchable` | boolean | `true` when `pitboard use` can switch to it: it is not in use, and the `refresh_expires_at` of its parked login has not passed. |
| `parked` | object or null | The parked login's `parked_at`, `access_expires_at` and `refresh_expires_at`, or `null` when nothing is parked. An expiry is `null` when unknown. `refresh_expires_at` is always `null` for Codex. |
| `lasts` | object or null | `seconds` and `why`. For the account in use, until its first limit runs out at its [pace](/concepts/usage#pace) (`why` is `filling`), or else until its first reset (`resets`). For any other account, until its first reset. `null` when no limit has a reset ahead. |
| `usage` | object or null | The reading: `source`, `observed_at` (when it was taken) and `windows`. `null` when no usage is known. |
| `stale` | string or null | Why the reading is not live, as [Stale codes](/reference/json-output#stale-codes) lists. |
| `provider` | string | `claude` or `codex`. |
| `qualified` | string or null | The label with its tool, such as `claude/work`. `null` for a login nobody enrolled. |

`source` is `live` when Pitboard asked the service this time. It is `remembered` for the last reading Pitboard recorded, from the command line, the app or a Claude Code status line.

Each object in `windows` is one limit:

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | string | The limit, such as `session` or `five_hour` for a five-hour limit and `weekly_all` or `seven_day` for a weekly one. |
| `scope` | string or null | The model or surface a narrower limit applies to, by the name Anthropic gives it. `null` for the account's own limit, and always for Codex. |
| `percent` | number | How much of the limit is used. Over 100 when the limit is exceeded. |
| `resets_at` | integer or null | When the limit resets. |
| `is_active` | boolean | Anthropic's own `is_active` for the limit. Always `true` for Codex. |
| `severity` | string or null | Anthropic's own grade of the limit. `null` where it gives none, as for every Codex limit. |
| `length_seconds` | integer | How long the limit's period runs, such as `18000`. Left out when unknown. |
| `pace` | object or null | The limit's [pace](/concepts/usage#pace) as of `observed_at`. `expected` is the share an even pace would have used. `delta` is `percent` less `expected`, in percentage points. `standing` is `over`, `under` or `even` (within 5 points). Over pace adds `runs_out_in`, the seconds left until the limit runs out at its rate since its period began. `null` in a period's first 3%, for a limit used up, after its reset, and where its reset or length is unknown. |

## Watch events

Each event's envelope has `command` set to `watch`. With `--once`, `watch` prints one event. The `data` of every event has `event` and `threshold`, the share it switches at, such as `95`.

| `event` | When | Other fields |
| --- | --- | --- |
| `watching` | `watch` starts. Not printed with `--once`. | None |
| `idle` | No limit of the account in use has reached the share. | `account`, `limit`, `as_of` and `held_until` |
| `switched` | Pitboard switched Claude Code. | `from`, `to`, `limit` and `adoption` |
| `waiting` | A limit reached the share, and a try at switching away came to nothing. | `from`, `limit` and `until` |
| `no_room` | A limit reached the share, and no other account has room. | `from`, `limit` and `unread` |
| `skipped` | A limit reached the share, and Pitboard stays on the account for a `reason`. | `from`, `limit` and `reason`, and `until` for `settling` |
| `not_watching` | Pitboard cannot decide whether to switch. | `reason`, and `email`, `account`, or `detail` and `until`, by reason |

The other fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `account` | string | The Claude Code account in use, by its label: for `idle`, the one Pitboard watches, and for `no_reading`, the one with no reading. |
| `from` | string | The Claude Code account in use, by its label as `pitboard use` takes it. |
| `to` | string | The account switched to, by its label. |
| `limit` | object or null | The limit of `from` that reached the share, as last read: `kind`, `scope`, `percent` and `resets_at`, as in [Status data](/reference/json-output#status-data). A limit reaches the share at its whole percentage, a half rounded up, so `percent` can be `94.5` for a `threshold` of `95`. For `idle`, the fullest limit of `account` that has not reset, or `null` when it has none. |
| `as_of` | integer or null | When the reading of `account` was taken. |
| `held_until` | integer or null | When Pitboard may next ask Anthropic about `account`, while it waits after a rate limit or an error. `null` otherwise. |
| `unread` | array of strings | The accounts Pitboard could switch to that Anthropic has given no reading of yet, by label. Empty when there are none. |
| `adoption` | object | How sessions already running pick up the switch: the `polling` or `renewal` shape of [Data by command](/reference/json-output#data-by-command). |
| `until` | integer | For `waiting`, when Pitboard tries again. For `settling`, when the account has been in use 5 minutes. For `not_identified`, when Pitboard tries again to identify the login. |
| `reason` | string | A code from the next two tables. |
| `email` | string | For `not_enrolled`, the email address of the account whose login Claude Code has stored. |
| `detail` | string | For `not_identified`, why Pitboard could not identify the login, in a few words. |

For `skipped`, `reason` is one of these:

| `reason` | Meaning |
| --- | --- |
| `already_switched` | Pitboard switched away from this limit once before it resets, and the account is back in use. |
| `attempts_spent` | Three tries at switching away from this limit failed. Pitboard tries no more before it resets. |
| `settling` | The account was put in use less than 5 minutes ago. |
| `auth_overridden` | Claude Code signs in another way, such as with `ANTHROPIC_API_KEY` or `apiKeyHelper`, so a switch would change nothing its sessions use. |

For `not_watching`, `reason` is one of these:

| `reason` | Meaning |
| --- | --- |
| `switch_interrupted` | A switch did not finish. |
| `custom_oauth_endpoint` | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, so Pitboard does not act on Claude Code. |
| `nothing_signed_in` | Claude Code has no login stored. |
| `not_enrolled` | Claude Code holds the login of an account not enrolled. `email` names it. |
| `not_identified` | Pitboard could not identify Claude Code's login, for `detail`. |
| `no_reading` | Anthropic has given no reading of `account`, the account in use. |

[When it holds back](/guides/automatic-switching#when-it-holds-back) says when each reason ends.

An error prints an envelope with `ok` set to `false`, and `watch` goes on. An error that ends `watch` prints the same, and `watch` exits with its status. [`watch`](/reference/account-commands#watch) says which errors end it, and what it prints only once.

A switch prints this on one line:

```json
{
  "v": 1,
  "command": "watch",
  "ok": true,
  "data": {
    "event": "switched",
    "threshold": 95,
    "from": "work",
    "to": "personal",
    "limit": {
      "kind": "session",
      "scope": null,
      "percent": 96.0,
      "resets_at": 1790474400
    },
    "adoption": {
      "follows": "polling",
      "within_seconds": 33
    }
  },
  "warnings": [],
  "error": null
}
```

## Stale codes

[Usage shows old numbers](/troubleshooting#usage-shows-old-numbers) gives the text `pitboard status` prints for each code, and what to do.

| `stale` | Meaning |
| --- | --- |
| `nothing_signed_in` | Nothing is signed in to the tool. |
| `login_unreadable` | The tool's login is there and could not be read, such as behind a locked keychain. |
| `login_unusable` | The tool's login is not one Pitboard can park or switch, such as one made with an API key. |
| `session_expired` | The login in use has expired. The tool renews it at its next request. |
| `parked_access_expired` | The parked login's access token has expired, and Pitboard could not renew it this time. |
| `nothing_parked` | The account has no parked login. |
| `login_replaced` | A sign-in outside Pitboard replaced the account's only login, so nothing is parked. Given with `--offline` too. |
| `park_unreadable` | Pitboard could not read the parked login. |
| `rate_limited` | The service asked for fewer requests, and Pitboard waits before it asks again. |
| `unreachable` | The service could not be reached. |
| `server_error` | The service answered with an error. |
| `answer_not_understood` | The service's answer was not in a shape Pitboard reads. |
| `login_refused` | The service no longer accepts the parked login. On the account in use, Anthropic no longer accepts the login in use, which Pitboard tried to renew to identify it. |
| `asked_recently` | Pitboard asked too recently for the limit to have moved one percentage point, so it did not ask again. |
| `interrupted` | The request stopped before it had an answer. |
| `not_asked` | Pitboard read the account without asking the service, as `pitboard status --offline` does. |
