Paths here are defaults. [Environment variables](/reference/files#environment-variables) can move them.

## The Pitboard directory

Pitboard's directory is `~/.pitboard`, or the path in `PITBOARD_HOME`. The command line and the app share it.

Pitboard creates each directory at mode 0700 and each file at 0600. A directory that already exists keeps its mode. A copy in `backups/` keeps the mode of Claude Code's config.

| File | Holds | Written or taken by |
| --- | --- | --- |
| `state.json` | The enrolled accounts with their email addresses and ids, their parked logins' names and expiry, and whose login each tool has stored | Every change and renewal, and a read that finds a tool's stored login changed |
| `state.lock` | The lock that lets one change run at a time | As `state.json`, and every automatic switch |
| `journal.json` | The record of a switch until it is done. One left behind marks an [interrupted switch](/concepts/switching#interrupted-switches). | A switch |
| `pending` | Names of parked logins about to be written, one per line, which the next change resolves. Absent when empty. | Anything that parks a login |
| `autoswitch.json` | What the automatic switch tried and said at each limit, until a minute after it resets, or 7 days with no reset known. When it last failed to identify Claude Code's login. | The automatic switch |
| `signin.lock` | The lock that allows one sign-in at a time | A sign-in |
| `signin/` | Where a tool signs in, apart from the login in use. Removed when the sign-in ends, or by the next one. | A sign-in |
| `vault/` | Linux: the parked logins, one file each | Anything that parks or renews a login |
| `usage.json` | The newest usage reading of each account | Reading usage, and the status line |
| `usage.lock` | The lock around `usage.json` and `sessions.json` | As `usage.json` |
| `asking.json` | When Pitboard last asked Anthropic or OpenAI about each account, and any wait before it asks again | Reading usage |
| `sessions.json` | What each Claude Code session last passed the status line. A session unseen for 7 days is dropped. | The status line |
| `backups/` | Claude Code's config as it was before Pitboard rewrote it, named `claude.json.<seconds since 1970>`. The 10 newest stay. | A Claude Code switch, and `pitboard use` of the account in use where the config names another |
| `audit.log`, `audit.log.1` | The activity log that [`pitboard log`](/reference/maintenance-commands#log) prints, and the one before it | Every change, renewal and automatic switch, and a read that finds a sign-in outside Pitboard |
| `app.json` | The app's preferences, listed in [The app](/reference/files#the-app) | The app |
| `told.json` | Each run-out the app has notified you of, by account and limit, with its reset | The app |

Only `vault/` and `signin/` can hold a login. `backups/` holds your email address, account ids and the path of each project Claude Code has opened.

Pitboard refuses a directory that a sync client copies to other machines, with `state_on_synced_drive`. It reads the path with links resolved:

| Where in the path | Refused |
| --- | --- |
| Anywhere as written, or as a whole folder name in any case | `Dropbox`, `Google Drive`, `OneDrive`, `com~apple~CloudDocs`, `Sync` |
| A folder named like these, in any case | `OneDrive - <organisation>`, `OneDrive-<kind>`, `Dropbox (<team>)`, `GoogleDrive-<account>` |
| Two adjacent folders, in any case | `Library/CloudStorage`, `Library/Mobile Documents` |

Your home's own folders count, so `/home/sync/.pitboard` is refused.

## Parked logins

On macOS, each parked login is an item in your default keychain, named `pitboard-park-<account id>-<time>`. Its keychain account is the one Claude Code's own item uses, from `USER`.

On Linux, each is a file in `~/.pitboard/vault/`, named `pitboard-park-<account id>-<time>.json`.

| Part | What it is |
| --- | --- |
| `<account id>` | The id Pitboard gives the account at enrolment, which never changes. Claude Code: the Anthropic account UUID and organisation UUID joined by `_`, or the account UUID alone for an older account. Codex: built from the account's ChatGPT ids. |
| `<time>` | When the login was parked or last renewed, in milliseconds since 1 January 1970 |

[Where parked logins are kept](/security#where-parked-logins-are-kept) says who can read them.

## Claude Code files

Each place was read in Claude Code builds 2.1.278 to 2.1.294.

| Path | What Pitboard does with it |
| --- | --- |
| `~/.claude.json` | Read for the account it names: see [How Pitboard knows whose login it is](/concepts/switching#how-pitboard-knows-whose-login-it-is). A Claude Code switch copies it to `backups/`, then writes the incoming account into it. A `.config.json` in Claude Code's config directory wins over it. |
| Keychain item `Claude Code-credentials` | macOS: the login in use. A switch reads and replaces it. With `CLAUDE_CONFIG_DIR` or `CLAUDE_SECURESTORAGE_CONFIG_DIR` set, the name ends in `-` and the first 8 hex characters of the SHA-256 of that path as written. |
| `~/.claude/.credentials.json` | Linux: the login in use. macOS: a [login file behind the keychain](/concepts/switching#open-sessions), read after the keychain item. Pitboard writes it only where the keychain holds no login. Otherwise only [`pitboard stow`](/reference/recovery-commands#stow) changes or deletes it. |
| `~/.claude/.storage-write.lock` | The lock Claude Code takes around each write of its login. Pitboard takes it whenever it writes the login in use: a switch, a sign-in to the account in use, and `pitboard stow`. |
| `~/.claude/.oauth_refresh.lock` and `~/.claude.lock` | The locks Claude Code takes, in that order, before it renews its login. Pitboard holds both through every Claude Code switch and `pitboard stow`. |
| `~/.claude/daemon.lock` | Read by `pitboard doctor` for the daemon Claude Code last started and its version. |
| `~/.claude/settings.json` | Read for `apiKeyHelper` and for an `env` block that sets a [variable Pitboard checks](/reference/files#variables-that-override-the-login) or `CLAUDE_CODE_CUSTOM_OAUTH_URL`. There, `""`, `"0"` and `"false"` count as unset. A project's settings are not read. |
| `managed-settings.json` and `managed-settings.d/*.json` | Read as `settings.json` is, in `/Library/Application Support/ClaudeCode` on macOS or `/etc/claude-code` on Linux. |

[What a switch does](/concepts/switching#what-a-switch-does) says how long Pitboard waits for a lock.

## Codex files

Each place was read in Codex 0.160.0.

| Path | What Pitboard does with it |
| --- | --- |
| `~/.codex/auth.json` | The login in use. A switch reads and replaces it. |
| `~/.codex/config.toml` | Read for the settings that choose Codex's login store. Never written. |

Pitboard switches Codex only while `auth.json` is its store: see [Before you enrol a Codex account](/guides/codex#before-you-enrol-a-codex-account). Codex reads `cli_auth_credentials_store`, and `secret_auth_storage` under `[features]`, from these places, each over the one before:

1. Codex's own default, `file`.
2. `/etc/codex/config.toml`.
3. `config.toml` in `~/.codex` or `CODEX_HOME`.
4. `/etc/codex/managed_config.toml`.
5. On macOS, the managed preference `config_toml_base64` of `com.openai.codex`, which a configuration profile sets.

`/etc/codex/requirements.toml`, then on macOS the managed preference `requirements_toml_base64`, pin the store over all five.

The `Codex login store` line of `pitboard doctor` names the place that chose. Codex does not start while one of them is there and unreadable. Pitboard then refuses with `live_store_unsupported`.

Pitboard reads a `profile = "<name>"` line as choosing the `[profiles.<name>]` table, which never sets the store. It refuses a line that names a profile no table defines.

Pitboard does not read three places Codex also reads:

- A trusted project's `.codex/config.toml`, which can move the login while Codex runs there.
- A profile's `<name>.config.toml`, read only with `--profile`, which `codex login` refuses.
- An enterprise's cloud configuration, which `codex login` does not load. Whether a running Codex follows its store is not known.

## Renewal schedule

`pitboard schedule install`, or turning on **Renew parked logins daily** in **Settings** > **General**, writes these files. `pitboard schedule uninstall`, or turning it off, removes them. So does `pitboard uninstall` while Pitboard's directory is `~/.pitboard`.

| Item | macOS | Linux |
| --- | --- | --- |
| Files | `~/Library/LaunchAgents/com.datlechin.pitboard.renew.plist` | `pitboard-renew.service` and `pitboard-renew.timer` in `~/.config/systemd/user`, even with `XDG_CONFIG_HOME` set |
| Runs | `<program> renew` | `<program> renew --scheduled` |
| When | `StartInterval` 86400 and `RunAtLoad` false: first a day after it is written | `OnUnitActiveSec=86400`, `OnStartupSec=900` and `Persistent=true` |
| Environment | `EnvironmentVariables` | One `Environment=` line each |

`<program>` is the `pitboard` that installed the job, by the path it was started with, such as Homebrew's link. From the app, it is `Pitboard.app/Contents/Helpers/pitboard`.

The environment holds `PITBOARD_NO_ARGV` and the proxy variables as they were set at install: see [`schedule`](/reference/maintenance-commands#schedule). Each file is mode 600, since a proxy's address can hold a password.

## The app

The app is `Pitboard.app`, with the bundle identifier `com.usepitboard.Pitboard`.

| Path inside `Pitboard.app` | What it is |
| --- | --- |
| `Contents/Helpers/pitboard` | The command line |
| `Contents/Resources/man/pitboard.1` | The man page |
| `Contents/Resources/completions/pitboard.bash`, `pitboard.zsh` and `pitboard.fish` | Shell completions |
| `Contents/PlugIns/PitboardShare.appex` | The [Share extension](/reference/account-windows#share-extension) |

The app keeps these keys in `~/Library/Preferences/com.usepitboard.Pitboard.plist`:

| Key | Holds |
| --- | --- |
| `menuBarShows` | [Menu bar shows](/reference/settings#menu-bar-shows): `nameAndUsage`, `usage` or `icon` |
| `settingsTab` | The Settings tab shown last: `general`, `commandLine` or `updates` |
| Keys of Sparkle, the app's updater | Its update settings and when it last checked |

It keeps these in `app.json` in Pitboard's directory, so they follow `PITBOARD_HOME`:

| Key | Holds |
| --- | --- |
| `second_account_declined` | The tools, `claude` or `codex`, whose second-account tip you dismissed with **Not Now** |
| `has_been_seen` | Whether the app has opened its window at first launch |
| `auto_switch` | `true` while **Switch Claude Code automatically** is on. Left out while it is off. |
| `auto_switch_at` | The share it switches at, a whole percentage. 95 while left out. A value outside 50 to 99 reads as the nearer end. |

macOS keeps **Open Pitboard at login** as a login item.

The app's other files are in `~/Library/Application Support`, `~/Library/Caches`, `~/Library/HTTPStorages` and `~/Library/Saved Application State`, each named after `com.usepitboard.Pitboard`.

## Account windows

[Account windows](/guides/account-windows) keep their data and records under your own `~/Library`, whatever `HOME` says. [Where account windows keep their data](/security#where-account-windows-keep-their-data) has the rules.

| Path | What it is |
| --- | --- |
| `~/Library/WebKit/com.usepitboard.Pitboard/WebsiteDataStore/<id>` | One account window's website data, sign-in included |
| `~/Library/Application Support/com.usepitboard.Pitboard/windows.json` | The windows' records: the data folders the app made, by Pitboard directory, and the page each window was last on |
| `~/Library/Containers/com.usepitboard.Pitboard.share` and `~/Library/Application Scripts/com.usepitboard.Pitboard.share` | Folders macOS makes for the sandboxed Share extension. Pitboard writes nothing there. |
| `~/Downloads` | Where account windows save [downloads](/reference/account-windows#downloads) |

`<id>` is a version 5 UUID of `claude:` or `codex:` and the account's id.

## Environment variables

The app reads the environment macOS starts it with, not your shell's. `launchctl setenv` adds to it. Daily renewal gets launchd's or systemd's, plus what [`schedule`](/reference/maintenance-commands#schedule) gives it.

A variable that names a folder must hold a full path: [`home_not_absolute`](/reference/errors#the-pitboard-directory) lists which may be empty.

| Variable | Read by | Effect |
| --- | --- | --- |
| `HOME` | Both | Your home, the `~` in every path here. Unset, your account's home. |
| `PITBOARD_HOME` | Both | Pitboard's directory, in place of `~/.pitboard`. Daily renewal renews `~/.pitboard` whatever this says. |
| `PITBOARD_NO_ARGV` | Both | `1`: on macOS, Pitboard never writes a login on `security`'s argument line. See [Large logins on macOS](/security#large-logins-on-macos). |
| `PITBOARD_API_BASE` | Both | For Pitboard's tests. An `http` URL on a loopback IP address gets Pitboard's requests. |
| `PITBOARD_CLAUDE`, `PITBOARD_CODEX` | Both | The `claude` or `codex` program to sign in with, in place of the one Pitboard finds. Empty counts as unset. |
| `CLAUDE_CONFIG_DIR` | Both | Claude Code's config directory, in place of `~/.claude`. The config file, `.credentials.json`, the locks and `settings.json` follow it, and the keychain item's name gains a suffix. |
| `CLAUDE_SECURESTORAGE_CONFIG_DIR` | Both | The directory that holds `.credentials.json` and the locks and picks the keychain item's suffix, in place of the config directory. Set but empty: `~/.claude` and `Claude Code-credentials`. |
| `USER` | Both | macOS: the keychain account of Claude Code's item and of parked logins. Unset or empty, your login name. With a character other than letters, digits, `.`, `_` and `-`, `claude-code-user`. |
| `CLAUDE_CODE_CUSTOM_OAUTH_URL` | Both | Not empty: Pitboard does not act on Claude Code. See [Custom OAuth endpoint](/reference/files#custom-oauth-endpoint). |
| `ANTHROPIC_API_KEY` and eight more | Both | Not empty: Claude Code ignores the login Pitboard switches. See [Variables that override the login](/reference/files#variables-that-override-the-login). |
| `CLAUDE_CODE_HOVER_REST` | Both | `1` or `true`: `pitboard doctor`'s `storage v5` check reads as on. Measured in 2.1.278, the login stays in the keychain. |
| `CODEX_HOME` | Both | Codex's directory, in place of `~/.codex`. Empty counts as unset. |
| `SUDO_UID` | Both | Not empty, as `sudo` sets it: Pitboard refuses every change with `elevated`. See [Pitboard changes nothing as root](/troubleshooting#pitboard-changes-nothing-as-root). |
| `PATH` | Both | Where `claude` and `codex` are looked for, in directories named from the root. The app asks your login shell for its `PATH` instead: see [Pitboard cannot find Claude Code](/troubleshooting#pitboard-cannot-find-claude-code). |
| `SHELL` | App | The login shell the app asks for its `PATH`. Unset or empty, your account's shell. |
| `NO_COLOR` | Command line | Not empty: no colour in the output. For the status line, see [`statusline`](/reference/integration-commands#statusline). |
| `XPC_SERVICE_NAME` | Command line | macOS: set by launchd. `com.datlechin.pitboard.renew` marks a run of daily renewal. |
| `ALL_PROXY`, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, each also in lower case | Both | The proxy for Pitboard's requests. See [Proxies](/reference/files#proxies). |

### Custom OAuth endpoint

`CLAUDE_CODE_CUSTOM_OAUTH_URL` counts when set in the environment or in an `env` block of Claude Code's settings. As read in Claude Code 2.1.284 and 2.1.289, Claude Code then keeps its login and config under names Pitboard does not read. Pitboard refuses these with `custom_oauth_endpoint`:

- `enroll`, `use`, `forget`, `rename` and `stow` of a Claude Code account, and the same in the app.
- `repair` and `uninstall`.
- `abandon` of a Claude Code switch, and every change while one is interrupted.

Changes to Codex accounts go ahead. The automatic switch does not watch Claude Code, and says so: see [When it holds back](/guides/automatic-switching#when-it-holds-back).

### Variables that override the login

As read in Claude Code 2.1.278, each of these makes Claude Code ignore the login Pitboard switches:

`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_GATEWAY`, `CLAUDE_CODE_USE_ANTHROPIC_AWS`, `CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD`.

Pitboard reads them from its environment and from Claude Code's settings, along with `apiKeyHelper`. While any is set, changes to Claude Code accounts go ahead but warn with `auth_overridden`, as does `pitboard doctor`. The automatic switch holds back.

### Proxies

Pitboard's requests go through the proxy these variables name. It does not read the system's proxy settings.

- Pitboard reads `ALL_PROXY`, `all_proxy`, `HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY`, then `http_proxy`, and takes the first that holds a proxy's address.
- An address with no scheme is `http://`.
- Pitboard goes through `http://` and `https://` proxies, not SOCKS ones: `socks://`, `socks4://`, `socks4a://`, `socks5://` and `socks5h://`.
- While a SOCKS proxy is named, each request to a host outside `NO_PROXY` fails before anything is sent, naming the variable.
- Pitboard then follows no redirect.

`NO_PROXY` lists the hosts Pitboard reaches directly, separated by commas. Pitboard reads `no_proxy` only while `NO_PROXY` is unset. Entries ignore case, and a space is part of an entry.

| Entry | Hosts it names |
| --- | --- |
| `*` | Every host |
| `*example.com` | Every host ending with `example.com`, `badexample.com` included |
| `.example.com` | Every host ending with `.example.com` |
| `api*` | Every host starting with `api` |
| `10.` | Every host starting with `10.` |
| Anything else | That host alone |

Pitboard reaches these hosts without looking up the proxy's name, which need not resolve.
