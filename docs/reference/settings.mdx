To open Settings, click Pitboard's item in the menu bar, then choose **Settings** (Command-Comma). It opens on the tab you used last.

## General

### Open Pitboard at login

When this is on, macOS opens Pitboard each time you log in.

If macOS needs your approval, the tab says **macOS is waiting for you to allow Pitboard in Login Items.** Until you allow Pitboard in System Settings, the switch stays on but Pitboard does not open at login. **Open Login Items Settings** opens that part of System Settings.

### Menu bar shows

Sets what the menu bar item shows beside its icon. For which account and limit it shows, see [Menu bar app](/reference/app#menu-bar-item).

| Choice | The menu bar item shows |
| --- | --- |
| **Account and usage** (the default) | The account's label and its usage, such as **work 42%** |
| **Usage only** | The usage alone, such as **42%** |
| **Icon only** | The icon alone |

### Renew parked logins daily

This setting is in the **While you're away** section.

When you turn it on, launchd, your Mac's scheduler, runs `pitboard renew` once a day with the command line inside the app. That run renews due parked logins and nothing else: it never switches account or asks for usage.

The setting is also on after `pitboard schedule install`, whose schedule runs the `pitboard` that installed it. While it is on, **Runs** shows **Every day** and **Scheduled in** shows the file of the [renewal schedule](/reference/files#renewal-schedule).

You cannot turn it on while macOS runs the app from a temporary copy. macOS does that until you move the app to your Applications folder.

For why parked logins need renewing, see [Keep parked logins alive](/guides/renewal).

### Renew Now

Renews every due parked login, as `pitboard renew` does, then reads usage again, as **Refresh** in Pitboard's menu does. For when a parked login is due, see [Maintenance commands](/reference/maintenance-commands#renew).

The text beside the button then gives the result, in the same line `pitboard renew` prints:

- **No parked login was due.**
- **2 due; none could be renewed this time.**
- **Renewed one.**
- **Renewed all 2.**
- **Renewed 1 of 2; the rest are tried again next time.**

**No parked login was due.** also appears while another Pitboard run is changing something, while a switch is interrupted, or when the account list cannot be read.

### Claude Desktop

This section appears when the app finds `Claude.app`, or when a Claude Desktop account is enrolled.

**Show live usage** sets where Claude Desktop's numbers come from. Turning it on opens a dialog that says what Pitboard reads from the keychain, and only its **Continue** turns live usage on. Turning it off forgets Claude's key, as `pitboard desktop live-usage disable` does.

The line under the switch says what is in effect:

| Line | Meaning |
| --- | --- |
| **Off. Numbers come from Claude's own history, without reset times.** | Live usage is off. |
| **On. Numbers come from claude.ai.** | Live usage is on, and the last read of Claude's key worked. |
| **On. Pitboard asks claude.ai at the next read.** | Live usage is on, and Pitboard has not asked claude.ai yet. |
| **Paused: macOS stopped letting Pitboard read Claude's key.** | Live usage is on, and macOS refused the read. **Allow Again** opens the dialog again. |

For what live usage reads, see [Use Pitboard with Claude Desktop](/guides/claude-desktop#see-usage-from-claudeai).

## Command Line

### In your terminal

Shows the `pitboard` a terminal would run, or **Not installed**. Pitboard looks on your login shell's `PATH` first, then in `~/.cargo/bin`, `~/.local/bin`, `/opt/homebrew/bin` and `/usr/local/bin`.

A note under the row says how that `pitboard` is updated:

| The `pitboard` found | Note under the row |
| --- | --- |
| The one inside the app, directly or through a link | **The one inside this app, so it updates with the app.** |
| Any other install | **Installed apart from this app, so update it the way you installed it.** |

The tab also names `pitboard status` for scripts and `pitboard repair` for a parked login Pitboard's records have lost track of.

### Install Command Line Tool

Appears only when no `pitboard` is found, so it never replaces one you installed. It links `/usr/local/bin/pitboard` to `Pitboard.app/Contents/Helpers/pitboard`, the command line inside the app. macOS asks for an administrator's password first.

Pitboard keeps a file at `/usr/local/bin/pitboard` that is not a link, and says `/usr/local/bin/pitboard` **is already there and is not a link, so it was kept.** Any other failure shows the reason macOS gives, or **The link could not be made.**

While the app runs from a temporary copy, the tab shows no button: a link into that copy would break.

## Updates

In a copy from a release download or the `pitboard-app` cask, the tab has three controls.

### Check for updates automatically

On by default. While it is on, Pitboard checks GitHub for a newer version once a day. For what the check sends, see [Security and privacy](/security#what-leaves-your-machine).

### Download and install updates automatically

Off by default. When it is on, an update the daily check finds downloads in the background and installs when Pitboard quits. It is dimmed while **Check for updates automatically** is off.

### Check Now

Checks for a newer version at once, in the update window.

Beside the button is the version you are running, as **Pitboard** `<version>`. After the daily check finds a newer version, the text reads **Pitboard** `<version>` **is ready to install.**

For the **Install Pitboard** `<version>` item in Pitboard's menu, see [Menu bar app](/reference/app#menu).

### A copy built from source

A copy built from source has no update key, the public key that verifies an update, so it cannot update itself. Its **Updates** tab shows only **Version** and a note saying so.
