The app opens account windows on macOS and Windows, and Linux has no app. [Use each account's site](/guides/account-windows) says how to open one, sign in and sign out.

Each enrolled Claude Code account has one window on claude.ai, and each enrolled Codex account one on chatgpt.com. A Claude Desktop account has none, and neither does a login nobody enrolled.

## Account windows

Opening an open window brings it to the front. A window opens at the last page of its site it showed, other than a sign-in page, or else at `https://claude.ai/` or `https://chatgpt.com/`. It closes once a read of the accounts no longer lists its account.

The title is the account's label. When the other site has an account with the same label, the title adds the site: **work (claude.ai)**.

On macOS, zoom steps from 50% to 300%, as in Safari, and resets when the window closes. The page's shortcut menu has no **Download Linked File**, **Download Image** or **Download Video**: WebKit would cancel those downloads.

On Windows, WebView2 serves the page's own keys, find bar and zoom, as Microsoft Edge does. **Downloads** joins the toolbar once the window has a download.

## Pages and links

| Address | Goes to |
| --- | --- |
| The site's pages, on its host or [an alias](#refused-links) | The window, even from a link that asks for a new tab |
| chatgpt.com's sign-in pages, on `auth.openai.com`, `login.live.com`, `login.microsoftonline.com` and `appleid.apple.com` | The window, or a [sign-in window](#sign-in-window) |
| Google's sign-in, `accounts.google.com` | Nowhere, with a note at the top of the window |
| Any other web page | Your default browser |
| An email address, `mailto:` | Your default email app |
| A link to another app, such as `vscode:` | Nowhere, with a note at the top of the window |

Email and app links act only when clicked or opened in a new window. A page that sends a web page to your browser without a click gets a note too.

A frame inside the page, such as an artifact, loads any address but a file on your computer.

A page's alert, confirmation or question opens as a dialog titled with the asking host, such as **claude.ai says**. A frame's names the frame's host, or no host when it has none.

## Sign-in window

A page opens a sign-in window when it opens a sign-in page or a blank page in a new window. Only the site's page or a sign-in page in the account's window can, never a frame.

It opens centred on the account's window, at the size the page asks for. On macOS, it defaults to 500 by 640 points and is never smaller than 320 by 400.

It shares the account's website data, so a sign-in there is the account's. Its page loads only the site, the site's sign-in pages and a blank page. Anything else goes where the account's window would send it.

It has no toolbar and opens no window of its own. It closes when its page closes it, as a finished sign-in does, when you close it or the account's window, when you remove the window's website data, or when another sign-in window opens in its place.

Whether chatgpt.com's **Continue with Microsoft** and **Continue with Apple** open a sign-in window is not known.

## Downloads

Downloads go to your Downloads folder. A download never replaces a file.

| Download | Saved |
| --- | --- |
| Started by the site's own page | At once |
| Started by anything else, such as an artifact | After you choose **Download** in the question that names the file and its host |
| Started in a sign-in window, or from an address that is not `https:`, `blob:` or `data:` | Never |

A failed download's partial file is deleted. A download goes on after its window closes. While one runs, **Quit Pitboard** on macOS, or **Exit** on Windows, asks first, and quitting stops every download and deletes what each wrote.

| System | A second `report.pdf` is saved as | **Downloads** in the toolbar |
| --- | --- | --- |
| macOS | `report 2.pdf`, then `report 3.pdf` | Lists the downloads newest first. **Cancel** deletes what a download wrote. |
| Windows | `report (1).pdf`, then `report (2).pdf` | Opens WebView2's own list |

On Windows, a window closed during a download comes back when you open the account's window again, or when **Exit** asks.

## Website data

The app records each window's website data and last page in `windows.json`, a file only you can read. It makes a window's data when the window first opens. A renamed account keeps it. [Account windows](/reference/files#account-windows) gives the paths.

| Deleted | When |
| --- | --- |
| A window's data | You remove its website data. That signs the window out on this computer only, and the window starts again at 100% zoom. |
| A window's data | You remove its account, in the app or with `pitboard forget`. The app deletes it at its next successful read of the accounts. |
| Every window's data | You choose **Uninstall Pitboard** in the app's Settings. |
| Every window's data | On Windows, you remove Pitboard in **Settings** > **Apps** > **Installed apps**. |

The app deletes a window's data only where its own Pitboard directory recorded it and no other existing one did. A copy run with another Pitboard directory therefore signs no other copy's windows out. While the app cannot read `windows.json`, it deletes nothing.

On Windows, WebView2 lets go of a window's data only once every account window has closed. Until then, that window does not open: the icon's menu leaves it out, and an account's shortcut menu and opened row dim it and say why.

## Open Link window

The **Open Link** window asks which account opens a [Pitboard link](#pitboard-links). On Windows, it is the **Open link** window. Nothing opens until you choose, even when the site has one account.

It selects the account you last chose for the site since Pitboard started, else the account in use, else the first. For 750 ms after the accounts appear, **Open** is dimmed and a double-click on an account does nothing, which stops a Return meant for another app.

A link brings the window to the front. A second link replaces the first, and the selection and the 750 ms wait start again. With no account on the link's site, **Add Account** opens the **Add Account** dialog for the site's tool, and the link waits.

If the account's window is open, it loads the link, and **Back** returns to the page before. Otherwise the window opens on the link.

## Refused links

The Share extension on macOS and the **Open Link** window refuse these links, and say why:

- A link on another site, such as `example.com` or `www.claude.ai`, or with a port or a user name.
- A sign-in link: under `/magic-link` on claude.ai, or `/api/auth` on chatgpt.com. It would sign the window in as whoever the link belongs to.
- A link that is not `http` or `https`, or has a `.` or `..` path segment.
- A link longer than 8192 characters.
- A [Pitboard link](#pitboard-links) this version cannot read.

Pitboard opens an `http` link, or one with no scheme such as `claude.ai/new`, as `https`. A link on `chat.openai.com`, `www.chatgpt.com` or `chat.com` opens as the same link on `chatgpt.com`. Each of those hosts redirects there with the path kept, measured on 29 September 2026.

## Pitboard links

A Pitboard link is `pitboard://open?url=` followed by a page's link, percent-encoded. On macOS, the Share extension hands a page to the app as one. On Windows, the installer registers `pitboard://` for Pitboard.

```text
pitboard://open?url=https%3A%2F%2Fclaude.ai%2Fchat%2F0e5a
```

Anything on your computer can open a Pitboard link, so one only ever shows the **Open Link** window.

The app [refuses](#refused-links) one with a port, a user name, a fragment, a host other than `open` or a path other than `/`. Its query must be one non-empty `url` and nothing else.

## Share extension

On macOS, the app includes a Share extension, **Pitboard** in a browser's Share menu. On Windows, the share sheet lists only a signed Pitboard, so the app takes no page from it.

The extension is offered for one web page at a time. It checks the page against the [refused links](#refused-links) and hands it to the app it came in as a [Pitboard link](#pitboard-links), keeping nothing. A refused page does not start Pitboard. The extension is sandboxed, with no network, file or shared-folder access.
