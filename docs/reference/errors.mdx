Adding a code is not a breaking change; renaming or removing one is.

The command line prints the message after `error:` or `warning:` on standard error. With `--json`, the code is in `error.code` or `warnings[].code`, as [The envelope](/reference/json-output#the-envelope) shows. The app shows the message in its own words, under a title that names what failed, such as **Couldn't switch to work**. It ends with a step in the app, such as **Sign In Again**, or with **Learn More**, which opens the part of this page that lists the code.

Where a fix is a command, the app's way follows it, starting "In the app". Those steps give the macOS app's words. On Windows, you select each control, and it reads in sentence case, such as **Sign in again**.

[Exit codes](/reference/commands#exit-codes) says what each exit status means. `label_unusable` appears only in [`pitboard log`](/reference/maintenance-commands#log).

A row that starts with a tool's name gives what the code means for that tool.

On Windows, a message names `claude.cmd` or `codex.cmd` where Pitboard found the one npm installs, as [Claude Code does not start in Windows PowerShell](/troubleshooting/accounts#claude-code-does-not-start-in-windows-powershell) says.

## Accounts and labels

| Code | Exit | Meaning | What to do |
| --- | --- | --- | --- |
| `account_unknown` | 1 | No account is enrolled under that label. The message lists the labels that are. | Check the label, or add the account with `pitboard enroll <label> --sign-in`. In the app, click **Add Account**. |
| `label_taken` | 1 | The label belongs to another account of the same tool. | Choose another label. |
| `already_enrolled` | 1 | The account is enrolled under the label the message names. | Use that label. To add another account, run `pitboard enroll <label> --sign-in`. In the app, sign in to a different account in **Add Account**. |
| `label_ambiguous` | 1 | A label with no tool, such as `work`, names accounts of more than one tool. | Add the tool: `claude/work`, `codex/work` or `desktop/work`. |
| `provider_unknown` | 1 | A label for `use`, `forget` or the first of `rename` starts with an unknown tool, such as `codx/work`. | Start it with `claude/`, `codex/` or `desktop/`, or leave the tool out. |
| `live_account_not_enrolled` | 1 | The account in use is not enrolled, so Pitboard cannot [park](/concepts/switching#parked-logins) its login. | Enrol it with `pitboard enroll <label>`, `pitboard enroll codex/<label>` or `pitboard enroll desktop/<label>`. In the app, click **Add Account**. |
| `cannot_forget_active_account` | 1 | The account is in use. | Switch to another account, then forget it. In the app, switch to another account, then choose **Remove Account**. |
| `account_not_in_use` | 1 | You clicked **Update Claude Code's Config** for an account no longer in use. Pitboard wrote nothing. | Nothing. A switch writes the config itself. |
| `usage` | 2 | The command line is wrong. | Check it with `--help`. |
| `usage` | 2 | A label for `enroll`, or the second label for `rename`, breaks the [label rules](/reference/commands#labels). | Choose a label the rules allow. |
| `usage` | 2 | The second label for `rename` names another tool, as in `pitboard rename work codex/job`. | Keep the account's tool. To move it, enrol the account in that tool. |

| --- | --- | --- | --- |

| `parked_login_belongs_elsewhere` | 1 | The parked login belongs to another account than the label's. Nothing moved. | Run `pitboard doctor`, then `pitboard enroll <label> --sign-in`. In the app, open **Diagnostics**, then click **Sign In Again**. |
| `parked_credential_missing` | 1 | The parked login is missing from where Pitboard keeps it: the keychain, `vault` in Pitboard's directory on Linux and Windows, or `~/.pitboard/parks` for Claude Desktop. | Run `pitboard enroll <label> --sign-in`. In the app, click **Sign In Again**. |
| `parked_credential_corrupt` | 1 | The parked login is not the one Pitboard recorded. | Run `pitboard enroll <label> --sign-in`. In the app, click **Sign In Again**. |
| `park_slot_exhausted` | 1 | Pitboard found no free name to park a login under. | Run `pitboard doctor`. In the app, open **Diagnostics**. |
| `renewal_failed` | 1 | Pitboard could not [renew](/guides/renewal) a parked login. | Run `pitboard doctor` if it keeps happening. In the app, open **Diagnostics**. |
| `credential_too_large` | 3 | On macOS, the login is too large for `security` to read from standard input, and `PITBOARD_NO_ARGV=1` forbids the argument line. | Unset `PITBOARD_NO_ARGV`. Or, for Claude Code, sign out of MCP servers you no longer use. See [Large logins on macOS](/security#large-logins-on-macos). |
| `credential_too_large` | 3 | On Windows, Claude Code's login is too large for Credential Manager, even in pieces. | Sign out of MCP servers you no longer use. |
| `vault_form_unsupported` | 1 | `pitboard vault move` ran on macOS or Windows, which keep parked logins one way. Nothing changed. | Nothing. Only Linux keeps them either way. |

## Switching

These come from a Claude Code or Codex switch. A Claude Desktop switch has its own, in [Claude Desktop](#claude-desktop).

| Code | Exit | Meaning | What to do |
| --- | --- | --- | --- |
| `switch_rolled_back` | 1 | Pitboard could not write the incoming login, so it put the outgoing one back. Nothing was lost. | Fix the reason the message gives, then switch again. |
| `switch_did_not_hold` | 3 | Claude Code: a `/logout` removed the incoming login before the switch finished. Both logins are parked. | Run `claude`, sign in to any enrolled account, then run `pitboard use` with the account you switched to. In the app, switch to that account. |
| `switch_did_not_hold` | 3 | Codex: a `codex` process started before the switch rewrote `auth.json` during it. The incoming login is still parked. | Quit every `codex`, then run `pitboard`. Run neither `codex login` nor `codex logout` first: each revokes the login it finds. In the app, click **Refresh**. |
| `switch_unverified` | 3 | Writing the incoming login failed, and Pitboard could not read the login back to see what changed. Nothing was deleted. | Unlock the keychain, run Pitboard from a desktop session where Credential Manager holds the login, or make `.credentials.json` or `auth.json` readable to you. Then run the same `pitboard use` again. In the app, switch again. |
| `switch_corrupted` | 3 | Pitboard could not write the incoming login or put the outgoing one back. The outgoing login is still parked. | Sign in to any enrolled account with `claude` or `codex login`, then run `pitboard use` with the account you switched from. In the app, switch to that account. |
| `signed_in_account_changed` | 1 | The account in use changed during the switch. Nothing moved. | Try again. |
| `identity_unverifiable` | 1 | Pitboard could not confirm with Anthropic or OpenAI whose login it was about to move, so it moved nothing. The message names the login, the one signed in or the one parked for the account switched to, and what the service answered. | Do what the message says. If the message names a SOCKS proxy, set that variable to an HTTP proxy or unset it, as [Proxies](/reference/environment-variables#proxies) describes. |
| `live_login_refused` | 1 | Anthropic refuses the refresh token of Claude Code's login in use for good, so that login no longer works and Pitboard cannot park it. | Run `pitboard use <label> --yes` to put the account's login in its place, or sign in to Claude Code again. In the app, choose **Replace** when Pitboard asks. |
| `account_on_hold` | 1 | Anthropic has put the account on hold. Pitboard keeps its login. | Follow Anthropic's instructions for the account, at the link the message gives, then try again. |
| `replace_failed` | 1 | Pitboard could not put the account's login in place of the refused one. The account's login is still parked. | Run the switch again. If it keeps failing, run `pitboard doctor`. In the app, open **Diagnostics**. |
| `install_failed` | 1 | Nothing was signed in, and Pitboard could not put the account's login where the tool reads it. The account's login is still parked. | Fix the reason the message gives, then run the switch again. |
| `session_expired` | 1 | The tool's login in use has expired, so Pitboard cannot identify it. If the message says `cannot be renewed`, Pitboard tried to renew it, and Anthropic no longer accepts it or it has no refresh token. | Run `claude` or `codex` once so it renews its login, then try again. If the message says `cannot be renewed`, run `claude` and sign in. |

## Interrupted switches

A Claude Code or Codex switch that was interrupted, and that the next change cannot finish, shows `recovery_undetermined` in these places:

| Where | How |
| --- | --- |
| Every change | An error. The change stops and changes nothing. |
| `pitboard status` | A warning. |
| Each read in the app | The notice **A switch didn't finish**, with a **Cancel Switch** button. |
| `pitboard status --offline` | A warning. |
| `pitboard doctor` | Listed under `interrupted switch`. |
| The app's **Diagnostics** | Listed under **Switch That Didn't Finish**. |

When only Anthropic can identify the login in use, the last two rows show nothing.

| Code | Exit | Meaning | What to do |
| --- | --- | --- | --- |
| `recovery_undetermined` | 1 | An earlier switch was interrupted, and Pitboard cannot yet tell whether it finished. Nothing changed. | Run `claude` or `codex` once, then try again. If it still fails, see [An interrupted switch cannot be finished](/troubleshooting/recovery#an-interrupted-switch-cannot-be-finished). |
| `recovery_elsewhere` | 1 | `CLAUDE_CONFIG_DIR` or `CODEX_HOME` differs from the interrupted switch's, so Pitboard cannot tell what it did. Nothing changed. | Set the variable back and try again, or run [`pitboard abandon`](/reference/recovery-commands#abandon). In the app, click **Cancel Switch** on the notice. |
| `recovery_failed` | 1 | Pitboard could not read or write `journal.json`, its record of a switch in progress. | Check that you can read and write the file the message names. |
| `recovery_record_corrupt` | 3 | `journal.json` is damaged. Nothing changed. | Check that `pitboard status`, or the app, shows the account you expect in use, then delete the file the message names. |

An interrupted Claude Desktop move has its own codes, in [Claude Desktop](#claude-desktop).

| `state_version_unknown` | 1 | The account list is in a format no Pitboard has written. | Delete the file the message names and enrol your accounts again. |
| `state_names_unknown_tool` | 1 | The account list has an account of a tool this Pitboard does not know. | [Update Pitboard](/install#update-pitboard). |

| `pitboard_open` | 1 | `pitboard uninstall` while the Pitboard app is open, which would make Pitboard's directory again. | Variable | Refused when |
| --- | --- |
| `HOME`, or `USERPROFILE` on Windows, `PITBOARD_HOME`, `CLAUDE_CONFIG_DIR` | Empty or relative, such as `pitboard` |
| `CLAUDE_SECURESTORAGE_CONFIG_DIR`, `CODEX_HOME` | Relative |

## Claude Code and Codex files

| Code | Exit | Meaning | What to do |
| --- | --- | --- | --- |
| `claude_config_missing` | 1 | Claude Code has not run on this machine: its config file is missing. | Run `claude` once, sign in, then try again. |
| `claude_config_unreadable` | 1 | Pitboard could not read Claude Code's config. | Check that you can read the file the message names. |
| `claude_config_not_json` | 3 | Claude Code's config is not valid JSON, perhaps because it is mid-write. | Wait a few seconds and try again. |

| `live_credential_shape_unexpected` | 3 | The login in use is not shaped like a Claude Code or Codex login. | Run `pitboard doctor` before you switch again. In the app, open **Diagnostics**. |
| `live_store_unsupported` | 3 | Codex keeps its login outside `auth.json`, is signed in with an API key or has settings Pitboard cannot read. The message names the setting. | See [Codex files](/reference/files#codex-files). |
| `login_restricted` | 3 | A setting of the tool's rules out the login a change would put in use: Codex would sign out of it and delete it, or leave it unused, and Claude Code would refuse it. The message names the setting. Nothing changed. | For Codex, see [Codex settings rule out an account](/troubleshooting/codex#codex-settings-rule-out-an-account). For Claude Code, see [Before you add a Claude Code account](/guides/claude-code#before-you-add-a-claude-code-account). |
| `codex_home_missing` | 1 | On Windows, `CODEX_HOME` names no folder, so Codex does not start. | Make that folder, or unset `CODEX_HOME`. |
| `custom_oauth_endpoint` | 3 | `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, so Pitboard does not act on Claude Code. | Unset it in the environment and in the `env` block of any Claude Code settings file. See [Custom OAuth endpoint](/reference/environment-variables#custom-oauth-endpoint). |
| `left_login_changed` | 1 | The login file behind the keychain or Credential Manager changed, or is gone, since [`pitboard stow`](/reference/recovery-commands#stow) said what it held. | Run `pitboard stow` again. In the app, click **Clean Up** again. |
| `left_login_not_enrolled` | 1 | The login file behind the keychain or Credential Manager holds the login of an account not enrolled here, which the message names. | Enrol that account, then run `pitboard stow` again. In the app, add that account, then click **Clean Up** again. |
| `left_login_unidentified` | 1 | `pitboard stow` could not ask Anthropic whose login the file holds, or could not renew it. | Check the connection and try again. |
| `stored_login_changed` | 1 | A sign-in replaced Claude Code's stored login while `pitboard stow` was deleting the file because of that login. | Run `pitboard stow` again. In the app, click **Clean Up** again. |

An error that stops `pitboard stow` keeps its own code, cause and exit status. The file stays, and the message ends with what `stow` did first. An ending of `that login no longer works` means `stow` renewed the file's login and could not write it back.
