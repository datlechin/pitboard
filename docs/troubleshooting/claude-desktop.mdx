title: "Fix Claude Desktop accounts"
sidebarTitle: "Claude Desktop"
description: "Fix a Claude Desktop change refused while Claude is open, an unfinished add, an interrupted move or a login that lapsed."
---

These fixes are for macOS. On Windows and Linux, Pitboard leaves Claude Desktop alone, so none of them applies.

## Claude is open

A Claude Desktop change stops with `app_open`, and changes nothing, while Claude is open:

```text
error: Claude is open, and Pitboard changes its login only while it is closed. Quit Claude with Command-Q, then run this again. Nothing has changed.
```

Closing its window leaves it running.

If the error says Claude has quit and names a part of it still running, such as `ShipIt (pid 812)`, wait until it ends. Or quit it in Activity Monitor. Then try again.

## Claude is waiting to reset its data

A Claude Desktop change stops with `login_folder_unknown`, and changes nothing:

```text
error: Claude's data folder is waiting for Reset App Data, which deletes what it holds the next time Claude opens, so Pitboard moves no Claude Desktop login. Open Claude, quit it with Command-Q, then run this again. Nothing has changed.
```

Claude's **Reset App Data** did not finish. Open Claude to let it finish, which signs Claude out, then quit it and try again. Your parked accounts stay in Pitboard.

## Finish or undo an add or a sign-in again

An add or a sign-in again left halfway keeps Claude signed out and the account in use parked, after a restart too. You leave one with Control-C on the command line, or **Later** in the app. The app then shows **Adding a Claude Desktop account didn't finish** or **Signing in to home again didn't finish**.

To finish, sign in to the account in Claude and quit Claude. Then click **Finish Adding** or **Finish Signing In** on the notice, then **Add the Account Claude Shows** or **Add home** in the dialog. On the command line, run `pitboard enroll` with the label you were adding or signing in to, such as `pitboard enroll desktop/travel`.

To undo it, click **Switch Back to work** on the notice, or run `pitboard use desktop/work`. Once Claude is signed in to the account you are adding, the undo is refused: finish the add instead.

## Give up an interrupted move

Give up only when an error about an interrupted move says to. [A Claude Desktop move was interrupted](/troubleshooting/recovery#a-claude-desktop-move-was-interrupted) says what comes first.

In the app, click **Cancel Switch** on the notice **A switch in Claude didn't finish**, then **Cancel Switch** again to confirm. On the command line, run `pitboard abandon`, then do what its output says. [`abandon`](/reference/recovery-commands#abandon) lists what it prints.

## A parked Claude Desktop account opens signed out

After a switch to a Claude Desktop account, Claude shows its sign-in page: the parked login no longer works. `pitboard` may already have said `sign-in may have lapsed`.

Quit Claude, then [sign in to the account again](/guides/claude-desktop#sign-in-again), so Pitboard records the new login.

## Account data in a form Pitboard has not read

`pitboard doctor` warns on its `Claude data folder layout` line, and Pitboard starts no Claude Desktop move, refusing with `login_folder_unknown`:

```text
error: Claude's data folder holds `Cookies-wal`, a part of the account's data this Pitboard has not read, so Pitboard moves no Claude Desktop login. Update Pitboard, or report it at https://github.com/datlechin/pitboard/issues if no release reads it yet. Nothing has changed.
```

This build of Claude keeps part of a store Pitboard moves where Pitboard has no record of it, so a move would split the store. [Update Pitboard](/install#update-pitboard), or [report a problem](/troubleshooting#report-a-problem) with the name if no release reads it yet. Claude Code and Codex switches go ahead.
