In each case here, reads such as `pitboard status` and the status line still answer from the last numbers measured, and write nothing.

## Pitboard changes nothing as root

With `sudo`, Pitboard refuses every change with `elevated`: a file or keychain item made as root would be out of reach of your own runs. On macOS, it refuses every change as root too.

On Linux, root changes things where root owns every folder Pitboard writes in, as on a server or container whose only user is root. Those are your home, the Pitboard directory and the homes of Claude Code and Codex. Pitboard refuses root where another user owns one of them:

- `su -m` and `su -p` keep your `HOME`.
- `su` keeps `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `PITBOARD_HOME` where you set them.
- A container can be given your `~/.claude` or `~/.codex` in place of root's.

Run Pitboard as yourself. [Remove files Pitboard made as root](/install/remove#remove-files-pitboard-made-as-root) cleans up after an earlier Pitboard run as root.

### `SUDO_UID` is set in your own shell

Pitboard takes any run with a non-empty `SUDO_UID` as one under `sudo`. A shell started with `sudo -iu` and your own name passes it on, such as to a tmux server. If `id -un` prints your own name there, run the command without it:

```sh
env -u SUDO_UID pitboard use work
```

To stop it for good, start that shell or tmux again without `sudo`. For the install script, pipe it to `env -u SUDO_UID sh` in place of `sh`.

## Pitboard changes nothing as administrator

On Windows, Pitboard refuses every change with `elevated` when it runs elevated: a file it made would belong to the administrators.

| Where it runs | What to do |
| --- | --- |
| A terminal started with **Run as administrator** | Run Pitboard from a terminal that is not elevated. |
| An account with User Account Control turned off, or the built-in Administrator | Run Pitboard from a standard account, or turn User Account Control on. |

## Pitboard changes nothing on this version of Windows

On a Windows older than Windows 11 24H2, build 26100, Pitboard refuses every change with `system_too_old`. The app still installs and opens. Windows Server 2025 meets the floor. Update Windows to use Pitboard there.
