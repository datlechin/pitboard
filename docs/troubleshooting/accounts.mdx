## Claude Code shows another account than Pitboard

`/status` in Claude Code shows the account its config names. Pitboard shows the account whose login is stored, which requests use. A sign-in, or a session started on another login, can write another account into the config: see [How Pitboard knows whose login it is](/concepts/identity).

Pitboard warns with the cause, such as `config_names_another` or `in_use_unconfirmed`, and [Warning codes](/reference/errors#warning-codes) gives each fix.

After a switch, an open session keeps the old account for up to about 33 seconds, or until its next renewal while a login file sits behind the store: see [Claude Code over SSH uses another account](/troubleshooting#claude-code-over-ssh-uses-another-account).

## Claude Code or Codex inside WSL keeps its account

Pitboard for Windows switches the Claude Code and Codex installed on Windows. Switch those inside WSL with Pitboard inside WSL, as [Install inside WSL](/install#install-inside-wsl) says.

## macOS says the keychain is locked

Where macOS cannot ask for your password, as over SSH, a locked keychain stops Pitboard with `credential_store_locked`:

```text
error: the credential store could not be read: the keychain is locked and cannot ask to be unlocked from here; unlock it with `security unlock-keychain`, or run Pitboard from a desktop session
```

Unlock it, then run the command again. Meanwhile `pitboard doctor` marks each parked login `not read: the keychain is locked`, and none needs a sign-in.

## Windows says Credential Manager cannot be reached

A sign-in over SSH with a key cannot reach Credential Manager, so Pitboard cannot tell where Claude Code keeps its login, and stops with `credential_store_locked`:

```text
error: the credential store could not be read: Credential Manager cannot be reached from this logon, as in a sign-in over SSH with a key; run Pitboard from a desktop session
```

Run the command again from a desktop session. Nothing is wrong with the login, and no account needs a sign-in.

## The Claude Code login in Credential Manager cannot be read

On Windows, Pitboard stops with `credential_store_unreadable` and says that Claude Code cannot read the login either. Measured with Claude Code 2.1.302 on 18 October 2026: moving a login from `.credentials.json` into Credential Manager left part of it missing, and lost it.

Run `claude auth logout`, which deletes what is left, then sign in to Claude Code again. Where another account is enrolled, `pitboard use` puts its login in place instead. The account whose login was lost then reads `login replaced outside Pitboard`: [sign in to it again](/guides/sign-in-again).

## Claude Code does not start in Windows PowerShell

Windows PowerShell's default execution policy, `Restricted`, refuses the `claude.ps1` that npm installs, and `claude` fails with `PSSecurityException`. Run `claude.cmd` in its place, as in `claude.cmd auth logout`. Measured with Windows PowerShell 5.1 and Claude Code 2.1.302 on 18 October 2026.

A Codex installed with npm is the same: run `codex.cmd`. Where Pitboard finds the `claude.cmd` or `codex.cmd` that npm installs, its messages name that.

## Usage shows old numbers

Old numbers carry their age and often a reason, as in `measured 14:02, 3m ago · Anthropic could not be reached`. [Stale codes](/reference/errors#stale-codes) says what to do about each reason.

With no reason, Pitboard asked moments ago, and [waits](/concepts/usage#how-often-pitboard-asks) 3 minutes for a five-hour limit. `pitboard status --fresh`, or **Refresh** in the app, asks anyway.

## Pitboard cannot find a tool

The command line looks for `claude` and `codex` on your `PATH`, and says:

```text
error: `claude` is not on this machine, and Pitboard signs in with Claude Code's own sign-in. Install Claude Code, or point Pitboard at it.
```

The app's **Add Account** dialog says so too, and links how to install the tool.

Install the tool. For Codex, install OpenAI's Codex CLI: Pitboard does not use the copy inside the ChatGPT app. If the tool is installed, add its folder to your `PATH`, or set `PITBOARD_CLAUDE` or `PITBOARD_CODEX` to its path.

<Tabs>
  <Tab title="macOS">
    The app looks on your login shell's `PATH`, then in `~/.local/bin`, `/opt/homebrew/bin` and `/usr/local/bin`. It sees `PITBOARD_CLAUDE` and `PITBOARD_CODEX` only when `launchctl setenv` set them.
  </Tab>
  <Tab title="Windows">
    The app looks on the `Path` Windows gives a program started from Start, then where each tool's installers put it:

    | Tool | Folders |
    | --- | --- |
    | Claude Code | `.local\bin` in your user folder |
    | Codex | `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`, or the folder `CODEX_INSTALL_DIR` names |
    | Both | `%APPDATA%\npm`, `%LOCALAPPDATA%\Microsoft\WinGet\Links` and `scoop\shims` in your user folder |

    It sees `PITBOARD_CLAUDE` and `PITBOARD_CODEX` only when they are set for your Windows account, not in one terminal.
  </Tab>
</Tabs>

The app looks again each time the dialog opens and each time its window comes to the front.
