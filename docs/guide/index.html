pitboard · guide

Guide

Everything pitboard does, in the order you meet it.

Install

brew install datlechin/tap/pitboard        # the command line
brew install --cask datlechin/tap/pitboard # the menu bar app, macOS 14 or later

Or cargo install pitboard, or cargo binstall pitboard to fetch the built binary. On Linux the latest release carries static binaries for x86_64 and aarch64.

Add your accounts

pitboard enroll personal
pitboard enroll work --sign-in

The first records the account you are signed in as now. The second runs Claude Code's own sign-in in a separate directory, so the login you are using stays where it is. Do not use /login to add an account: that replaces the login in use, and pitboard cannot keep a copy of a login it did not see leave.

Sign in as the account you mean to add. The browser is probably still signed in as the first one, and Claude Code will hand that back; pitboard then says the account is already enrolled.

Every day

pitboard             # who is signed in, and what each account has left
pitboard use work    # switch

A Claude Code session that is already open picks up the switch within about 33 seconds, without restarting. Each account holds one parked login: switching to an account uses that login up, and switching away parks a fresh one.

When something is wrong

  • pitboard doctor checks everything pitboard depends on.
  • pitboard log shows what pitboard has changed, and when.
  • pitboard enroll work --sign-in signs in again to an account whose parked login expired or went missing.
  • pitboard abandon gives up on an interrupted switch that cannot be finished, keeping every login. Only needed when recovery cannot reach Anthropic.
  • pitboard uninstall deletes every parked login and pitboard's own files.

In Claude Code's status line

{ "statusLine": { "type": "command", "command": "pitboard statusline" } }

In ~/.claude/settings.json. It reads the session Claude Code passes it and pitboard's own files: no network, no credential touched.

Scripting

Every command that reports a result takes --json and prints the same envelope, including on failure: {v, command, ok, data, warnings, error}. Error codes are stable. Exit codes: 0 done, 1 not done, 2 command line wrong, 3 a login or Claude Code's files are in a state pitboard will not act on.

Large logins

macOS reads at most 4097 bytes of command from standard input, and a login with MCP server tokens in it can be larger. Claude Code then writes it on the argument line, where any process running as you can read it while the call lasts, and it does that for the same login on every refresh. pitboard refuses instead, unless PITBOARD_ARGV_FALLBACK=1 says to do what Claude Code does.

What it will not do

  • No switching by itself on any server signal.
  • No pooling or proxying of requests.
  • No failover when an account is on hold.
  • No renewing of the login you are signed in as. That is Claude Code's job.
  • No copying parked logins between machines. Presenting a refresh token another machine has rotated makes Claude Code drop the login on both.
