---
title: "Switch before an account runs out"
sidebarTitle: "Switch automatically"
description: "Have Pitboard switch Claude Code to another of your accounts before the one in use reaches a limit."
---

Automatic switching is off until you choose it. It acts once a limit of the Claude Code account in use reaches a share you choose: 95% by default, from 50% to 99%.

It switches early because open Claude Code sessions take up to about 33 seconds to follow, and never switches Codex, whose sessions do not follow at all. [Open sessions](/concepts/open-sessions) explains both.

## Turn it on

<Tabs>
  <Tab title="macOS">
    In **Settings** > **Limits**, choose **Switch Automatically** in **When a limit reaches**. Set the share in **At**, in its field or with its stepper, 95% at first.
  </Tab>
  <Tab title="Windows">
    Right-click Pitboard's icon in the notification area and select **Settings**. Under **Limits**, select **Switch automatically** in **When a limit reaches**, then expand it and set the share in **At**.
  </Tab>
</Tabs>

The app switches only while it is open, and posts a notification for each switch. Its **Switch Back** switches back to the account it left, as the notice in **Accounts** does.

On the command line, run `pitboard watch` and leave the terminal open. It switches at its own share, `--at`, 95 by default, and never reads the app's **When a limit reaches**.

```sh
pitboard watch --at 90
```

```text
Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 90%. Stop with Ctrl-C.
13:41:05 Watching work: 82% of its 5-hour limit, as of 13:41.
14:02:11 Switched Claude Code from work to personal: work has used 91% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.
```

[`watch`](/reference/account-commands#watch) lists every line.

The app, `pitboard watch` and `pitboard use` can run at once and never make two switches from one reading. [What a switch does](/concepts/switching#what-a-switch-does) explains why.

Anthropic's terms may cover automatic switching: see [Is this allowed](/concepts/limits#is-this-allowed).

## Run it in the background

`pitboard watch install` starts `pitboard watch` in the background, and again at each sign-in, at the share you give it. On Linux, which has no app, it is how Pitboard switches and warms up with no terminal open.

```sh
pitboard watch install --at 90
```

`pitboard watch uninstall` stops it. [The watch service](/reference/account-commands#the-watch-service) says what each system runs.

On Linux, where systemd did not start the system, as in many containers, it refuses with [`schedule_unsupported`](/reference/errors#renewal-schedule). Leave `pitboard watch` running in a terminal instead.

## Which account it switches to

Pitboard watches the account whose login Claude Code has stored, as Anthropic [identifies it](/concepts/identity), not the account Claude Code's config names.

Pitboard switches to another enrolled Claude Code account with room under the share in every limit. [Which account it switches to](/reference/automatic-switching#which-account-it-switches-to) gives every rule.

If no account qualifies, nothing moves until the account runs out. The app then offers a switch by the same rules at 100%, as [When an account runs out](/guides/switch#when-an-account-runs-out) describes.

## What it never does

- Switch back by itself. Next time, it may choose the account it left.
- Try an account again after its parked login failed, before the limit it was tried for resets.
- Quit an app.

## When it holds back

When Pitboard stays on the account or cannot decide, the app posts a notification and `pitboard watch` prints the reason. [Automatic switching](/reference/automatic-switching) lists each reason and what ends it.

On macOS, a run that cannot read the keychain, such as `pitboard watch` over SSH, fails only its own tries: see [macOS says the keychain is locked](/troubleshooting/accounts#macos-says-the-keychain-is-locked). On Windows, the same holds for a run in a sign-in over SSH with a key: see [Windows says Credential Manager cannot be reached](/troubleshooting/accounts#windows-says-credential-manager-cannot-be-reached).

A login file behind the keychain, or on Windows behind Credential Manager, does not stop a switch. [Open sessions](/concepts/open-sessions) says when open sessions follow it.

## Keep the numbers fresh

Pitboard decides from the usage it last read, so a busy session can reach the limit between [two reads](/concepts/usage#how-often-pitboard-asks).

[Show usage in Claude Code's status line](/guides/status-line) to record each session's usage after every response, where its periods identify the account. The app and `pitboard watch` see that as soon as it is written. The status line never switches.
