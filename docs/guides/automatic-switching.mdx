---

Automatic switching is off until you turn it on. It acts once a limit of the Claude Code account in use reaches a share you choose: 95% by default, from 50% to 99%.

Pitboard switches early because open Claude Code sessions take up to about 33 seconds to follow. It never switches Codex, whose open sessions do not follow a switch. [Open sessions](/concepts/switching#open-sessions) explains both.

## Turn it on

<Tabs>
  <Tab title="App">
    In **Settings** > **General**, under **Before an account runs out**, turn on **Switch Claude Code automatically**. Set the share with **Switch when a limit reaches 95%**.

    The app switches only while it is open, and posts a notification for each switch. [Switch Claude Code automatically](/reference/settings#switch-claude-code-automatically) lists what the line under the share says.
  </Tab>
  <Tab title="Command line">
    Run `pitboard watch` and leave the terminal open. It switches whether the app's setting is on or off, at its own share: `--at`, 95 by default.

    ```sh
    pitboard watch --at 90
    ```

    ```text
    Watching Claude Code. Pitboard switches to another of your accounts once a limit of the one in use reaches 90%. Stop with Ctrl-C.
    13:41:05 Watching work: 82% of its 5-hour limit, as of 13:41.
    14:02:11 Switched Claude Code from work to personal: work has used 91% of its 5-hour limit. Claude Code sessions already running follow within 33 seconds.
    14:02:13 Watching personal: 12% of its 5-hour limit, as of 14:01.
    ```

    [`watch`](/reference/account-commands#watch) lists every line it prints.
  </Tab>
</Tabs>

The app, `pitboard watch` and `pitboard use` can run at once and never make two switches from one reading. [Who starts a switch](/concepts/switching#who-starts-a-switch) explains why. [`pitboard log`](/reference/maintenance-commands#log) records each automatic switch as `auto-switch`.

## Which account it watches

Pitboard watches the account whose login Claude Code has stored, as Anthropic identifies it, not the account Claude Code's config names. After `/login` in Claude Code, it watches the account you signed in to. [How Pitboard knows whose login it is](/concepts/switching#how-pitboard-knows-whose-login-it-is) explains how.

## Which account it switches to

Pitboard watches every limit of the account in use, a model's weekly limit included. A limit counts at the whole percentage Pitboard shows, so 94.5% reaches 95%.

Once a limit reaches the share, Pitboard looks for another enrolled Claude Code account that:

- Has a parked login that has not expired.
- Has a reading from Anthropic.
- Has used less than the share of every limit it has.

An account without the limit at the share qualifies, such as a Team seat with no weekly limit for all models.

A reading may leave a limit out when Anthropic answers without its list of limits, or Pitboard cannot read the answer whole. Such a reading qualifies only with the five-hour and weekly limits, and with a model's weekly limit when that one is at the share.

Pitboard takes the account with the most room in the limit at the share, counting a missing limit as unused. On a tie, it takes the one least full in its other limits. A limit past its reset time counts as reset.

When several limits are at the share, Pitboard acts on the fullest one it has not already left or given up on.

If none qualifies, nothing moves. Once the account runs out, the app offers a switch by this rule at 100%, as [When an account runs out](/guides/switch#when-an-account-runs-out) describes.

## What it never does

- Switch back by itself. Next time, it may choose the account it left.
- Try an account again after its parked login failed, before the limit it was tried for resets.
- Quit an app.

## When it holds back

While one of these holds, Pitboard decides nothing, and the app posts **Pitboard is not switching Claude Code**.

| Reason | Ends when |
| --- | --- |
| A switch was interrupted. | Your next change finishes it, or [`pitboard abandon`](/reference/recovery-commands#abandon) gives up on it. |
| Claude Code uses [`CLAUDE_CODE_CUSTOM_OAUTH_URL`](/reference/files#environment-variables). | You unset it. |
| Claude Code has no login stored. | You sign in. |
| Claude Code has the login of an account you have not enrolled. | You enrol it. |
| Pitboard cannot identify Claude Code's login. | A later try identifies it. |
| Anthropic has given no reading of the account in use. | Pitboard's next read gets one. |

Once a limit reaches the share, Pitboard stays on the account while one of these holds. The app posts **Claude Code was not switched** and `pitboard log` records `auto-stay`, once for each limit and its reset.

| Reason | Ends when |
| --- | --- |
| No other account qualifies. | One does, or the limit resets. |
| Pitboard already left this limit, and the account is back in use. | The limit resets. |
| Three tries at this limit failed. | The limit resets. |
| A switch, sign-in or enrolment put the account in use less than 5 minutes ago. | 5 minutes pass. |
| Claude Code signs in another way, such as `apiKeyHelper`. | You remove that setting, which `pitboard doctor` names. |

A failed try posts **Pitboard could not switch Claude Code**. The next try waits 1 minute, and each failure in a row doubles the wait, up to 15 minutes. A failure that may pass, such as Anthropic out of reach, does not count toward the three tries.

A run that cannot read the keychain, such as `pitboard watch` over SSH, fails only its own tries. See [macOS says the keychain is locked](/troubleshooting#macos-says-the-keychain-is-locked).

A login file behind the keychain does not stop a switch. [Open sessions](/concepts/switching#open-sessions) says when open sessions follow it.

## Keep the numbers fresh

Pitboard decides from the usage it last read, so a busy session can reach the limit between two reads. [How often Pitboard asks](/concepts/usage#how-often-pitboard-asks) gives the interval.

[Show usage in Claude Code's status line](/guides/status-line) adds `pitboard statusline`. After each response, it records the session's usage where its periods identify the account. The app and `pitboard watch` see that within 2 seconds. The status line never switches.
