Until you enrol a Codex account, Pitboard lists nothing about OpenAI's Codex CLI, not even the account Codex is signed in to. It asks OpenAI nothing either.

## Before you enrol a Codex account

Pitboard switches Codex only while Codex is signed in with ChatGPT. Codex must keep that login in its file store: `~/.codex/auth.json`, or `auth.json` in `CODEX_HOME`. To check, run:

```sh
pitboard doctor
```

In the Codex section, `Codex login store` reads `file`, and `Codex login` reads your email address. If it says `cannot tell`, fix the place it names.

Codex's setting `cli_auth_credentials_store` chooses the store. Pitboard refuses every store but `file`:

| `Codex login store` | Where Codex keeps the login |
| --- | --- |
| `keyring` | A keychain item Codex made for itself. |
| `auto` | The same keychain item, falling back to the file. |
| `secrets` | An encrypted file whose key is in the keychain: `keyring` or `auto` with `secret_auth_storage` turned on in `[features]`. |
| `ephemeral` | In memory, for one run of Codex. |

Read in Codex 0.154.0. Pitboard does not read Codex's keychain stores, because every read would ask you for permission. A login kept in memory leaves nothing to park.

If the store is `file` but Codex is signed out or uses an API key, run `codex login` and sign in with ChatGPT.

### Use the file store

If the `Codex login store` line names your own `config.toml` or `/etc/codex/config.toml`, set the file store in your own `config.toml`, in `~/.codex` or `CODEX_HOME`:

```toml title="~/.codex/config.toml"
cli_auth_credentials_store = "file"
```

Then run `codex login` and sign in with ChatGPT.

If the line names `/etc/codex/managed_config.toml`, `/etc/codex/requirements.toml` or a managed preference of `com.openai.codex`, only an administrator can change the store. [Codex files](/reference/files#codex-files) lists every place Codex reads the setting from.

## Add Codex accounts

<Tabs>
  <Tab title="App">
    <Steps>
      <Step title="Open the dialog">
        Click Pitboard's item in the menu bar, then choose **Add Account**. If the dialog has a **Tool** pop-up menu, choose **Codex**.
      </Step>
      <Step title="Name the account">
        Enter a name such as `work`, then click **Sign In**.
      </Step>
      <Step title="Sign in">
        In your browser, sign in with the ChatGPT account you are adding. If the browser does not open, click **Open Sign-In Page**.
      </Step>
    </Steps>

    If the dialog says Codex is not offered, install Codex, then quit Pitboard and open it again. The app looks for `codex` only when it opens.

    Once one Codex account is enrolled, name the account Codex is signed in to as in [Add the account you are signed in to](/guides/accounts#add-the-account-you-are-signed-in-to).
  </Tab>
  <Tab title="Command line">
    A Codex label starts with `codex/`.

    ```sh
    pitboard enroll codex/personal          # the account Codex is signed in to
    pitboard enroll codex/work --sign-in    # another account
    ```

    With `--sign-in`, your browser opens. Sign in with the ChatGPT account you are adding.

    ```text
    Enrolled codex/work (work@example.com). Switch to it with: pitboard use codex/work
    ```
  </Tab>
</Tabs>

Do not add accounts with `codex login`. It revokes the login in use, which then needs a browser sign-in: see [Add another account](/guides/accounts#add-another-account).

## How Codex accounts differ

- Nothing that runs Codex follows a switch. Start each again as [What happens to open sessions](/guides/switch#what-happens-to-open-sessions) says.
- Pitboard never switches Codex by itself. [Switch before an account runs out](/guides/automatic-switching) is for Claude Code only.
- Pitboard identifies a Codex login from the login itself, without asking OpenAI. See [How Pitboard knows whose login it is](/concepts/switching#how-pitboard-knows-whose-login-it-is).
- A switch still asks OpenAI whether the parked login works, by reading that account's usage. The read spends none of its limits: see [Where the numbers come from](/concepts/usage#where-the-numbers-come-from).
- A parked Codex login shows `ready` with no `good for` time, because Codex states no lifetime for its login (read in 0.154.0).
- On macOS, Pitboard passes every parked Codex login to `security` as an argument: see [Large logins on macOS](/security#large-logins-on-macos).
