Until you enrol a Codex account, Pitboard lists nothing about OpenAI's Codex CLI, not even the account Codex is signed in to, and asks OpenAI nothing.

## Add Codex accounts

Add each one as [Add another account](/guides/accounts#add-another-account) shows: in the app, choose **Codex** under **Tool** and enter the name alone, and on the command line, start the label with `codex/`.

In the app, start with **Add Codex Account** in the tip **Use Pitboard with Codex**. Pitboard reads which account Codex is signed in to only then, and offers to name it. On the command line, `pitboard enroll codex/personal` enrols that account at once.

Adding an account runs `codex login` from OpenAI's Codex CLI, not the copy inside the ChatGPT app. If the dialog says Pitboard cannot find the Codex CLI, see [Pitboard cannot find a tool](/troubleshooting/accounts#pitboard-cannot-find-a-tool).

If Pitboard refuses to enrol a Codex account, its message says why, and [Fix Codex accounts](/troubleshooting/codex) says what to change.

## Restart what runs Codex

Nothing that runs Codex follows a switch, so restart each:

| What runs Codex | What to do |
| --- | --- |
| A `codex` session | Quit it and start it again. |
| The ChatGPT app on macOS | Quit it with Command-Q, not by closing its windows, and open it again. |
| The ChatGPT app on Windows | Quit it from its icon in the notification area, and open it again. |
| The ChatGPT app on Linux | Quit it and open it again. |
| Codex's background app server on macOS and Linux | Run `codex app-server daemon restart`. |
| Codex's background app server on Windows | Run `codex app-server daemon restart` from a terminal that is not elevated. |
| Codex in an editor | Run **Developer: Reload Window** in each window that uses Codex. |

Read in the ChatGPT app 26.928.31416 for macOS and Codex 0.159.3. The app server's Windows row is read in Codex 0.162.1 for Windows, and the ChatGPT app's Linux row in its package 26.1016.61520 for Linux. Quitting the ChatGPT app on Windows, by hand or for a switch, has not been measured, and neither has the editor row.

After a Codex switch, Pitboard lists which of these still run. If it cannot read the process list, it warns with `sessions_unknown`.

As read in Codex 0.164.0, a background app server that an older Codex set up can run from the same folder as `codex` sessions. Pitboard then lists it as a `codex` session.

In the app, a Codex switch while the ChatGPT app is open asks first, then quits it, switches and opens it again. [Quitting Claude or the ChatGPT app](/reference/mac-app#quitting-claude-or-the-chatgpt-app) says how long it waits. The command line never quits an app.

<Warning>
  Do not sign out in anything that ran Codex before the switch, such as `/logout` in a `codex` session or **Log Out** in the ChatGPT app. Each holds the parked login, and signing out revokes it at OpenAI: see [Why Codex logins are moved, not copied](/concepts/switching#why-codex-logins-are-moved-not-copied).

  If you did, [sign in to the old account again](/guides/sign-in-again), or run `pitboard enroll codex/personal --sign-in`.
</Warning>

## How Codex accounts differ

- Pitboard never switches Codex by itself.
- Pitboard identifies a Codex login from the login itself, without asking OpenAI. See [How Pitboard knows whose login it is](/concepts/identity).
- A switch asks OpenAI whether the parked login works by [reading that account's usage](/concepts/usage#where-the-numbers-come-from), which spends none of its limits.
- A parked Codex login shows `ready` with no `good for` time, because Codex states no lifetime for its login (read in 0.154.0).
- On macOS, Pitboard passes every parked Codex login to `security` as an argument: see [Large logins on macOS](/security#large-logins-on-macos).
