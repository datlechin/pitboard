## Why parked logins expire

How long a [parked login](/concepts/switching#parked-logins) lasts depends on its tool:

| Tool | How long it lasts | `pitboard` shows | The app shows |
| --- | --- | --- | --- |
| Claude Code | 30 days after its last renewal | `ready · good for 26d 4h` | **Parked login good for 26 more days** |
| Codex | Pitboard knows no expiry for it | `ready`, with no time | No time |
| Claude Desktop | Until claude.ai ends the sign-in | `ready · sign-in may lapse in 25d 3h` | **Its sign-in may lapse in 25 days** |

Pitboard never renews a Claude Desktop parked login. [What Pitboard does not do for Claude Desktop](/concepts/claude-desktop#what-pitboard-does-not-do-for-claude-desktop) says how far to trust its date.

Pitboard renews parked logins only when it runs: `pitboard` in a terminal, the app while it is open, or daily renewal. After 30 days with none of them, every Claude Code parked login has expired. [`renew`](/reference/maintenance-commands#renew) says when each one is due.

An expired parked login needs a browser sign-in: see [Sign in to an account again](/guides/sign-in-again).

The login in use belongs to its tool, which renews it. [When Pitboard renews a login in use](/concepts/identity#when-pitboard-renews-a-login-in-use) names the cases where Pitboard does.

## Turn on daily renewal

Daily renewal runs `pitboard renew` once a day, from the system's own scheduler. It renews your parked logins and does nothing else. [`schedule`](/reference/maintenance-commands#schedule) says when each system runs it.

<Tabs>
  <Tab title="macOS">
    Click Pitboard's item in the menu bar, choose **Settings**, then click **Renewal**. Turn on **Renew parked logins daily**.

    The app must be in your Applications folder: until you move it there, macOS runs a temporary copy, and the setting cannot be turned on.
  </Tab>
  <Tab title="Windows">
    Right-click Pitboard's icon in the notification area and select **Settings**. Under **Renewal**, turn on **Renew parked logins daily**.
  </Tab>
</Tabs>

On the command line:

```sh
pitboard schedule install
```

```text
Parked logins will be renewed daily.
/Users/me/Library/LaunchAgents/com.datlechin.pitboard.renew.plist

It renews your own parked logins and does nothing else: it never switches account and never asks Anthropic for usage.
```

The second line says where the schedule is: on Windows, the task's path, such as `\Pitboard\Renew S-1-5-21-…`.

Each run renews whatever is due. Behind a proxy, turn it on with `pitboard schedule install` from a shell that sets the proxy, and run it again after the proxy changes. [`schedule`](/reference/maintenance-commands#schedule) lists the variables it keeps.

It renews only the parked logins in Pitboard's own directory: `~/.pitboard`, or `%LOCALAPPDATA%\Pitboard` on Windows. While `PITBOARD_HOME` names another directory, turning it on fails with `schedule_not_default_home`. To renew the parked logins there, run `pitboard renew` yourself with `PITBOARD_HOME` set.

## Check or turn off daily renewal

In the app, **Renew parked logins daily** in the **Renewal** settings shows whether it is on. Turn it off to stop daily renewal.

On the command line:

```sh
pitboard schedule status
```

```text
Parked logins are renewed every 1d 0h by this computer's own scheduler.
/Users/me/Library/LaunchAgents/com.datlechin.pitboard.renew.plist
```

To stop it:

```sh
pitboard schedule uninstall
```

If `pitboard doctor` reports a problem with its `renewal schedule` check, see [Daily renewal stopped working](/troubleshooting/renewal#daily-renewal-stopped-working).

## Renew now

A parked login that `pitboard` shows as `expires in 2d 3h` needs only a renewal, not a sign-in.

While the app is open, it renews parked logins as it reads usage. On the command line:

```sh
pitboard renew
```

```text
Renewed all 2.
```

For every line it can print, see [`renew`](/reference/maintenance-commands#renew).

## Accounts you no longer use

Pitboard keeps renewing a Claude Code or Codex parked login for as long as its account stays enrolled. `pitboard doctor` warns about such an account unused for 30 days or more.

If you are not coming back to an account, forget it: see [Forget an account](/guides/accounts#forget-an-account).
