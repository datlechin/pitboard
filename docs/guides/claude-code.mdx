Pitboard switches Claude Code on macOS, Windows and Linux. A switch puts another account's [parked login](/concepts/switching#parked-logins) where Claude Code reads its login:

| System | Where Claude Code keeps its login |
| --- | --- |
| macOS | The keychain |
| Windows | `.credentials.json` in Claude Code's folder, or Credential Manager with that file behind it |
| Linux | `.credentials.json` in Claude Code's folder |

Claude Code's folder is `~/.claude`, or the folder `CLAUDE_CONFIG_DIR` names. [Claude Code files](/reference/files#claude-code-files) lists what Pitboard reads there.

## Before you add a Claude Code account

A variable such as `ANTHROPIC_API_KEY`, or `apiKeyHelper` in Claude Code's settings, makes Claude Code ignore the login Pitboard switches. Changes to Claude Code accounts still go ahead, with the warning `auth_overridden`. [Variables that override the login](/reference/environment-variables#variables-that-override-the-login) lists them all. To check, run:

```sh
pitboard doctor
```

The `what a session authenticates with` line warns and names the setting when Claude Code signs in another way.

Where managed settings set `forceLoginOrgUUID`, Claude Code refuses a login of any other organisation, as read in Claude Code 2.1.309. Pitboard then refuses with `login_restricted` to switch to such an account. Only whoever manages this computer can change the setting.

Where managed settings set `forceLoginMethod` to `console`, Claude Code's sign-in makes an Anthropic Console API key and keeps no claude.ai login, as read in Claude Code 2.1.310. Pitboard then refuses with `sign_in_pinned_to_console` to start a sign-in, and switches to accounts you already added go ahead. Only whoever manages this computer can change the setting.

While `CLAUDE_CODE_CUSTOM_OAUTH_URL` is set, Pitboard refuses every change to Claude Code accounts with `custom_oauth_endpoint`. [Custom OAuth endpoint](/reference/environment-variables#custom-oauth-endpoint) says why.

On Windows, Claude Code keeps its login in Credential Manager where `CLAUDE_CODE_FORCE_WINDOWS_CREDMAN` is `1`, or where a feature it caches turns that store on, as read in Claude Code 2.1.301. The `credential store` line of `pitboard doctor` names the store Pitboard reads. Where Credential Manager holds a Claude Code login and nothing Pitboard reads says Claude Code uses it, Pitboard refuses every change until you set the variable in `settings.json`:

```json title="%USERPROFILE%\.claude\settings.json"
{
  "env": {
    "CLAUDE_CODE_FORCE_WINDOWS_CREDMAN": "1"
  }
}
```

A Windows profile that roams takes Credential Manager's items to every PC you sign in to, so a switch on one changes Claude Code's login on the others. The `credential store` line warns about it.

## Add Claude Code accounts

Add each one as [Add another account](/guides/accounts#add-another-account) shows. In the app, choose **Claude Code** under **Tool**.

A label with no prefix enrols a Claude Code account: `pitboard enroll work --sign-in` adds one. `pitboard enroll personal` enrols the account Claude Code is signed in to, as [Add the account you are signed in to](/guides/accounts#add-the-account-you-are-signed-in-to) shows. Where another tool also has a `work`, other commands need `claude/work`: see [Labels](/reference/commands#labels).

Do not add an account with Claude Code's `/login`, as [Add another account](/guides/accounts#add-another-account) warns.

If Pitboard says `claude` is not on this machine, see [Pitboard cannot find a tool](/troubleshooting/accounts#pitboard-cannot-find-a-tool). In Windows PowerShell, run a Claude Code installed with npm as `claude.cmd`, as [Claude Code does not start in Windows PowerShell](/troubleshooting/accounts#claude-code-does-not-start-in-windows-powershell) says.

## How Claude Code accounts differ

- Open Claude Code sessions follow a switch with no restart. [How open sessions follow a switch](/concepts/open-sessions) says when, and what can pin them.
- Pitboard switches only Claude Code by itself: see [Switch before an account runs out](/guides/automatic-switching).
- Pitboard warms up only Claude Code accounts: see [Warm up accounts](/guides/warm-up).
- `pitboard statusline` shows each Claude Code account's usage in Claude Code's status line: see [Show usage in Claude Code's status line](/guides/status-line).
- Pitboard asks Anthropic to identify a Claude Code login: see [How Pitboard knows whose login it is](/concepts/identity).
- `/status` in Claude Code can name another account than Pitboard shows: see [Claude Code shows another account than Pitboard](/troubleshooting/accounts#claude-code-shows-another-account-than-pitboard).
- A parked Claude Code login expires if Pitboard does not run to renew it: see [Keep parked logins alive](/guides/renewal).
- In the app, a Claude Code account's [account window](/guides/account-windows) opens claude.ai.
