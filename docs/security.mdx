---
title: "Security and privacy"
description: "Pitboard keeps parked logins on your machine, sends them only to the service that issued them, and has no telemetry."
---

Pitboard moves and stores the OAuth refresh tokens of Claude Code and OpenAI's Codex CLI, and on macOS the files that hold a Claude Desktop login. Each grants full access to a paid account. [SECURITY.md](https://github.com/datlechin/pitboard/blob/main/SECURITY.md) lists what Pitboard protects against and how to report a vulnerability. [Website data](/reference/account-windows#website-data) covers each account window's sign-in.

## Where parked logins are kept

<Tabs>
  <Tab title="macOS">
    Claude Code and Codex parked logins are keychain items whose names start with `pitboard-park-`. Pitboard reads and writes them, and Claude Code's item, only through `/usr/bin/security`, the one program that item trusts.

    Codex keeps its own login in a plaintext `auth.json`. `pitboard doctor` fails if anyone else has access to a login file Claude Code left behind the keychain, and warns for Codex's `auth.json`.
  </Tab>
  <Tab title="Windows">
    Parked logins are files in `vault` in Pitboard's directory, `%USERPROFILE%\AppData\Local\Pitboard`. Pitboard seals each with Windows' data protection under your own Windows account, never the machine's, so no other account can open one. Pitboard makes its folders and files reachable only by you, SYSTEM and Administrators.

    Claude Code keeps its own login in a plaintext `.credentials.json`, which takes the access list of its folder, or in Credential Manager, which every sign-in of yours on that PC reads. Codex keeps its login in a plaintext `auth.json`. `pitboard doctor` fails if anyone else can reach a parked login or Claude Code's file, and warns for Codex's `auth.json`, each time with the `icacls` commands that fix it.
  </Tab>
  <Tab title="Linux">
    Parked logins are items in your login keyring, the Secret Service's default collection, which every Pitboard directory of your session shares. Pitboard reaches it over your session's D-Bus, through an encrypted session.

    A Pitboard directory made where no Secret Service answers, such as in a container, keeps its parked logins as files in `~/.pitboard/vault/`, at mode 0600 in a 0700 directory, and so does one an earlier Pitboard made. Claude Code keeps its own login in a plaintext `~/.claude/.credentials.json`. Any process running as you can read these files. `pitboard doctor` fails if anyone else has access to them, and warns for Codex's `auth.json`.
  </Tab>
</Tabs>

A Claude Code parked login holds the OAuth block and the account's other fields, such as `trustedDeviceToken`. Whether restoring a device token spares a re-verification has not been measured. A Codex parked login is the whole `auth.json`, which can also hold an OpenAI API key, as read in Codex 0.154.0.

On macOS, a Claude Desktop parked login is Claude's own files and keys of `config.json`, in a folder under `~/.pitboard/parks` that only you can open. Pitboard renames them there and back, and never copies them. It reads no keychain item for Claude Desktop, `Claude Safe Storage` included, and decrypts no cookie. Of the session cookie, it keeps only a fingerprint. `pitboard doctor` fails if anyone else has access to `parks`. [Folders in parks](/reference/files#folders-in-parks) has the layout.

## What leaves your machine

Pitboard has no server of its own and sends no request for a Claude Desktop account. It makes only these requests itself:

| Request | Carries | Used for |
| --- | --- | --- |
| `api.anthropic.com/api/oauth/validate` | An access token | Identifying a Claude Code login |
| `api.anthropic.com/api/oauth/profile` | An access token | The email of a Claude Code account Pitboard does not know yet |
| `api.anthropic.com/api/oauth/usage` | An access token | A Claude Code account's usage |
| `platform.claude.com/v1/oauth/token` | A refresh token and the client id it was issued to | Renewing a Claude Code parked login, or the login in use in the [three cases](/concepts/identity#when-pitboard-renews-a-login-in-use) where Pitboard does |
| `chatgpt.com/backend-api/wham/usage` | An access token and the ChatGPT account id | A Codex account's usage, and checking a login before a switch to it |
| `auth.openai.com/oauth/token`, or the issuer a Codex login records | A refresh token and the client id the login records, or Codex's | Renewing a Codex parked login |
| claude.ai, chatgpt.com, their sign-in pages and what their pages load | What the site keeps in that window | An account window, through WebKit on macOS or WebView2 on Windows |
| `github.com/datlechin/pitboard/releases` | Nothing of yours | The app's [update check](/reference/settings#updates) and downloads, its feed `appcast.xml` on macOS and `appcast-windows.xml` on Windows, and the tarball the install script downloads |
| `usepitboard.com/install.sh` | Nothing of yours | The line in [Install with the script](/install#install-with-the-script): a redirect, kept at Cloudflare, to the script on GitHub |

GitHub redirects each release download to `release-assets.githubusercontent.com`, as measured on 12 October 2026. The command line never checks for updates.

Pitboard's own requests verify TLS against your system's trust store and time out after 5 seconds. Each names Pitboard in its `User-Agent`, `pitboard/<version>`. A [proxy](/reference/environment-variables#proxies) sees each request's host, not what it carries. A company proxy whose root certificate your system trusts can decrypt each request, tokens included.

## What a warm-up sends

A [warm-up](/guides/warm-up) is Claude Code's own request: `claude -p` sends Anthropic one message on Claude Code's smallest model, with no tools, and fetches what Claude Code fetches as it starts, such as the account's profile and policy limits. Measured with Claude Code 2.1.296, the request costs about 3,100 tokens of the plan.

Pitboard starts it from a folder of its own in the Pitboard directory, with `PATH`, your user name and any proxy variables from its own environment and nothing else. It hands Claude Code the account's access token on a pipe, never a refresh token, so the run cannot renew or spend a login. As read in 2.1.296, Claude Code keeps that token in no store.

On Windows, Pitboard also passes on `SystemRoot`, and names the Git Bash it finds in `CLAUDE_CODE_GIT_BASH_PATH`. As read in 2.1.301 on Windows, Claude Code reads no token from a pipe. As read in 2.1.303, it takes one in `CLAUDE_CODE_OAUTH_TOKEN` instead, as a login with no refresh token. Pitboard hands the access token in that variable, and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` keeps it from most programs Claude Code starts. Some get Claude Code's whole environment, token included: `where.exe` as it looks for Git where Pitboard found no Git Bash to name, some `git` commands, and a `proxyAuthHelper` set in managed settings. Another process running as you can read the token there while the run lasts, at most 2 minutes. No warm-up on Windows has been measured against Anthropic, so whether Claude Code keeps the token in a store there is not known.

## Large logins on macOS

Pitboard hands a login to `security` in hex on standard input, where `ps` cannot see it. That input stays within 4032 bytes, Claude Code's own ceiling as read in 2.1.284: about 2 KB of login. MCP server tokens can push a Claude Code login past that, and every Codex parked login is past it.

Past it, Pitboard passes the login as an argument, which another process running as you could read while the call lasts. A switch, a `--sign-in` enrolment or `pitboard stow` that does this says so. A renewal does not. `pitboard doctor` warns while Claude Code's login is that large.

With `PITBOARD_NO_ARGV=1`, Pitboard refuses such a write. It then parks no Codex account, and leaves a parked login that size unrenewed. Opened from Finder or at login, the app lacks your shell's `PITBOARD_NO_ARGV`. A renewal schedule installed while it is set keeps it.

On Windows, no login goes on an argument line: Credential Manager takes a large login in up to 256 pieces, about 450 KB. A larger one stops a change with [`credential_too_large`](/reference/errors#parked-logins). `PITBOARD_NO_ARGV` changes nothing there, and `pitboard doctor` warns while it is set.
