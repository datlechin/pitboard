Pitboard moves and stores the OAuth refresh tokens of Claude Code and OpenAI's Codex CLI, and the files that hold a Claude Desktop login. Each grants full access to a paid account. [SECURITY.md](https://github.com/datlechin/pitboard/blob/main/SECURITY.md) lists what Pitboard protects against and how to report a vulnerability. [How account windows keep their data](/concepts/account-windows) covers each window's sign-in.

## Where parked logins are kept

On macOS, Claude Code and Codex parked logins are keychain items whose names start with `pitboard-park-`. Pitboard reads and writes them, and Claude Code's item, only through `/usr/bin/security`, the one program that item trusts.

On Linux, parked logins are files in `~/.pitboard/vault/`, at mode 0600 in a 0700 directory, and Claude Code keeps its own login in a plaintext `~/.claude/.credentials.json`. Any process running as you can read both. `pitboard doctor` fails if anyone else has access to either, and warns for Codex's `auth.json`.

A Claude Desktop parked login is Claude's own files and keys of `config.json`, in a folder under `~/.pitboard/parks` that only you can open. Pitboard renames them there and back, and never copies them. It reads no keychain item for Claude Desktop, `Claude Safe Storage` included, and decrypts no cookie. Of the session cookie, it keeps only a fingerprint. `pitboard doctor` fails if anyone else has access to `parks`. [Folders in parks](/reference/files#folders-in-parks) has the layout.

A Claude Code parked login holds the OAuth block and the account's other fields, such as `trustedDeviceToken`. Whether restoring a device token spares a re-verification has not been measured. A Codex parked login is the whole `auth.json`, which can also hold an OpenAI API key, as read in Codex 0.154.0.

## What leaves your machine

Pitboard has no server of its own and sends no request for a Claude Desktop account. It makes only these requests itself:

| Request | Carries | Used for |
| --- | --- | --- |
| `api.anthropic.com/api/oauth/validate` | An access token | Identifying a Claude Code login |
| `api.anthropic.com/api/oauth/profile` | An access token | The email of a Claude Code account Pitboard does not know yet |
| `api.anthropic.com/api/oauth/usage` | An access token | A Claude Code account's usage |
| `platform.claude.com/v1/oauth/token` | A refresh token and the client id it was issued to | Renewing a Claude Code parked login, or the login in use in the [three cases](/concepts/identity#when-pitboard-renews-a-login-in-use) where Pitboard does |
| `chatgpt.com/backend-api/wham/usage` | An access token and the ChatGPT account id | A Codex account's usage, and checking a login before a switch to it |
| `auth.openai.com/oauth/token` | A refresh token and Codex's client id | Renewing a Codex parked login |
| claude.ai, chatgpt.com, their sign-in pages and what their pages load | What the site keeps in that window | An account window, through WebKit |
| `github.com/datlechin/pitboard/releases` | Nothing of yours | The app's [update check](/reference/settings#updates) and downloads, and the tarball the install script downloads |
| `usepitboard.com/install.sh` | Nothing of yours | The line in [Install with the script](/install#install-with-the-script): a redirect, kept at Cloudflare, to the script on GitHub |

GitHub redirects each release download to `release-assets.githubusercontent.com`, as measured on 12 October 2026. The command line never checks for updates.

A [warm-up](/guides/warm-up#what-a-warm-up-sends) is Claude Code's own request, made with the account's access token and never a refresh token.

Pitboard's own requests verify TLS against your system's trust store and time out after 5 seconds. A [proxy](/reference/files#proxies) sees each request's host, not what it carries. A company proxy whose root certificate your system trusts can decrypt each request, tokens included.

## Large logins on macOS

Pitboard hands a login to `security` in hex on standard input, where `ps` cannot see it. That input stays within 4032 bytes, Claude Code's own ceiling as read in 2.1.284: about 2 KB of login. MCP server tokens can push a Claude Code login past that, and every Codex parked login is past it.

Past it, Pitboard passes the login as an argument, which another process running as you could read while the call lasts. A switch, a `--sign-in` enrolment or `pitboard stow` that does this says so. A renewal does not. `pitboard doctor` warns while Claude Code's login is that large.

With `PITBOARD_NO_ARGV=1`, Pitboard refuses such a write. It then parks no Codex account, and leaves a parked login that size unrenewed. Opened from Finder or at login, the app lacks your shell's `PITBOARD_NO_ARGV`. A renewal schedule installed while it is set keeps it.
