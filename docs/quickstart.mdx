---
title: "Quickstart"
description: "Install Pitboard, add two Claude Code accounts, see what each has left and switch between them."
---

Enrol two Claude Code accounts with Pitboard's command line, switch between them and see what each account has left.

Before you start, install Claude Code, run `claude` once and sign in to one of your accounts.

<Steps>
  <Step title="Install Pitboard">
    Run one of these commands, not both. The menu bar app includes the command line.

    ```sh
    brew install datlechin/tap/pitboard            # the command line, macOS and Linux
    brew install --cask datlechin/tap/pitboard-app # the menu bar app, macOS 14 or later
    ```

    To check the install, run `pitboard --version`. It prints `pitboard` and the version number. For other ways to install, see [Install Pitboard](/install).
  </Step>
  <Step title="Add the account you are signed in to">
    Enrol the account Claude Code is signed in to, under the label `personal`. A label is the short name you give an account.

    ```sh
    pitboard enroll personal
    ```

    ```text
    Enrolled personal (me@example.com), the account signed in now.
    Add another without signing out of it: pitboard enroll <label> --sign-in
    ```
  </Step>
  <Step title="Add a second account">
    Enrol your second account as `work`. The `--sign-in` option runs Claude Code's own sign-in, and Claude Code stays signed in to `personal`.

    ```sh
    pitboard enroll work --sign-in
    ```

    Pitboard prints this line:

    ```text
    Opening Claude Code's sign-in. Sign in as the account to add; the account in use now stays signed in.
    ```

    Claude Code's sign-in opens in your browser. Sign in there as your second account. Pitboard keeps that account's login until you switch to it, and prints:

    ```text
    Enrolled work (me@company.com). Switch to it with: pitboard use work
    ```
  </Step>
  <Step title="Switch to it">
    Switch Claude Code to `work`.

    ```sh
    pitboard use work
    ```

    ```text
    Switched to work; personal is parked.
    Claude Code sessions already running follow within 33 seconds.
    ```

    `work` is the account in use. `personal`'s login is parked: Pitboard keeps it until you switch back with `pitboard use personal`.

    A Claude Code session that is already open picks up the switch within about 33 seconds. You do not have to restart it. If the second line names `.credentials.json` instead, open sessions keep `personal` until their login is next renewed, as [Open sessions](/concepts/switching#open-sessions) explains.
  </Step>
  <Step title="See what each account has left">
    Run `pitboard` on its own.

    ```sh
    pitboard
    ```

    ```text
    ● work      me@company.com  signed in
        5h    █░░│░░░░░░   12%  resets in 3h 02m  27% under pace
        week  ████░░│░░░   40%  resets in 2d 4h   29% under pace

    ○ personal  me@example.com  ready · good for 26d 4h
        5h    ██████░│░░   59%  resets in 1h 10m  18% under pace
        week  █│█████░░░   73%  resets in 5d 18h  55% over pace
    ```

    The account in use is marked `●` and `signed in`. `ready` means you can switch to the account, and `good for 26d 4h` is how long its parked login lasts.

    Under each account, `5h` is its five-hour limit and `week` is its weekly limit. Each line shows how much of the limit is used, when it resets and how its use compares with an even [pace](/concepts/usage#pace).

    When a limit of the account in use is over pace, a last line under it says when it runs out. For what each line means, see [Check what each account has left](/guides/usage#read-the-lines-under-each-account).
  </Step>
</Steps>
