---
title: "Remove Pitboard"
description: "Delete parked logins with `pitboard uninstall`, then remove Pitboard the way you installed it."
---

Removing the program alone leaves every parked login on the machine.

## Delete parked logins first

`pitboard uninstall` turns off daily renewal, deletes every parked login this Pitboard wrote, then deletes `~/.pitboard`.

<Warning>
  `pitboard uninstall` cannot be undone. Claude Code and OpenAI's Codex CLI stay signed in to the accounts in use. Every other account needs a browser sign-in before you can use it again.
</Warning>

<Steps>
  <Step title="Quit the app">
    If the app is open, click Pitboard's item in the menu bar, then choose **Quit Pitboard**. While it runs, it recreates `~/.pitboard`.
  </Step>
  <Step title="Remove the status line">
    If Claude Code's status line runs `pitboard statusline`, delete the `statusLine` field from `~/.claude/settings.json`, or the call from your own script. Each run recreates `~/.pitboard`.
  </Step>
  <Step title="Delete the parked logins">
    ```sh
    pitboard uninstall
    ```

    It asks first. Enter `y`, or add `--yes` to skip the question.

    If your shell cannot find `pitboard`, run the copy inside the app:

    ```sh
    /Applications/Pitboard.app/Contents/Helpers/pitboard uninstall
    ```
  </Step>
</Steps>

With two parked logins and daily renewal on, it prints:

```text
Removed 2 parked login(s). The login each tool is signed in with is untouched.
Turned off the daily renewal schedule.
~/.pitboard is gone. Remove Pitboard itself the way you installed it.
```

If a parked login cannot be deleted, Pitboard keeps `~/.pitboard`. Run `pitboard uninstall` again.

On macOS, deleting `~/.pitboard` by hand leaves the parked logins in the keychain, still valid. Nothing else names them, so `pitboard uninstall` cannot find them. If you already deleted it, delete the `pitboard-park-` items in Keychain Access.

If you set `PITBOARD_HOME`, or `pitboard uninstall` refuses or leaves parked logins, see [`uninstall`](/reference/maintenance-commands#uninstall).

## Remove Pitboard itself

| Installed with | To remove it |
| --- | --- |
| `pitboard` cask | `brew uninstall --cask pitboard` |
| `pitboard-app` cask | `brew uninstall --cask pitboard-app` |
| `cargo binstall` or `cargo install` | `cargo uninstall pitboard` |
| A release tarball | Delete `pitboard`, and the man page and completion files if you copied them. |
| The app from a release download | Move `Pitboard.app` to the Trash. |

- `--zap` on either cask also removes a daily renewal schedule that `pitboard uninstall` left.
- `--zap` on `pitboard-app` also removes the app's files in `~/Library`.
- Neither cask's `--zap` deletes `~/.pitboard`.

If the app came from the `pitboard` cask of 0.3.0 or earlier, leave out `--zap`: see [From the old app cask](/install/upgrade-from-0-3-0#from-the-old-app-cask).

Otherwise the app's files in `~/Library` stay. They hold each account window's claude.ai or chatgpt.com sign-in, and `pitboard uninstall` does not delete them. To remove them, move each `com.usepitboard.Pitboard` item that [The app](/reference/files#the-app) and [Account windows](/reference/files#account-windows) list to the Trash. To sign out one window and keep the app, see [Sign a window out](/guides/account-windows#sign-a-window-out).

If you clicked **Install Command Line Tool** in **Settings** > **Command Line**, delete the link it made. Nothing else removes it.

```sh
sudo rm /usr/local/bin/pitboard
```

## Remove files Pitboard made as root

Pitboard 0.7.0 and earlier did not refuse to run as root or under `sudo`. What those runs made belongs to root, and Pitboard [changes nothing as root](/troubleshooting#pitboard-changes-nothing-as-root). Delete it by hand from a root shell, such as `sudo -i` starts.

On Linux:

```sh
systemctl --user disable --now pitboard-renew.timer
rm ~/.config/systemd/user/pitboard-renew.service ~/.config/systemd/user/pitboard-renew.timer
rm -r ~/.pitboard
```

On macOS:

```sh
launchctl bootout gui/$(id -u)/com.datlechin.pitboard.renew
rm ~/Library/LaunchAgents/com.datlechin.pitboard.renew.plist
rm -r ~/.pitboard
```

Where a command finds nothing to remove, go on to the next. If `PITBOARD_HOME` named another directory, delete that one instead of `~/.pitboard`.

In a root shell, `~` is root's home. Under `sudo`, Pitboard used the home `sudo` passed on, which can be yours. Run the `rm` commands again with `~` written as your home's full path, such as `/Users/me`.

On Linux, the parked logins go with the directory. On macOS, they stay in a keychain. Which keychain a run as root wrote to is not measured, so search Keychain Access for `pitboard-park-`.
