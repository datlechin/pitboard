---
title: "Remove Pitboard"
description: "Uninstall Pitboard from the app, or delete parked logins with `pitboard uninstall` and remove Pitboard the way you installed it."
---

Removing the program alone leaves every parked login on the machine. The app's **Uninstall Pitboard** removes both. On Linux, it deletes the parked logins and names the command that removes the app. On the command line, delete the parked logins first, then remove Pitboard the way you installed it.

<Warning>
  Uninstalling cannot be undone. Each tool stays signed in to the account in use. Every other account needs a sign-in again before you can use it.
</Warning>

## Uninstall from the app

The app deletes every saved sign-in, as `pitboard uninstall` does, and its own settings, then removes itself. On macOS and Windows, it also deletes what its account windows keep. On Linux, your package manager removes it.

<Tabs>
  <Tab title="macOS">
    In **Settings** > **Advanced**, click **Uninstall Pitboard**, then **Uninstall**. If Pitboard holds a saved Claude Desktop sign-in and Claude is open, click **Quit Claude and Uninstall** when it asks. Then click **Move to Trash**, and enter an administrator's password if macOS asks for one to remove the command line's link in `/usr/local/bin`. Pitboard quits.

    A copy from the `pitboard-app` cask shows **Remove Pitboard with Homebrew** instead: run `brew uninstall --cask pitboard-app`, as [Remove Pitboard itself](#remove-pitboard-itself) says. Either way, Pitboard moves its caches, saved window state and account windows' website data in `~/Library` to the Trash, as [The app](/reference/files#the-app) lists.

    If Pitboard cannot remove everything, do what **Advanced** says, then click **Try Again**.
  </Tab>
  <Tab title="Windows">
    In **Settings** > **Advanced**, select **Uninstall** on the **Uninstall Pitboard** card, then **Uninstall**. Pitboard exits, and Windows Installer removes the app with a progress bar, as [Remove Pitboard itself](#remove-pitboard-itself) lists.

    If Pitboard cannot remove everything, do what the card says, then select **Try again**.
  </Tab>
  <Tab title="Linux">
    In **Preferences** > **Advanced**, click **Uninstall Pitboard**, then **Uninstall**. Pitboard turns off **Start Pitboard at Login** and removes its folders, `~/.local/share/com.usepitboard.Pitboard` and `~/.cache/com.usepitboard.Pitboard`. **Remove the App** then names the command that removes the app and the command line, such as `sudo apt remove pitboard-app pitboard`, with **Copy** beside it. Run it in a terminal, then click **Quit**.

    If Pitboard cannot remove everything, do what **Advanced** says, then click **Try Again**.
  </Tab>
</Tabs>

## Delete parked logins first

`pitboard uninstall` stops the watch service, turns off daily renewal, deletes every parked login this Pitboard wrote, then deletes the Pitboard directory, `~/.pitboard`. On Windows, the directory is `%USERPROFILE%\AppData\Local\Pitboard`.

<Steps>
  <Step title="Quit the app">
    If the app is open, click Pitboard's item in the menu bar, then choose **Quit Pitboard**. On Windows, right-click Pitboard's icon in the notification area, then select **Exit**. On Linux, press Ctrl+Q in the Pitboard window, or choose **Quit** in its tray menu. `pitboard uninstall` refuses while the app runs.
  </Step>
  <Step title="Remove the status line">
    If Claude Code's status line runs `pitboard statusline`, delete the `statusLine` field from `~/.claude/settings.json`, or the call from your own script. On Windows, the file is `%USERPROFILE%\.claude\settings.json`. Each run makes the Pitboard directory again.
  </Step>
  <Step title="Quit Claude">
    If a Claude Desktop account is parked, quit Claude with Command-Q. `pitboard uninstall` refuses while Claude is open.
  </Step>
  <Step title="Delete the parked logins">
    ```sh
    pitboard uninstall
    ```

    It asks first. Enter `y`, or add `--yes` to skip the question.

    If your shell cannot find `pitboard`, run the copy inside the app:

    ```sh
    /Applications/Pitboard.app/Contents/Helpers/pitboard uninstall
    ```

    If you installed with the script, run `~/.local/bin/pitboard uninstall`.

    On Windows, run the copy the installer put in place:

    ```powershell
    & "$env:LOCALAPPDATA\Programs\Pitboard\bin\pitboard.exe" uninstall
    ```
  </Step>
</Steps>

With two parked logins and daily renewal on, it prints:

```text
Removed 2 parked login(s). The login each tool is signed in with is untouched.
Turned off the daily renewal schedule.
~/.pitboard is gone. Remove Pitboard itself the way you installed it.
```

On Windows, the last line names the directory in full, such as `C:\Users\me\AppData\Local\Pitboard`.

Deleting the directory by hand leaves daily renewal and the watch service in place. `pitboard schedule uninstall` and `pitboard watch uninstall` remove them.

Parked logins outside the directory stay, still valid. Nothing else names them, so `pitboard uninstall` cannot find them:

| Parked logins | After you delete the directory by hand |
| --- | --- |
| Claude Code's and Codex's on macOS, in the keychain | They stay. Delete the `pitboard-park-` items in Keychain Access. |
| On Linux, in your login keyring, or KWallet on KDE Plasma | They stay. Delete the items labelled `Pitboard parked login` there. |
| On Linux, in [files](/reference/files#parked-logins) | They go with it. |
| On Windows | They go with it, as files in the directory. |

If you set `PITBOARD_HOME`, or `pitboard uninstall` refuses, keeps the directory or leaves parked logins, see [`uninstall`](/reference/maintenance-commands#uninstall).

## Remove Pitboard itself

| Installed with | To remove it |
| --- | --- |
| The install script | Delete the five files it installed. |
| `pitboard` cask | `brew uninstall --cask pitboard` |
| `pitboard-app` cask | `brew uninstall --cask pitboard-app` |
| `cargo binstall` or `cargo install` | `cargo uninstall pitboard` |
| A release tarball or zip | Delete `pitboard` or `pitboard.exe`, and the man page and completion files if you copied them. |
| The app on macOS, from a release download | Move `Pitboard.app` to the Trash, or [uninstall it from the app](#uninstall-from-the-app). |
| The app on Windows | In **Settings** > **Apps** > **Installed apps**, select **Uninstall** in the menu beside **Pitboard**, or [uninstall it from the app](#uninstall-from-the-app). |
| The Linux packages, with apt | `sudo apt remove pitboard-app pitboard` |
| The Linux packages, with dnf | `sudo dnf remove pitboard-app pitboard` |
| The Linux packages, with zypper | `sudo zypper remove pitboard-app pitboard` |

Removing the Linux packages leaves Pitboard's repository set up. [Remove the repository](/install/linux-repository#remove-the-repository) says how to remove it too.

For the install script:

```sh
rm ~/.local/bin/pitboard ~/.local/share/man/man1/pitboard.1 \
  ~/.local/share/bash-completion/completions/pitboard \
  ~/.local/share/zsh/site-functions/_pitboard \
  ~/.local/share/fish/vendor_completions.d/pitboard.fish
```

With `PITBOARD_INSTALL_DIR` set, `pitboard` is in that folder and the rest in the `share` folder beside it.

- `--zap` on either cask also removes a daily renewal schedule and a watch service that `pitboard uninstall` left.
- `--zap` on `pitboard-app` also removes the app's files in `~/Library`.
- Neither cask's `--zap` deletes `~/.pitboard`.

If the app came from the `pitboard` cask of 0.3.0 or earlier, leave out `--zap`: see [From the old app cask](/install/upgrade-from-0-3-0#from-the-old-app-cask).

Otherwise the app's files in `~/Library` stay, each account window's sign-in included, since `pitboard uninstall` does not delete them. To remove them, move each `com.usepitboard.Pitboard` item that [The app](/reference/files#the-app) and [Account windows](/reference/files#account-windows) list to the Trash.

If you clicked **Install Command Line Tool** in **Settings** > **Advanced**, delete the link it made. Only the app's **Uninstall Pitboard** removes it for you.

```sh
sudo rm /usr/local/bin/pitboard
```

On Windows, uninstalling the app removes `%LOCALAPPDATA%\Programs\Pitboard`, its Start shortcut, its `PATH` entry, its `pitboard://` links, its start at sign-in, its Jump List and `%LOCALAPPDATA%\Pitboard App`, where the account windows keep their sign-ins. It turns off daily renewal and the watch service, each where its task runs the app's own `pitboard.exe`. From **Settings** > **Apps**, it leaves the parked logins and the Pitboard directory, so run `pitboard uninstall` first. The app's **Uninstall Pitboard** deletes them too.

If you added the app's completions to your PowerShell profile, delete that line from the file `$PROFILE` names.

A task that runs another copy, such as Scoop's, stays. From a terminal run as administrator, the uninstall leaves the app's own tasks too, since [Pitboard changes nothing as administrator](/troubleshooting/refused-changes#pitboard-changes-nothing-as-administrator).

A task left running a `pitboard.exe` you removed runs nothing. `Renew` is daily renewal's task and `Watch` the watch service's. Remove either in PowerShell:

```powershell
$sid = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
Unregister-ScheduledTask -TaskPath '\Pitboard\' -TaskName "Renew $sid" -Confirm:$false
Unregister-ScheduledTask -TaskPath '\Pitboard\' -TaskName "Watch $sid" -Confirm:$false
```

## Remove files Pitboard made as root

Pitboard 0.7.0 and earlier did not refuse to run as root or under `sudo`. What those runs made belongs to root, and Pitboard [changes nothing as root](/troubleshooting/refused-changes#pitboard-changes-nothing-as-root). Delete it by hand from a root shell, such as `sudo -i` starts.

On Linux:

```sh
systemctl --user disable --now pitboard-renew.timer
rm ~/.config/systemd/user/pitboard-renew.service ~/.config/systemd/user/pitboard-renew.timer
rm -r ~/.pitboard
```

On macOS:

```sh
launchctl bootout gui/$(id -u)/com.datlechin.pitboard.renew
rm ~/Library/LaunchAgents/com.datlechin.pitboard.renew.plist
rm -r ~/.pitboard
```

Where a command finds nothing to remove, go on to the next. If `PITBOARD_HOME` named another directory, delete that one instead of `~/.pitboard`.

In a root shell, `~` is root's home. Under `sudo`, Pitboard used the home `sudo` passed on, which can be yours. Run the `rm` commands again with `~` written as your home's full path, such as `/Users/me`.

On Linux, the parked logins go with the directory. On macOS, they stay in a keychain. Which keychain a run as root wrote to is not measured, so search Keychain Access for `pitboard-park-`.
