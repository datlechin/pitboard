## Check first

```sh
pitboard doctor
```

Do not switch accounts while any check shows `✗`, broken. [`doctor`](/reference/maintenance-commands#doctor) lists every check and mark.

`pitboard log` lists the last changes and how each ended. In the app, the Pitboard window's **This Mac** pane, or **This PC** on Windows, makes the same checks, and **Activity** shows the log.

## Claude Code over SSH uses another account

A Claude Code session started over SSH can stay on another account than Pitboard shows, through every switch, and Pitboard warns with `fallback_login`.

<Tabs>
  <Tab title="macOS">
    A `/login` while the keychain is locked, as over SSH, writes the login to `~/.claude/.credentials.json`, which such a session signs in with. [A login file behind the keychain or Credential Manager](/concepts/open-sessions#a-login-file-behind-the-keychain-or-credential-manager) says what else it does.

    1. In a desktop terminal, where the keychain is unlocked, run `pitboard stow`, or click **Put Away** on the app's notice **A login file is left behind the keychain**. A session signed in with the file is signed out.
    2. Before you start Claude Code over SSH, run `security unlock-keychain ~/Library/Keychains/login.keychain-db`, or start it from a desktop terminal. Do not run `/login` while the keychain is locked.
  </Tab>
  <Tab title="Windows">
    Where Claude Code keeps its login in Credential Manager, a sign-in over SSH with a key cannot reach it. A `/login` there writes the login to `.credentials.json` in Claude Code's folder, which such a session signs in with, as read in the Windows builds of Claude Code 2.1.301.

    1. In a desktop session, run `pitboard stow`, or select **Put away** on the app's notice **A login file is left behind Credential Manager**. A session signed in with the file is signed out.
    2. Start Claude Code from a desktop session, and do not run `/login` over SSH.
  </Tab>
</Tabs>

When `stow` deletes nothing, its message says why, and [`stow`](/reference/recovery-commands#stow) lists every outcome. If it cannot read the file, make the file readable to you, or delete `.credentials.json`, login and all.

## An account reads `login replaced outside Pitboard`

The only login of the account in use ended outside Pitboard: a sign-in such as `/login` or `codex login` wrote over it, or the account was signed out in Claude, which ends its login at claude.ai. Pitboard held no copy, so that login is gone, and every read warns with `login_replaced`.

[Sign in to the account again](/guides/sign-in-again), or [forget it](/guides/accounts#forget-an-account). Either stops the warning. To add another account without ending the login in use, follow [Add another account](/guides/accounts#add-another-account).

## Smart App Control blocks Pitboard

On Windows, Smart App Control blocks unsigned apps that Microsoft's cloud service cannot vouch for, and cannot allow a single app, as Microsoft's [What is Smart App Control](https://support.microsoft.com/en-us/topic/what-is-smart-app-control-285ea03d-fa88-4d56-882e-6698afdb7003) says.

With Smart App Control on, Windows opened Pitboard's unsigned installer and command line with no prompt, measured on 18 October 2026 on Windows 11 build 26300. Whether Smart App Control lets the app start has not been measured. The app loads `WinSparkle.dll`, which stays unsigned in signed releases too, as the [code signing policy](/install/code-signing-policy) says.

<Warning>
  Microsoft's page says recent Windows updates let you turn Smart App Control on again, and names none of them. On a Windows without them, it turns on again only after a clean installation of Windows.
</Warning>

To run a Pitboard file it blocks, open **Windows Security**, select **App & browser control** > **Smart App Control settings**, then **Off**. Windows asks for an administrator's consent.

## Report a problem

Open a [GitHub issue](https://github.com/datlechin/pitboard/issues/new/choose) with:

- What you ran, what it printed and what you expected.
- The output of `pitboard doctor --json`, not plain `pitboard doctor`: it replaces email addresses and account identifiers with digests, and your home with `~`.
- `pitboard --version`, and `claude --version` or `codex --version`.
- How you installed Pitboard, and your macOS or Linux version. On Windows, give the build and the system type, x64 or ARM64, which **Settings** > **System** > **About** shows.
- The last lines of `pitboard log`, if they help. A `reclaim` line can name an account identifier.

For a security problem, follow [Report a vulnerability](https://github.com/datlechin/pitboard/blob/main/SECURITY.md#report-a-vulnerability).
