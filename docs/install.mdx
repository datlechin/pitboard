## What you need

- For the command line: macOS on Apple silicon or Intel, or Linux on x86_64 or aarch64.
- For the app: macOS 14 or later, on Apple silicon or Intel.
- Claude Code or OpenAI's Codex CLI, signed in to one of your accounts.

The app includes the command line, so install one or the other. For Codex, read [Before you enrol a Codex account](/guides/codex#before-you-enrol-a-codex-account) first.

The Linux builds are static and run on any distribution. Pitboard is tested on macOS. On Linux it builds and passes its tests, but has not been run with real logins.

There is no Windows release. A Windows build answers only `--version`, `--help`, `completions` and `manpage`, and refuses the rest with [`windows_not_released`](/reference/errors#windows).

## Install with Homebrew

```sh
brew install datlechin/tap/pitboard              # the command line
brew install --cask datlechin/tap/pitboard-app   # the app
```

- Both casks install the man page and the bash, zsh and fish completions.
- The `pitboard-app` cask also puts the command line inside the app on your `PATH`.
- Homebrew installs only one of the two, since both put `pitboard` on your `PATH`.

The app shows Pitboard's item in the menu bar, and a Dock icon only while one of its windows is open.

## Install without Homebrew

[cargo-binstall](https://github.com/cargo-bins/cargo-binstall) downloads Pitboard's own release build for your machine:

```sh
cargo binstall pitboard
```

Building from source needs Rust 1.91 or later and a C compiler:

```sh
cargo install --locked pitboard
```

Neither installs the man page or the completions. [`pitboard manpage`](/reference/integration-commands#manpage) and [`pitboard completions`](/reference/integration-commands#completions) print them.

### Download a release file

The [Releases page](https://github.com/datlechin/pitboard/releases/latest) has these archives:

| For | File |
| --- | --- |
| macOS on Apple silicon | `pitboard-v<version>-aarch64-apple-darwin.tar.gz` |
| macOS on Intel | `pitboard-v<version>-x86_64-apple-darwin.tar.gz` |
| Linux on x86_64 | `pitboard-v<version>-x86_64-unknown-linux-musl.tar.gz` |
| Linux on aarch64 | `pitboard-v<version>-aarch64-unknown-linux-musl.tar.gz` |
| The app | `Pitboard-v<version>-macos.zip` |

Each tarball holds `pitboard`, `pitboard.1`, `completions/`, `LICENSE`, `NOTICE` and `README.md`. Copy `pitboard` to a directory on your `PATH`.

Move `Pitboard.app` to your Applications folder before you open it. Until then, macOS runs it from a temporary copy, and the app cannot turn on [daily renewal](/guides/renewal) or link its command line.

To check a file before you open it, follow [Verify a download](/install/verify).

### Build the app from source

In a clone of [Pitboard's repository](https://github.com/datlechin/pitboard), `./apps/macos/scripts/build-app.sh` writes `apps/macos/build/Pitboard.app`. Copy it to your Applications folder. [CONTRIBUTING.md](https://github.com/datlechin/pitboard/blob/main/CONTRIBUTING.md#the-app) lists what it needs. An app you build has no updater.

## Put the bundled command line on your PATH

Without the `pitboard-app` cask, link it from the app:

1. Click Pitboard's item in the menu bar, choose **Settings**, then click **Command Line**.
2. Click **Install Command Line Tool**, then enter an administrator's password when macOS asks.

`/usr/local/bin/pitboard` then points into the app, so the command line updates with it. The button shows only when Pitboard finds no other `pitboard`. [Command Line](/reference/settings#command-line) lists every case.

You can also run it as `/Applications/Pitboard.app/Contents/Helpers/pitboard`.

## Update Pitboard

| Installed with | To update |
| --- | --- |
| The `pitboard` cask | `brew upgrade pitboard` |
| The app, from its cask or a release file | It updates itself. |
| `cargo binstall` | `cargo binstall pitboard` |
| `cargo install` | `cargo install --locked pitboard` |
| A release tarball | Replace the files with the next release's. |
| An app you built | Build it again. |

- The app checks for an update once a day.
- When it finds one, Pitboard's menu shows **Install Pitboard** and the version.
- **Check for Updates** in Pitboard's menu checks at once.
- `brew upgrade --greedy` also upgrades the `pitboard-app` cask.
- [Updates](/reference/settings#updates) lists the app's update settings.

Keep a command line installed apart from the app at the app's version. An older one refuses a file the app wrote, with `was written by a newer Pitboard`.
